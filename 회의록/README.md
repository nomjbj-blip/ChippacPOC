## 작성 패턴

회의 녹취나 메모가 들어오면 아래 순서로 정리한다.

1. 회의 날짜는 사용자가 입력한 날짜를 기준으로 한다. 날짜가 없으면 입력한 날을 기준으로 하고 확인을 요청한다.
2. 폴더 `YYYY-MM-DD_회의주제/`를 만들고 다음 파일을 저장한다.
   - `녹취원문.txt`: 사용자가 준 원문을 그대로 보관
   - `회의록_내용.json`: 회의록 내용 (생성기 입력)
   - `YYYY-MM-DD_회의주제_회의록.docx`: 최종 Word 회의록
3. 작성 규칙 원본은 `D:\1_프로젝트 문서\98.AI 관련 정보\DocumentAgent\회의록 전용 Agent\AGENTS.md`를 따른다.
   - 번호 체계 I. / 1. / ①, 맑은 고딕 10pt, 내용 요약은 `•`
   - 원문에 없는 담당, 기한, 수치는 붉은색 `[확인 필요]` 또는 `[원문 확인 필요]`
   - 결정, 의견, 확인 필요 사항 구분, 가운데점 기호 사용 금지
4. Word 생성과 렌더링 점검

   ```bash
   NODE_PATH=<docx 설치 경로>/node_modules node 회의록/_도구/make_minutes.js <회의록_내용.json> <출력.docx>
   ```

   ```bash
   powershell -File 회의록/_도구/render_check.ps1 -Docx <출력.docx> -OutDir <점검폴더>
   ```

   - `docx` 패키지가 없으면 임시 폴더에서 `npm install docx` 후 `NODE_PATH`로 지정한다.
   - `render_check.ps1`은 Word로 PDF를 만든 뒤 페이지별 PNG를 생성한다. PNG로 번호, 들여쓰기, 표 넘침을 확인한다.
5. 이 README의 `회의 이력`과 `미결 Action Item 누적` 표를 갱신한다.

## 회의록_내용.json 구조

```json
{
  "title": "회의록",
  "info": { "name": "", "datetime": "", "place": "", "attendees": "", "writer": "" },
  "summary": ["요약 2~5개"],
  "agendas": [
    { "title": "큰 안건", "sections": [ { "title": "세부 안건", "items": ["하위 내용"] } ] },
    { "title": "세부 안건 없는 큰 안건", "items": ["하위 내용"] }
  ],
  "actions": [ { "task": "", "owner": "", "due": "", "status": "" } ],
  "notes": ["표 아래 참고 문장"]
}
```

`결정 및 후속 조치`는 마지막 큰 안건으로 자동 생성된다. 문자열 안의 `[확인 필요...]`와 `[원문 확인 필요...]`는 자동으로 붉은색이 된다.
