- 범위 단계: Standard
- 근거 문서: `DMS/Assistant/기능/F08_KLARF_업로드_DB적재.md`, `문서/설계/03_KLARF_Map/2026-10-07_KLARF_Upload_DB적재_설계.md` (사용자 결정 D1~D5)
- 변경 범위: Interface `iKlarfUpload.cs`, RO `KlarfUpload.cs`, BSL `KlarfUpload.cs`(소스 2026-10-07 12:25), 쿼리 XML 추가분, ENGUI `frmKlarfUpload` — 101_ServerBin BSL DLL 2026-10-08 12:22 (소스보다 나중 → 배포본 기준 검증)
- 기준 데이터(seed): `SampleFile/26_10_06 Sample File/XD106.02` + `Defect Images` 15장 (원본 KLARF: SetupID 46자, Defect 15, 검사 Die 26)
- DB 쓰기: 로컬 시험 DB. Probe 가 업로드 STEP 을 만들고 마지막에 삭제(SETUP/PRODUCT/LOT/WAFER 행은 남음 — 실제 업로드와 동일). 같은 Wafer 에 사용자 업로드 데이터가 있으면 아무것도 하지 않고 SKIPPED.
- 기존 검증 자산: `DMS/02_DMS/DACrux.SEMDMS.BSL/Probes/KlarfUploadProbe.ps1` (키 `KLARF_UPLOAD_PROBE`, 검사 35개 내외), `DMS/02_DMS/DACrux.SEMDMS.ENGUI/Verification/Verify-KlarfUpload.ps1` (키 `KLARF_UPLOAD_FORM_SMOKE`)
- 작성/갱신: 2026-10-12 (program-verify 파일럿)

## 시나리오

### SCN-01 [정상] 샘플 KLARF + 이미지 15장 업로드 → 기존 조회 BSL 로 재조회
- 사전조건: DB healthy, 샘플 Wafer 에 사용자 업로드 데이터 없음
- 단계:
  1. BeginUpload 미리보기
     - expect: Wafer 1행, WAFER_ID = `<Lot>-02`, RAW_WAFER_ID = `XD106.02`, Defect 15 / 검사 Die 26 / 이미지 이름 15 (원본 KLARF)
  2. 이미지 15장 + CommitUpload
     - expect: RESULT = SAVED, SAVED_IMAGES = 15, IMAGE_PATH = FTP 상대 경로 (D4)
  3. 기존 화면 BSL 재조회 (GetDMSStepWaferList / GetDefectMapInfo / GetDefectData / GetDefectImagePath01 / GetDefectMapViewer_Info)
     - expect: 왼쪽 Wafer 조회·Include Image 에 표시, MAP 1 / DIE 26, Defect 15, Defect 1 X = -23229.419 / Y = 86770.97, CLASSNUMBER = ROUGHBIN 54 (D3), 이미지 경로 15행
- 실행 수단: Probe `KlarfUploadProbe.ps1` — 검사 '미리보기…' ~ 'Defect Map Viewer 정보…'
- 실패 의미: 업로드 저장 규칙이 기존 자동 적재/조회 경로와 어긋남 (화면에서 데이터가 안 보임)
- 데이터 정리: Probe 마지막 DeleteUploadedStep

### SCN-02 [입력검증] 잘못된 입력은 저장 전에 거부
- 단계: 항목 수 부족 / 경로가 섞인 파일 이름 / 잘못된 업로드 키 / 이미지 이름에 경로
  - expect: 각각 오류 메시지 반환(빈 문자열 아님), DB 행 생성 없음
- 실행 수단: Probe — '입력 항목 수 부족', '경로가 섞인 파일 이름', '잘못된 업로드 키', '이미지 이름에 경로'
- 실패 의미: 경로 조작(디렉터리 이탈)·잘못된 키로 서버 폴더/DB 오염 가능

### SCN-03 [예외] 이미지 저장소 설정 없음 + 이미지 있음
- expect: `KLARF_IMAGE_ROOT` 를 언급하는 오류, 기존 STEP Defect 15 그대로 (부분 저장 없음)
- 실행 수단: Probe — '저장소 설정 없음 + 이미지 -> 오류', '오류 후 기존 STEP 그대로'

### SCN-04 [권한/상태] 같은 파일 재업로드 (D1 삭제 후 재등록)
- 단계:
  1. 다시 미리보기 → expect: EXISTS, EXIST_STEP_SEQ = 직전 STEP
  2. 건너뜀(N) → expect: SKIPPED
  3. 재등록(Y, 이미지 14장만) → expect: 새 STEP, DELETED_STEP_SEQ = 이전 STEP, 이미지 행 14, 이전 STEP Defect/이미지 0
- 실행 수단: Probe — '다시 미리보기 EXISTS', '건너뜀(N)', '재등록(Y)', '이미지 14장만', '이전 STEP … 삭제됨'

### SCN-05 [경계] SETUP_ID 46자 (기존 바인딩 size 40 무오류 절단 위험)
- expect: TQD_SETUP.SETUP_ID 가 46자 그대로 (D2, 2026-10-07 실측: 기존 쿼리는 40자로 잘림)
- 실행 수단: Probe — 'SetupID 46자 / Step ID 원문', 'TQD_SETUP.SETUP_ID 46자 그대로 (D2)'

### SCN-06 [경계] SETUP_ID 컬럼 한계 초과 (129자 이상)
- expect: **NEEDS_CONTEXT** — 129자 이상 SetupID 를 거부할지/자를지 결정 없음. 결정 전까지 기대값을 정하지 않는다.
- 실행 수단: 신규 Probe 필요 (결정 후)

### SCN-07 [경계] Defect 0건 KLARF
- expect: (설계 기준 추정) 저장 성공, Defect 0, 이미지 0, 조회 화면 예외 없음 — 근거 문서 확인 필요
- 실행 수단: 신규 Probe 필요 + 합성 KLARF 필요 (샘플 없음) → 이번 실행 **미실행**

### SCN-08 [부정] 자동 적재 데이터·기존 쿼리 보호
- expect: 기존 SELECT_SETUP_SEQ → Setup 261, SELECT_STEP_INFO → STEP 401 (회귀), 자동 적재 STEP 401 COMMENT 는 UPLOAD 아님(삭제 대상 아님), 없는 STEP 삭제 → 0, Commit 후 작업 폴더 0, 업로드 STEP 삭제 → 1 / 하위 0
- 실행 수단: Probe — '기존 SELECT_SETUP_SEQ…', '기존 SELECT_STEP_INFO…', '자동 적재 STEP 401…', '없는 STEP 삭제', '작업 폴더 정리', '업로드 STEP 삭제', '삭제 후…'

### SCN-09 [정상] 화면 → RO → BSL 한 프로세스 Smoke
- expect: `KLARF_UPLOAD_FORM_SMOKE=PASS`, 폼 생성·[DB 저장] 흐름 예외 없음
- 실행 수단: Smoke `Verify-KlarfUpload.ps1` (Interface/DSL/BSL/RO/ENGUI 를 %TEMP% 빌드, 로컬 DB 사용, 기본 삭제)
- 주의: 현재 소스로 빌드하므로 다른 세션의 진행 중 변경이 섞일 수 있다 → 빌드 실패 시 '환경'으로 판정하고 원인 파일을 기록

### SCN-10 [정상] 실제 DMS 메뉴(DMS > KLARF 업로드)에서 업로드 후 Defect Map Viewer 표시
- 실행 수단: 화면(사용자) — **화면 확인 대기**
- 단계: DACrux 실행 → POC 메뉴 > KLARF Upload → XD106.02 선택 → DB 저장 → 왼쪽 Wafer 조회에서 해당 Wafer 선택 → Defect Map / Image Gallery 확인
- 비고: D4 영향으로 Image Gallery 썸네일은 상대 경로 때문에 안 보일 수 있음(설계 문서 기재, 기존 제한)
