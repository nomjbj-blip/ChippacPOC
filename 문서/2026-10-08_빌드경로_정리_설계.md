# 빌드 출력 경로 / 참조 정리 설계

작성: 2026-10-08 / Claude (CLAUDE-040) / 대상 솔루션: `DMS/00_Solution/DACrux2015wc_ChippacPOC/DACrux2015wc.sln`

## 1. 목적 (사용자 지시)

- Debug / Release 가 같은 경로로 출력한다.
- 솔루션 안 프로젝트끼리는 **프로젝트 참조**로 참조한다.
- `06_CoreLibSource`(코어) 출력은 `71_CoreLib`, 다른 프로젝트는 그것을 참조한다.
- Client 는 `100_ClientBin`, Service(서버) 는 `101_ServerBin`.
- 애매한 것은 그대로 둔다. 사용하지 않는 출력 경로는 지운다.
- 빌드 순서 때문에 여러 번 빌드하는 문제를 없앤다.

Interface 는 서버 / 클라이언트 양쪽이 쓰므로 현재 Debug 경로를 유지한다(SEMDMS.Interface = Client, TEST.Interface = Server). 반대쪽에는 프로젝트 참조의 Copy Local 로 복사된다.

### 런타임 폴더에 DLL 이 채워지는 방식

코어가 `71_CoreLib` 로 나가면, `100_ClientBin` / `101_ServerBin` 에는 **참조하는 프로젝트를 빌드할 때 Copy Local 로 복사**된다(간접 의존 DLL 포함). 예:

- DACruxV5(Client) -> Framework / Framework.Base / Common.Setup / ENGUI ... -> `100_ClientBin`
- DataService(Server) -> Framework.Server -> Framework.BSL / Framework.DSL / SP.Common -> `101_ServerBin`
- SEMDMS.BSL(Server) -> Common.DSL / Data.Parser / SEMDMS.Interface -> `101_ServerBin`

기존 파일 참조도 Copy Local(기본값 true)이었으므로 복사 동작은 같다. 기존 `<Private>` 설정은 그대로 옮긴다.

## 4. 참조 기준

- 솔루션 안 프로젝트 어셈블리를 가리키는 `<Reference>` 는 모두 `<ProjectReference>`(Project GUID / Name 포함)로 바꾼다.
- 솔루션 밖 DLL(FarPoint / Infragistics / Miracom.Middleware / Oracle / DACrux.Framework.PropertyGrid 처럼 소스가 없는 것)은 기존 HintPath 그대로 둔다.
- 솔루션 밖 프로젝트 참조(ProjectManager -> `03_STAT/DACrux.BStats`)는 그대로 둔다.

## 5. 빌드 순서

솔루션에 수동 `ProjectDependencies` 는 없다. 프로젝트 참조로 바꾸면 VS / MSBuild 가 참조 그래프로 순서를 정한다. 변경 후 그래프에 순환이 없는지 검사하고, 계산된 순서를 7절에 남긴다. 한 번의 "솔루션 빌드" 로 끝나야 정상이다.

## 6. 작업 순서

1. 현황 조사(완료) -> 이 설계 문서
2. csproj 수정(스크립트, 인코딩 / 줄바꿈 유지)
   1. Debug / Release `OutputPath` 를 3절 기준으로 통일
   2. 솔루션에서 쓰지 않는 구성 PropertyGroup 삭제(x86 / 64), 기본 Platform x86 -> AnyCPU
   3. 솔루션 안 파일 참조 -> 프로젝트 참조
3. 검증
   1. 참조 그래프 순환 검사 / 빌드 순서 계산
   2. MSBuild 로 솔루션 Debug / Release 각각 1회 빌드(출력은 TEMP 로 돌려 운영 폴더를 덮지 않음) -> 한 번에 성공해야 함
   3. 프로젝트별 실제 OutputPath 평가값 확인(Debug / Release 동일)
4. 문서(작업 현황 / 변경 이력) / 커밋
5. 사용자: VS 에서 솔루션 빌드(이때 운영 폴더 / 71_CoreLib 로 실제 출력)

### 검증

- 방법: 소스 / 참조 폴더를 `%TEMP%\ChippacVerify2` 에 복사하고, **`71_CoreLib` 에서 솔루션이 만드는 코어 DLL 을 뺀 상태**에서 솔루션을 MSBuild 로 그대로 빌드(출력 경로 재정의 없음). 순서가 틀리면 참조 오류가 나는 조건이다. 운영 폴더 / 실제 71_CoreLib 은 건드리지 않았다.
- Debug: **1회 빌드로 성공(오류 0)**. 출력: `71_CoreLib` 코어 24개, `100_ClientBin` 30개(클라이언트 + Copy Local 코어), `101_ServerBin` 105개(서버 / 서비스 사본 + Copy Local 코어). 프로젝트 폴더에 `bin\Debug` 생성 없음.
- Release: GdsMapControl(제외 대상, 기존 문제) 외 전부 성공. `101_ServerBin\TFF2KLA` 포함 같은 폴더로 출력.
- 미확인: VS IDE 에서의 빌드(사용자 확인 필요), 배포 후 실행.

### 사용자가 할 일

1. VS 에서 솔루션 다시 열기(csproj 가 바깥에서 바뀌었으므로 Reload).
2. 솔루션 빌드 1회 -> 이때 실제 `71_CoreLib` / `100_ClientBin` / `101_ServerBin` 으로 출력된다.
3. 이제 `07_CoreLib` 의 DACrux 코어 DLL 은 갱신되지 않는다(서드파티 / Miracom 참조 용도로만 남음).
