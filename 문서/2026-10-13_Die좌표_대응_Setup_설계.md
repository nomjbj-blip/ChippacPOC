## 3. 현재 시스템으로 커버되는가

| 필요한 것 | 현재 시스템 | 판정 |
| --- | --- | --- |
| Wafer 형상 / Die 배치 (76개) | File Map Setup -> `TQP_MAPDEF` / `TQP_USEMAP` (Map ID = Product) | **됨** |
| 통합 Die# (BS) | `DieNumberRule` LeftTop 행 우선 — **화면 표시만**, DB 에 없음. `TQP_USEMAP.DIE_NUM` 은 넘긴 행 순서(뜻 없음), `TQD_DEFECT.DIE_NUM` 은 모두 NULL | 표시만 됨, 조인 불가 |
| FS Die# (좌우 반전 번호) | 없음 | 안 됨 |
| BS KLARF Index -> Die# | 업로드 때 Index + 원점 -> Map 위치 (CLAUDE-075 설계 확인 대기). Die# 로 바꾸는 곳 없음 | 부분 |
| FS KLARF (TBDB / uPAD) | 반전 없음, 검사 공정별 면 정의 없음 | 안 됨 |
| E-Test TSVET / COWET (X, Y) -> Die# | 원본만 저장 (`TQP_GDS_ET_DIE.DIE_X / DIE_Y`) | 안 됨 |
| E-Test FT (Part ID = Die#) | `DIE_X / DIE_Y` NOT NULL + 파서가 (X, Y) 필수 -> **FT 파일 업로드 불가** | 안 됨 |
| Silterra 26 Die 구분 | 없음 | 안 됨 |
| 다른 Device (U8 / U8N / U11, 고객 미팅 예정) | Map 은 Device 마다 만들 수 있음 / 좌표 대응은 없음 | 안 됨 |

**결론: Setup 이 필요하다.** 다만 Map 을 새로 그리는 큰 화면이 아니다.
- 이미 있는 File Map Setup Map 을 Die# 기준으로 삼는다.
- 좌표계별 대응 규칙과 Die 구분, KLARF 검사 공정별 면만 정하는 **작은 Setup 화면**이다.
- 고객 표를 붙여넣으면 규칙이 자동으로 나오므로 사용자가 회전 / 반전을 몰라도 된다.

하드코딩(U9 식 고정)은 권장하지 않는다. 고객이 U8 / U8N / U11 Set-up 과 "Die-level coordination setting / Coordination offset"을 미팅 안건으로 올렸고, Device 마다 배치와 원점이 다르다.

## 4. 설계안 (이전안 — 8절로 대체: Die# / Die 별 표 없이 Type 별 규칙만)

### 4.1 개념

```text
File Map Setup Map (Device 의 Wafer 형상, 이미 있음)
  └─ Die 마스터: 사용 Die -> Die# (LeftTop 행 우선 = BS top view 고객 번호), Silterra 구분
       └─ 좌표계 규칙 (Device 마다): KLARF_BS / KLARF_FS / ET_XY = 방향(8가지) + 원점 이동
            └─ 좌표 대응표 (규칙으로 만든 1:1 표): (좌표계, X, Y) -> Die#   ← 조회 / 분석은 이 표로 조인
       └─ ET_PART (FT): Part ID = Die#
KLARF 검사 공정 -> 면 (C4 Bump = BS, TBDB = FS ...) -> KLARF_BS 또는 KLARF_FS
```

- Device 키는 **GDS 대표 Device (U9)**. E-Test Device(OMM) / KLARF Product(OMM_Hybrid)는 CLAUDE-055 Sub Device 연결(`GdsMapView.GetMapDeviceBySub`)로 찾는다. 고객 결정 "Full / Hybrid 는 같은 Device, Wafer Map 1개"와 맞는다.
- FS Die 번호는 따로 저장하지 않는다. Die# 는 하나(BS 기준)이고, FS 보기는 그림만 좌우로 뒤집어 같은 Die# 를 보여 준다(고객 그림과 같음).

### 4.2 DB (안, `TQP_GDS_` 접두어)

| 테이블 | 키 | 컬럼 | 비고 |
| --- | --- | --- | --- |
| `TQP_GDS_DIE_SET` | FACTORY, DEVICE_ID | MAP_ID(기준 Map, `TQP_MAPDEF`) / DIE_COUNT / NUMBER_START('LEFT_TOP') / DIE_SIZE_X·Y / SCRIBE_X·Y(고객 값 기록) / REMARK / 감사 | Device 1행 |
| `TQP_GDS_DIE` | FACTORY, DEVICE_ID, DIE_NO | MAP_X / MAP_Y (UQ) / GRID_ROW / GRID_COL / DIE_GROUP('SILTERRA' / 'NORMAL') | Die 마스터 (Map 에서 만든 스냅샷: Map 을 다시 만들어도 Die# 는 그대로) |
| `TQP_GDS_DIE_RULE` | FACTORY, DEVICE_ID, COORD_TYPE | M11 / M12 / M21 / M22 (-1·0·1) / OFFSET_X / OFFSET_Y / RULE_SOURCE('TABLE' 붙여넣기 / 'MANUAL') / CHECK_TEXT(검증 결과) / 감사 | COORD_TYPE = KLARF_BS / KLARF_FS / ET_XY |
| `TQP_GDS_DIE_COORD` | FACTORY, DEVICE_ID, COORD_TYPE, DIE_NO | COORD_X / COORD_Y (UQ: 좌표계 안에서 좌표 1개 = Die 1개) | 규칙으로 만든 1:1 표. 조인용 |
| `TQP_GDS_KLARF_SIDE` | FACTORY, DEVICE_ID, STEP_KEY | COORD_TYPE(KLARF_BS / KLARF_FS) / REMARK | KLARF 검사 공정별 면. **KLARF 작업과 협의** (6절) |

- 기존 `TQP_USEMAP.DIE_NUM` / `TQD_DEFECT.DIE_NUM` 은 손대지 않는다 (기존 화면 보존).
- Die# 는 E-Test / KLARF 데이터에 저장하지 않고 **조회 때 `TQP_GDS_DIE_COORD` 로 조인**한다. Setup 을 나중에 넣거나 고쳐도 이미 올린 데이터에 바로 반영된다.

### 4.3 서비스 (안)

| 메서드 | 내용 |
| --- | --- |
| `GetDieSet(factory, device)` / `GetDieList(factory, device)` | Device 의 기준 Map / Die 마스터 (Die# / Map X·Y / 구분 / 좌표계별 좌표) |
| `BuildDieFromMap(factory, device, mapId)` | Map 의 사용 Die -> LeftTop 행 우선 Die# (화면 `DieNumberRule` 과 같은 규칙, 서버에서 계산) |
| `SaveDieSet(...)` | Die 마스터 + 규칙 + 1:1 표를 한 번에 저장 (Device 단위 교체) |
| `ResolveDieNo(factory, device, coordType, x, y)` 계열 | 다른 서비스용. 실제 조회는 각 쿼리에서 `TQP_GDS_DIE_COORD` 조인 |

- 서비스 위치: 신규 `GdsDieCoord` (Interface / RO / BSL / DSL / XML). **Service config wellknown 1행이 필요하다.** wellknown 을 늘리지 않으려면 기존 서비스에 메서드를 붙이는 방법도 있다(5절 D8).

### 4.4 화면 (안) — POC 메뉴 "Die 좌표 Setup"

| 영역 | 내용 |
| --- | --- |
| 위 | Factory / GDS 대표 Device (U9) / 기준 Map (`TQP_MAPDEF` 목록, Sub Device 이름 Map 우선) / [Map 에서 Die# 만들기] [고객 대응표 붙여넣기] [저장] |
| 왼쪽 | Wafer Map 미리보기 — 기존 Map 컨트롤 + Die 번호 덧그리기(CLAUDE-069) 재사용. **BS / FS 보기 전환**, Die# 표시, Silterra 색, 고른 좌표계 좌표 표시 (고객 그림과 바로 비교) |
| 탭 [좌표계] | KLARF_BS / KLARF_FS / ET_XY 마다 방향(그대로 / 좌우 반전 / ... 8가지) + 원점(Die# 와 그 좌표) + 검증 결과 "76 / 76 일치" |
| 탭 [Die 목록] | Die# / Map X·Y / BS KLARF / FS KLARF / E-Test / Silterra 체크 |
| 탭 [KLARF 검사 공정] | 검사 공정 키 / 면(BS / FS). U9 기본값 = 고객 표 (SiN / RDL / C4 Bump / G2DB = BS, TBDB / uPAD = FS) |

붙여넣기 처리 (E-Test Spec 표 붙여넣기와 같은 방식):
1. 회의록 표를 그대로 복사한다. 열: E-Test (X, Y) / Back-side Klarf (X, Y) / Front-side Klarf (X, Y) / Die#
2. Die# 가 기준 Map 번호와 같은지 확인한다(개수 / 위치).
3. 좌표계마다 8가지 방향 중 모든 행에 맞는 규칙을 찾는다.
4. 맞는 규칙이 없으면 맞지 않는 행을 붉은색으로 보여 주고 저장하지 않는다.
5. 규칙이 정해지면 1:1 표를 만들어 미리보기에 표시한다.

## 8. 사용자 결정 반영: Type 별 Die X, Y 좌표 Mapping 만 (2026-10-13, 4·5절 대체 / 테이블·화면은 9절에서 Logic 으로 대체)

사용자 지시: "각 Type 별로 die 의 X, Y 좌표에 대해서만 Mapping 하면 된다. Index, #Die 별로 Setup 이 아니다."

-> Die 마다(76행) 등록하는 표, Die# 마스터, 1:1 대응표는 **만들지 않는다**. Device + Type 마다 **좌표 변환 규칙 1행**만 둔다.

### 8.1 개념

```text
Type 의 Die (x, y)  --[ Type 규칙: 방향 + 이동 ]-->  시스템 Die 좌표 (X, Y) = File Map Setup Map (TQP_USEMAP X, Y)
```

- 시스템 Die 좌표 = 현재 시스템 Map 좌표(File Map Setup, 왼쪽 아래 (1, 1)). 형상과 Die 배치는 이미 있는 Map 을 그대로 쓴다.
- Die# 가 필요하면 Map 에서 계산한다(이미 있는 LeftTop 행 우선 번호, 로컬 `OMM_Hybrid` Map 에서 고객 Die# 와 76 / 76 일치). 따로 저장 / 등록하지 않는다.
- Type: `ET` (E-Test TSVET / COWET 의 (X, Y)) / `KLARF_BS` / `KLARF_FS`.

U9 규칙 (Type (x, y) -> 시스템 (X, Y), 고객 표 76행 모두 일치 확인):

| Type | 방향 | 식 | 기준점 예 |
| --- | --- | --- | --- |
| ET | 대각 반전 (y = -x) | X = 12 - y, Y = 9 - x | E-Test (4, 5) = 시스템 (7, 5) |
| KLARF_BS | 그대로 | X = x + 7, Y = y + 5 | KLARF (0, 0) = 시스템 (7, 5) |
| KLARF_FS | 좌우 반전 | X = 6 - x, Y = y + 5 | KLARF (0, 0) = 시스템 (6, 5) |

### 8.2 DB (안) — 테이블 1개

`TQP_GDS_DIE_XY_MAP` (PK FACTORY + DEVICE_ID + COORD_TYPE)

| 컬럼 | 내용 |
| --- | --- |
| FACTORY / DEVICE_ID | Device = GDS 대표 Device (U9). E-Test / KLARF Device 이름은 CLAUDE-055 Sub Device 연결로 찾는다 |
| COORD_TYPE | ET / KLARF_BS / KLARF_FS |
| DIRECTION | 8가지 방향 코드 (NONE / MIRROR_X / MIRROR_Y / ROT_180 / ROT_90 / ROT_270 / DIAG / ANTI_DIAG) |
| REF_X / REF_Y | 기준점: 이 Type 좌표 |
| SYS_X / SYS_Y | 기준점: 시스템 좌표 (이동량은 방향 + 기준점으로 계산) |
| REMARK / 감사 컬럼 | |

변환은 정수 식이라 쿼리에서 바로 계산한다(조인 표 없음). 예: `E-Test DIE_X / DIE_Y` -> 시스템 X, Y -> `TQP_USEMAP` 의 Die.
