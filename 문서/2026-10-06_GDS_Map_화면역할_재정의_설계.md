# GDS Map 화면 역할 재정의 설계 (Setup / View)

작성: 2026-10-06 Claude (CLAUDE-026) / 상태: **사용자 결정 반영(8.1절) / 구현 1~5단계 완료(9~12절) / DMS 화면 확인 대기**

관련 문서: [GDS Map DB 저장 설계](2026-10-02_GDS_Map_DB저장_설계.md) 21절, [GDS Map 조회 화면 설계](2026-10-02_GDS_Map_조회화면_설계.md), [GDS Chain DB 저장 설계](2026-10-06_GDS_Chain_DB저장_설계.md) 10.1 / 11 / 12절

## 1. 확정 컨셉 (2026-10-06 사용자 지시)

| 화면 (메뉴) | 역할 | 하지 않는 것 |
| --- | --- | --- |
| **GDS Map Setup** (`MNU_DMS_GDS_MAP_SETUP`, `GdsMapForm`) | GDS 파일 읽기 -> Layer 필터(도형 수 확인) -> **Map DB 저장**(체크한 Layer만) / 원본 Grid 확인 | Chain 설정 / Chain 저장 |
| **GDS Map View** (`MNU_DMS_GDS_MAP_VIEW`, `GdsMapViewForm`) | DB Map 조회 -> **Chain 설정(만들기 / 탐색 / 수동 편집 / 유사 묶음) -> Chain DB 반영(저장 / 삭제)** / 저장된 Chain 불러오기 | GDS 파일 읽기 / Map 저장 |

이 문서는 Chain 저장 설계 12절(Setup 화면 [Chain 저장(DB)])을 대체한다. 12절 코드는 컴파일만 했고 운영 폴더에 반영하지 않았다(ClientBin GdsMap EXE `8c32a67c` 그대로).

## 2. 컨셉 변경으로 좋아지는 점

| 항목 | Setup에서 Chain 저장(이전) | View에서 Chain 저장(새 컨셉) |
| --- | --- | --- |
| 도형 ID 일치 | 같은 GDS 파일인지 SHA-256으로 확인해야 함 | DB 도형을 그대로 그리므로 **항상 일치**. 파일 검사 불필요 |
| Layer 범위 | Map에 없는 Layer를 쓰는 Chain을 검사 / 차단 | DB Layer만 화면에 있으므로 **구조적으로 발생하지 않음** |
| 이어서 편집 | 같은 파일을 다시 열고 불러오기 | 조회하면 DB Chain이 바로 목록에 나옴 |
| 작업 분리 | 파일 담당과 Chain 담당이 한 화면 | Map 등록(1회)과 Chain 설정(반복)이 화면으로 나뉨 |

## 3. 확인한 사실 (2026-10-06 소스)

- **DB에서 그린 도형으로도 Chain 탐색이 가능하다.** `MapPlacedSceneItemFactory`가 DB 행으로 `GdsBoundary` / `GdsPath` / `GdsText` Source를 다시 만들고 `PlacedElementId`도 넣는다. Chain 코드(`GdsMapControl_Chain.cs`)는 `item.Source is GdsBoundary / GdsPath`, `WorldPoints`, `PlacedElementId`만 쓰므로 그대로 동작한다(실제 탐색 결과 비교는 구현 1단계 Probe로 확인).
- **Chain 화면 코드는 `GdsMapForm` partial 5개 + 오늘 만든 `GdsMapForm_ChainDb.cs`다.** (`GdsMapTestForm_Chain.cs` / `_ChainEdit` / `_ChainExample` / `_ChainList` / `_ChainSimilarReview`, 약 1,700행) 의존 대상은 Designer 컨트롤 약 25개, `map`(GdsMapControl), `chkLayerItems`(LayerColorCheckedListBox + LayerDisplayItem), map 이벤트 2개(`MouseDown` / `MouseClick`)와 Form `KeyDown`이다.
- **View 화면에도 같은 이름의 `map` / `chkLayerItems`가 있다.** 따라서 partial 파일의 클래스 이름만 `GdsMapViewForm`으로 바꾸고 Designer 컨트롤을 옮기면 로직 수정 없이 이동할 수 있다.
- **View는 체크한 Layer만 조회한다**(`btnSearch_Click` -> Layer별 페이지 조회 -> `ShowPlacedElements`, 미조회 Layer는 목록에 "미조회" 표시). 다시 조회하면 지도 전체가 새로 그려진다.
- View의 조회 옵션 라디오(도면만 / Chain만 / 둘 다)는 Chain 저장 전이라 "Chain 옵션 비활성" 상태로 있다.
- Probe 영향: Chain Probe 7개는 `GdsMapControl`을 직접 쓰고 Form을 쓰지 않는다. `GdsMapDbRestoreProbe`는 Form 주석만 언급한다. 이동으로 깨지는 Probe는 없다.

## 4. 설계

### 4.1 코드 이동 (Setup -> View)

| 현재 | 이동 후 | 변경 |
| --- | --- | --- |
| `GdsMapTestForm_Chain.cs` 외 4개 (`partial class GdsMapForm`) | `GdsMapViewForm_Chain.cs` / `_ChainEdit` / `_ChainExample` / `_ChainList` / `_ChainSimilarReview` (`partial class GdsMapViewForm`) | 클래스 이름 / 파일 이름만. 로직은 그대로 |
| `GdsMapForm_ChainDb.cs` | `GdsMapViewForm_ChainDb.cs` | SHA-256 파일 검사 / Layer 범위 검사 제거, Factory / Device는 View의 조회 대상 사용 + 불러오기 추가(4.3) |
| `GdsMapForm.Designer.cs`의 Chain 컨트롤(Chain 목록 패널 / 유사 묶음 패널 / 상단 Chain 버튼 2줄 + 상태 창 / 격자 크기) | `GdsMapViewForm.Designer.cs` | 배치는 Setup과 같은 구성(왼쪽: Chain 목록 + 유사 묶음 목록, 지도 위: 상태 창 + 버튼 2줄). map `MouseDown` / `MouseClick`, Form `KeyDown` 연결 |
| `GdsMapForm.cs` | 같은 파일 | `InitializeChainSetupState()` / `ResetChainSetupAfterMapLoad()` / `InitializeChainDbState()` 호출 삭제. 지도 위 Chain 영역(`splitContainer1`) 제거 후 지도만 남김 |

Setup 화면에는 파일 열기 / Layer 목록(도형 수·합계) / DB 저장·중지 / 원본 Grid 탭만 남는다.

### 4.2 View 화면 흐름

```text
Factory / Device 선택 -> Map 정보 + Layer 목록(DB 도형 수)
 -> Layer 체크 -> [조회]  : 체크 Layer 도형 그리기 + DB Chain 목록 불러오기(자동)
 -> Chain 선택 -> (필요 Layer 미조회면 추가 조회 확인) -> Input / Output / 탐색 / 수동 편집 / 유사 묶음
 -> [Chain 저장(DB)] : 변경된 Chain 전체 덮어쓰기 + 삭제 대기 Chain 실제 삭제
```

- **다시 조회해도 Chain 편집 내용은 유지한다.** 같은 Device에서 Layer를 추가로 조회할 때 Chain 목록을 비우지 않는다(도형 ID가 같으므로). 탐색 결과는 키로 보관되어 그대로 쓸 수 있다. 화면 표시만 새로 만든다.
- **Device를 바꾸거나 화면을 닫을 때** 저장하지 않은 Chain 변경이 있으면 "저장하지 않은 Chain n개가 있습니다. 버릴까요?"를 묻는다.
- 조회 옵션 라디오(도면만 / Chain만 / 둘 다)는 8절 결정 2에 따른다.

### 4.3 Chain 불러오기 (DB -> 화면)

조회가 끝나면 `GetChainList` -> Chain마다 `GetChainLayers` / `GetChainRules` / `GetChainMembers` / `GetChainEdits`로 `ChainDefinition`을 만든다.

| DB | 화면 |
| --- | --- |
| CHAIN_SEQ / CODE / NAME / COLOR / APPLY_LAYER_RULES / CELL_SIZE | `ChainSeq` / `Code` / `Name` / `Color` / `ApplyLayerRules` / `CellSize` |
| CHAIN_LAYER | `LayerIds` |
| CHAIN_RULE | `LayerRules` |
| MEMBER ROLE INPUT / OUTPUT + MARKER_X / Y | `Inputs` / `Outputs` (`ChainEndpointPick` = 도형 후보 + 클릭 좌표) |
| MEMBER SOURCE TRACE | 신규 `SavedTraceKeys` (자동 탐색 결과 대신 사용) |
| EDIT ADD / EXCLUDE | `ManualAdded` / `ManualExcluded` |
| VERSION_STATUS DRAFT | 목록에 "(DB 미완료)" 표시 |

- 표시 / 저장 계산(`GetChainKeys`, `GetAutomaticChainKeys`)은 `LastResult`가 없으면 `SavedTraceKeys`를 자동 결과로 쓰도록 분기 1개를 넣는다. [후보 탐색]을 다시 하면 지금처럼 새 탐색 결과로 바뀐다.
- `ChainEndpointPick`의 도형 후보는 지도에서 ID로 만든다(`GdsMapControl`에 ID -> `ChainElementCandidate` 메서드 추가).
- 불러온 직후 저장 지문을 계산해 `SavedFingerprint`로 둔다. 아무것도 안 바꾸고 저장하면 "변경 없음".
- **Chain이 쓰는 Layer가 미조회일 때**: 지도에 없는 도형은 외곽선이 그려지지 않는다. 8절 결정 3에 따라 처리한다. 편집 / 저장 시에는 DB 키를 그대로 보존하므로 미조회 Layer의 Member가 저장 때 빠지지 않는다.
- Member의 Layer를 알기 위해 `SELECT_CHAIN_MEMBER`에 `TQP_GDS_PLACED_EL` 조인으로 `LAYER_ID` 열을 추가한다(XML만 변경, 서비스 계약 동일 / 반환 열 1개 추가).

### 4.4 Chain 저장 (View)

Chain 저장 설계 12절 로직을 그대로 쓰되 아래만 바꾼다.

- 제거: GDS 파일 SHA-256 비교, DB Map Layer 범위 검사(DB 도형만 화면에 있음).
- 유지: Input 1개 / Output ≤ 1개 / 포함 도형 있음 검사(어긋난 Chain만 제외), 변경 지문 비교, 삭제 대기 Chain 실제 삭제, Chain별 Begin -> Member·편집 배치 -> Complete, 확인창.
- 같은 Code 덮어쓰기 임시 대응은 불러오기가 생기므로 삭제한다. 새 Chain 번호는 DB에서 불러온 Chain의 최대 Code 다음부터 매긴다(`_nextChainOrdinal`).
- 동시 편집: 버전 이력이 없으므로 같은 Device를 두 사람이 동시에 저장하면 마지막 저장이 남는다(10.1절 결정 1). 1차에서는 안내만 한다.

│ [삭제][Chain 저장(DB)]│                                                     │
│ 유사 묶음 목록       │                  지도(map)                            │

## 6. 구현 단계 (작은 단위, 단계마다 확인)

| 단계 | 내용 | 확인 |
| --- | --- | --- |
| 1 | Chain 코드 / 컨트롤 이동(Setup -> View), Setup 정리. 동작 변경 없음 | 빌드 / Probe(Chain 7개 + DB 복원) / DMS 화면: Setup에 Chain 없음, View에서 Chain 만들기·탐색 동작 |
| 2 | 다시 조회 시 Chain 유지 / Device 변경·닫기 시 미저장 확인 | DMS 화면 |
| 3 | 불러오기(`SavedTraceKeys` / 단자 복원 / 미조회 Layer 처리) + `SELECT_CHAIN_MEMBER` LAYER_ID | Probe(저장 -> 불러오기 왕복 일치) + DMS 화면 |
| 4 | View [Chain 저장(DB)] (12절 로직 이동 / 검사 정리) | GdsChainProbe + DMS 화면(저장 -> 닫기 -> 다시 조회 -> 같은 Chain) |
| 5 | 조회 옵션 라디오 정리(결정 2) / 문서 / 메뉴 툴팁 | DMS 화면 |

각 단계 후 GdsMap EXE를 `100_ClientBin/GdsMap`에 반영하고(사용자는 DACrux 재시작) 확인 결과를 기록한다. 3단계만 서버 XML 1개가 바뀐다.

## 7. 영향과 위험

- 메뉴 / 호스트(`frmGdsMapSetup` / `frmGdsMapView`)는 바뀌지 않는다. 두 화면 모두 같은 GdsMap EXE에 있다.
- Setup에서 Chain을 쓰던 사용 습관이 바뀐다. Setup의 툴팁 "GDS Map/Chain 설정 화면"은 "GDS Map 등록(Layer 필터 / DB 저장)"으로 바꾸는 것을 제안한다(`MenuFile.mnu` 2곳, 맨 뒤 행 아님 -> 문구만 수정. 결정 4).
- View는 조회한 Layer만 메모리에 올린다. 전체 Layer(샘플 60만 도형)를 조회하면 DB 경로로 약 20~25초(CLAUDE-018 측정)가 걸린다. Chain 편집에 필요한 Layer만 조회하는 것을 기본으로 안내한다.
- 이동 대상 파일은 git에 추적되는 파일이다(`GdsMapTestForm_Chain*.cs`). 파일 이름 변경은 커밋 시 이동으로 기록된다.
