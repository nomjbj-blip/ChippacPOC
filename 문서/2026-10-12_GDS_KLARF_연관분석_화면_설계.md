# GDS × KLARF 연관 분석 화면 설계 (1차)

사용자 지시 (2026-10-12):

> GDS의 Map 정보와 Klarf File 간의 연관 분석화면을 만들어야 한다. GDS는 Chip Base 이고 Klarf는 Wafer 및 Chip에 대한 Defect 정보를 가지고 있다. POC 프로젝트에서 1차적으로 연관 분석할 수 있는 화면에 대해 설계를 진행 한다.
> 컨셉은 DMS Defect View 화면 컨셉으로 보여 주되 Chain 에 올라가 있는 Defect 개수에 따라 화면상에서 사용자가 확인 할 수 있도록 색 그라데이션 형태로 보여 주고 Chip을 더블클릭하여 상세 조회 화면으로 이동하는 컨셉이다.
> GDS에 대한 보기 기준을 두고 분석 버튼을 만들어서 각 Die 별로 분석 할 수 있어야 한다.
> 나중에 E-Test 결과 내용도 넣어서 Limit 에서 벗어난 Die도 볼수 있게 해야하는데 이부분은 염두하고 만 있고 지금은 GDS-Klarf에 대해서만 우선 설계 진행 하자

## 2. 범위

| 구분 | 1차 (이번 설계) | 나중 |
| --- | --- | --- |
| 데이터 | GDS Map + 저장된 Chain / KLARF 1 Wafer (STEP_SEQ 1개) | E-Test 결과 / Limit 판정 (9절 확장 자리만 둔다) |

| 색 기준 | Chain 영역 Defect 개수 구간 색 | Defect 타입별 색 (연구소 회신 후) / E-Test Fail |
| 여러 Wafer | 1 Wafer씩 분석 (왼쪽에서 여러 장을 골라도 콤보로 1장씩 전환) | Lot 합산 / Wafer 비교 |

## 3. 화면 구성과 흐름

화면 2개로 나눈다.

| 화면 | 역할 | 위치 (프로젝트) | 이유 |
| --- | --- | --- | --- |
| **A. GDS-KLARF 연관 분석** (Wafer Map) | Wafer 선택(왼쪽 DMSearch) / 보기 기준 / [분석] / Die별 구간 색 / Die · Chain · Defect 목록 / 이미지 | `02_DMS/DACrux.SEMDMS.ENGUI/DefectMapAnalysis` (.NET 4.0) | Defect 화면 기준 프로젝트(공통 개발 지침). 기존 Defect Map Viewer의 Wafer 선택 패널 / `DefectMap` 컨트롤 / Wafer 그리기 서비스를 그대로 쓴다 |
| **B. Die 상세 분석** (GDS Chip) | 선택 Die의 GDS 도면 + Chain 색 + Defect 위치 / Chain 영역 · 밖 Defect 목록 / Wafer 합산 보기 | `06_CoreLibSource/GdsMapControl` (.NET 4.8, OpenGL) + ENGUI 호스트 | GDS 도면은 GdsMapControl만 그릴 수 있다. 기존 `frmGdsMapView`와 같은 방식(실행 시 EXE 로드)으로 DMS에 붙인다 |

```text
DACrux 왼쪽 DMSearch(기존) 에서 Wafer 조회 -> [Search]
   -> 화면 A.DrawWafer(DPWafer[])               (기존 iSEMControl 계약)
   -> 기존 DefectMapAnalysis 서비스로 Wafer Map + Defect 점 그리기 (기존 Defect Map Viewer와 같은 모습)

화면 A 조건(보기 기준 / 허용오차 / Class / Chain) -> [분석]
   -> 신규 GdsKlarfAnalysis.AnalyzeWafer (서버 BSL, 1회 호출)
        Chain Member Bounds (1 쿼리) + KLARF Defect (기존 쿼리) -> 좌표 변환 -> 겹침 판정 -> 집계
   <- 결과 DataSet (Die 집계 / Die-Chain 집계 / Defect 판정 / Chain 목록 / 분석 기준)
   -> Die 색 = Chain 영역 Defect 수 구간 색, 오른쪽 목록 갱신

Die 클릭      -> 오른쪽 목록을 그 Die로 거르기 + 이미지 탭 갱신
Die 더블클릭  -> 화면 B (열려 있으면 앞으로, 없으면 ShowForm) -> ShowDie(결과 DataSet, Die)

화면 B
   GDS 도면은 (Factory, Device, 보기 기준)이 바뀔 때만 DB에서 읽는다 (전체 Layer 기준 약 18.7초)
   Die를 바꾸면 Defect 표시만 다시 그린다 (서버 호출 없음, A가 넘긴 결과 사용)
```

A의 분석 결과를 B에 그대로 넘긴다. 그래서 두 화면은 항상 같은 기준(보기 기준 / 허용오차 / Chain 범위)으로 같은 숫자를 보여 준다. B에서 기준을 바꾸려면 A에서 다시 [분석]한다.

### 4.4 Wafer Map 색 규칙

Die 색을 정하는 값 `N`은 **Die 안에서 Chain 영역에 걸린 Defect 수(중복 제거)**다. Defect 1개가 Chain 2개에 걸려도 1개로 센다 (A1).

| Die 상태 | 색 | 비고 |
| --- | --- | --- |
| 검사 계획 밖 (`TQD_SETUP_MAP`에 없음, Hybrid Mark die 등) | 기존 Map 표시 그대로 (Skip / Mark) | 76칸 중 26칸만 검사한 Hybrid 대응 |
| Defect 없음 | 흰색 `#FFFFFF` | 기존 Defect Count Color 0 구간과 같은 색 |
| Defect는 있으나 `N < 표시 기준` (Chain 밖 Defect만 있는 Die 포함) | 연회색 `#E0E0E0` | Defect가 있다는 것만 보여 준다 |
| `N >= 표시 기준` | 구간 색 5단계 `#DAF7A6 → #FFC300 → #FF5733 → #C70039 → #900C3F` | **기존 Defect Count Color 기본 색 순서를 그대로 사용** (연두 -> 노랑 -> 주황 -> 빨강 -> 자주). 엔지니어가 이미 익숙한 색 |

자동 구간 나누기:

```text
T = 표시 기준 (기본 1, 구간 표 첫 행 FROM),  M = 이 Wafer의 N 최대값
M - T + 1 <= 5  : 1개씩 한 구간 (예: M = 4 -> 1 / 2 / 3 / 4)
그보다 크면     : 폭 = ceil((M - T + 1) / 5) 로 5구간, 마지막 구간 TO = 999 (예: M = 23 -> 1-5 / 6-10 / 11-15 / 16-20 / 21+)
```

- 연속 그라데이션 대신 구간 색을 쓴다. 범례 숫자와 색이 정확히 맞아 "몇 개 이상"을 바로 읽을 수 있고, 기존 화면과 같은 방식이다.
- 구간 표에 구간별 Die 수를 같이 보여 준다.
- Die 안에 `N`을 쓰고, Die 화면 폭이 40px 이상이면 `(x, y)` Index도 쓴다 (`KlarfDefectMap.ShowDieIndexLabel` 재사용). 선택 Die는 기존처럼 빨간 3px 테두리.
- Defect 점: 기존 Map처럼 Defect 위치를 점으로 그린다. 분석 뒤에는 Chain 영역 Defect를 진한 색, Chain 밖 Defect를 회색으로 그린다 (`TypeColor`가 Class 기준이라 하위 클래스에서 그린다). [Defect 점] 체크로 끌 수 있다.

### 4.5 Map 컨트롤 구현 방식 (`GdsKlarfAnalysisMap : KlarfDefectMap`)

기존 Die 색 기능 4가지를 검토했다.

| 방법 | 판단 |
| --- | --- |
| A. `ItemCountColorList` (기존 Defect Count Color) | 개수를 Map에 올라간 Defect로만 센다(Chain 영역 수를 넣을 수 없다). 구간 밖 Die의 Defect를 숨긴다. `DieClear()`가 목록을 비운다 -> **색 자료 클래스만 재사용** |
| B. Density Die (`DieProp = 3`) | 흰색 -> 자홍 고정, 범례 없음 -> 사용 안 함 |
| C. `VisibleDieValue` + Gradation | Die 값 문자열이 함께 그려지고 `DefectMap`이 `m_ColorSet`을 숨겨 색 지정이 제한됨 -> 사용 안 함 |
| **D. 하위 클래스 `WaferMap_Paint` override** | `KlarfDefectMap`이 이미 쓰는 방식. `m_arrDies` / `m_gdiTempMap` / `m_iCurrentX/Y` 사용 가능 -> **채택** |

추가하는 것:

| 멤버 | 내용 |
| --- | --- |
| `SetDieValues(IDictionary<Point, int> chainDefectCounts, ISet<Point> defectDies, ItemCountColorList bands, int threshold)` | 분석 결과로 Die 채움색을 정하고 `Redraw()` |
| `SetDefectChainFlags(ISet<long> inChainDefectIds)` | Defect 점 색 구분 |
| `event DieDoubleClick(int xIndex, int yIndex)` | `OnDoubleClick` override에서 `m_iCurrentX/Y`로 발생. 기존 `DefectMap`에는 Die 더블클릭 이벤트가 없다(빈 Die는 빈 배열만 보낸다) |
| `WaferMap_Paint` override | 1) Die 채움 2) 기본 그리기(Defect 점 / 테두리) 3) `N` / Index 글자. 채움이 Defect 점을 덮지 않게 순서를 구현 1단계에서 확인한다 |

`06_CoreLibSource/DACrux.Map`은 수정하지 않는다 (공통 개발 지침). 하위 클래스는 ENGUI `DefectMapAnalysis` 폴더에 둔다.

## 6. 분석 로직

### 6.1 KLARF Die 안 좌표 -> GDS Chip 좌표 (1차 가정)

확인한 사실:

| 항목 | 값 | 출처 |
| --- | --- | --- |
| KLARF Die Pitch | 23,832 x 30,060 µm (XD106.02) | KLARF `DiePitch` / `TQD_SETUP.DIE_PITCH_X / Y` |
| KLARF Die 안 좌표 | `XREL / YREL` (µm). 샘플 범위 X 216 ~ 23,027 / Y 1,284 ~ 14,174 | `TQD_DEFECT` |
| GDS TOP Chip 범위 | X -11,880 ~ 11,880 (23,760) / Y -14,992.5 ~ 14,992.5 (29,985) µm | `GdsElements_20260929_130226.csv` Structure Min / Max |
| 크기 차이 | X 72 µm / Y 75 µm (양쪽 약 36 µm씩 = Scribe 폭으로 추정) | Pitch - Chip |
| 방향 | KLARF Pitch와 GDS Chip이 모두 세로가 긴 형태(X < Y) -> Die 안에서 90도 회전은 없다고 본다 | 위 두 값 |

그래서 1차 변환식을 다음과 같이 둔다. **GDS 원점 = Chip 중심, KLARF XREL / YREL = Pitch 칸 좌하단 기준**이라는 가정이다.

```text
gx_view = XREL - PitchX / 2 + 보정X        (보기 기준 좌표, KLARF 그대로)
gy_view = YREL - PitchY / 2 + 보정Y
GDS 저장 좌표와 비교할 때: 저장 기준(FRONT) ≠ 보기 기준이면 gx_stored = -gx_view, gy_stored = gy_view
```

- Member 도형(많음)을 반전하지 않고 Defect(적음)를 저장 기준으로 바꿔 비교한다. 결과 표시 좌표는 보기 기준 값을 쓴다.
- `보정X / 보정Y`는 화면 고급 입력(기본 0)으로 두고 분석 기준에 기록한다. 연구소 좌표 대응표가 오면 기본값을 정한다 (A5).
- 샘플 검증 (2026-10-12, scratchpad 스크립트 1회 실행, GDS CSV 기준): 이 식으로 XD106.02 Defect 15개를 바꾸면 모두 Chip 범위 안에 들어가고, 15개 중 12개(Back) / 13개(Front)가 Layer 3 / 5 / 6의 작은 도형(한 변 2 mm 이하) Bounds 위에 놓인다. **좌표가 Chip 안의 배선 위치에 떨어지는 것은 확인했지만, 도면이 좌우 대칭에 가까워 이 방법으로 Front / Back을 가를 수는 없다.** Chain을 저장한 뒤 화면 B에서 엔지니어가 Defect 이미지(RDLshort / RDLopen)와 위치를 대조해 확정한다.
- Scribe 오프셋 (2026-10-13): File Map Setup 은 Pitch 만 조정하고 Die / Scribe 크기는 받지 않는다. 위 식의 `- PitchX / 2` 는 Scribe 가 양쪽 균등이라는 가정이며, 한쪽으로 몰려 있으면 `보정X / 보정Y` 가 Scribe 오프셋 역할을 한다. Pitch 는 Map Setup 의 CHIP_SIZE 가 아니라 KLARF 값(`TQD_SETUP.DIE_PITCH_X / Y`)을 쓴다. Chip 위치 / Scribe 폭은 고객 확인 대상.
- KLARF 파일에 `OrientationInstructions "Front"` 표기가 있어 Back side 설명과 다르다 (E-Test 설계 Q2, 확인 대기).

### 6.2 보기 기준

사용자 지시의 "GDS에 대한 보기 기준"은 **이 KLARF Step을 어느 면에서 검사했는지에 GDS를 맞추는 선택**으로 해석한다.

| 보기 기준 | GDS | KLARF | 쓰는 경우 |
| --- | --- | --- | --- |
| Back side (기본) | 좌우 반전 (`X' = -X`) | 그대로 | 현재 받은 C4Bump 등 Back side Step |
| Front side | 원본 | 그대로 | Front side Step (연구소 단계 구분표 대기) |

- GDS Map 조회 화면의 보기 기준 기본값(Front)과 다르게, 이 화면은 Back side를 기본으로 한다. 현재 KLARF가 Back side이기 때문이다 (A6).
- 나중에 Step별 면 구분표(회의록 10-06 Action)가 오면 Step ID로 기본값을 자동 선택한다. 1차는 수동 선택.

### 6.3 겹침 판정

```text
Defect 사각형 = [gx - w/2 - Tol, gx + w/2 + Tol] x [gy - h/2 - Tol, gy + h/2 + Tol]
                (Defect 크기 반영 해제 시 w = h = 0)
Member 사각형 = TQP_GDS_PLACED_EL.MIN_X ~ MAX_X / MIN_Y ~ MAX_Y (저장 기준 좌표)
겹침          = 두 사각형이 경계 포함 겹치면 그 Member의 Chain에 "걸림"
```

- 대상 Chain: `TQP_GDS_CHAIN_VER.VERSION_STATUS = 'READY'` 인 Chain만. DRAFT(저장 미완료)는 제외하고 상태줄에 개수 표시.
- BSL에서 Member Bounds로 균일 격자 색인(칸 200 µm, 조정 가능)을 만든 뒤 Defect마다 주변 칸만 검사한다. Defect 수 x Member 수 전체 비교를 피한다.
- 긴 PATH(배선)는 Bounds가 실제 선보다 넓다. 대각선 배선 주변 빈 공간도 겹침이 될 수 있으므로 1차 결과는 "후보"로 표시하고, 정밀 판정(POINTS_BIN Polygon / PATH 폭)은 2차다 (Chain Setup 컨셉안 10.2절과 같은 판단).
- SQL이 아닌 BSL 메모리에서 판정하는 이유: DB 설계 13.3절은 SQL 거르기를 1차 후보로 적었지만, 반전 / 보정 / 허용오차 / Defect 크기를 C# 한 곳에서 계산해야 화면 B와 같은 식을 쓰고 2차 Polygon 판정으로 이어가기 쉽다. Member Bounds와 Defect는 각각 쿼리 1번으로 읽는다(둘 다 `DMSMGR` 연결). Member가 수만 건 이상이 되면 SQL 범위 거르기로 바꾸는 것을 검토한다.

### 6.4 집계 정의

| 값 | 정의 |
| --- | --- |
| 전체 Defect 수 (Die) | 그 Die의 Defect 수 (Class 필터 적용 후) |
| Chain 영역 Defect 수 (Die) = `N` | Chain이 1개 이상 걸린 Defect 수. **Defect 중복 제거** |
| Chain 밖 Defect 수 (Die) | 전체 - Chain 영역 |
| 걸린 Chain 수 (Die) | 그 Die에서 Defect가 1개 이상 걸린 Chain 종류 수 |
| Defect 수 (Die, Chain) | 그 Die에서 그 Chain에 걸린 Defect 수. 한 Defect가 Chain 2개에 걸리면 두 Chain에 각각 1 |
| Chip 밖 Defect | 변환 좌표가 Chip 범위 밖. Chain 밖으로 세고 목록에 "Chip 밖" 표시 (좌표 변환 오류 신호) |

## 14. 2026-10-12 사용자 수정 요청 반영 설계 (상세 이동 방식 / Chip 단위 상세 / 탭 제목 / 우클릭 메뉴)

사용자 지시: "상세 보기를 마우스로 Chip 선택 후 상세보기 화면으로 이동하는 방법으로 바꾸자. 상세 보기 화면은 해당 Chip에 대해서만 분석 할 수 있다. Tab 상단에는 상세보기(좌표정보)가 나오는 방법으로 하자. 현재 화면이 두개의 상세 화면이 나오는데 버그인지 확인. 해당 화면에서 Context Menu는 Freezoom, FitSize, Defect select, Die select, Detail Analysis(신규) 기능만 보이도록 하자. 설계 후 수정 시작"

### 14.1 상세 화면 두 개 = 버그 (원인 확인)

- `frmGdsKlarfAnalysis.OpenDetail` 은 상세 화면이 없으면 `ShowForm(숨김 메뉴)` 로 열고, 연 화면을 `MdiChildren.OfType<frmGdsDieAnalysis>()` 로 찾아 못 찾으면 직접 하나 더 연다.
- DACrux `DACruxMain.ShowForm` 은 `AssemblyUtil.LoadAssembly` = `Assembly.Load(byte[])` 로 ENGUI DLL 을 **매번 새로 읽는다**. 그래서 ShowForm 이 만든 화면은 이름은 같아도 다른 어셈블리 사본의 형식이라 `OfType` 이 찾지 못하고, 예비 경로가 두 번째 화면을 만들었다. (7.3절 설계의 결함)
- 수정: 상세 화면은 `ShowForm` 을 쓰지 않고 화면 A 가 직접 만든다(`MdiParent` 지정). 찾을 때는 형식 이름(FullName)으로 찾는다. 숨김 메뉴 행 `MNU_GDS_DIE_ANALYSIS` 는 여는 데 쓰지 않고, 화면이 활성화될 때 DACrux 가 왼쪽 DMSearch 패널을 닫는 기준(RESV_04 = DMS)으로만 남긴다.

### 14.2 상세 이동 방식

| 항목 | 변경 |
| --- | --- |
| 조건 줄 [상세 보기] 버튼 | 제거 |

- 나머지(Rotate Notch / Zone Select / Move View Center / Visible Shot / Visible Zone / 5% Zoom In·Out / Shot Option / Zone Option / Copy To Clipboard / Real Size Defect Drawing / Defect Image Mark / Defect View / Clear Selected Die / Visible Mark Die)는 숨긴다.

### 14.4 상세 화면 = 선택 Chip 1개

- 화면 B 에서 Die 콤보 / [이전] [다음] / 선택 Die · Wafer 합산 라디오를 제거한다. 다른 Chip 은 화면 A 에서 다시 고른다(같은 상세 화면을 재사용, 도면은 다시 읽지 않음).
- 화면 B 위쪽에 Chip 좌표 정보를 크게 표시: `Die (6, 8)  Defect 5 / Chain 영역 5 / 밖 0`.
- **탭 제목**: 호스트 `frmGdsDieAnalysis.Text = "상세보기 (6, 8)"`. DACrux MDI 탭에 그대로 보인다. Chip 을 바꾸면 제목도 바뀐다.
