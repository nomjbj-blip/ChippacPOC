## 1. 결론

**11개 화면 모두 E-Test 데이터로 동작시킬 수 있다.** 단, 아래 두 가지가 먼저 필요하다.

1. **E-Test -> YMS 테이블 변환(브리지) 1개.**
   - 지금 E-Test 는 `TQP_GDS_ET_*` 에만 저장되고 YMS 테이블(`TQP_LOT` / `TQP_WAFER` / `TD_<PROGRAM>` / `TQP_WAFER_SUM`)과 연결이 없다.
   - YMS Test 데이터 구조는 Bin 전용이 아니다. "Die 1행 x Parameter 컬럼"의 범용 구조이고 Bin 도 그중 한 컬럼이다.
   - 그래서 E-Test(Die 별 Parameter 값)를 그대로 담을 수 있다. Spec 판정 결과를 BIN 컬럼에 넣으면 Bin 계열 화면도 동작한다.
2. **메뉴 / 조건 설정 몇 줄.**
   - 11개 화면의 메뉴가 지금 대부분 숨김이다(상위 `MNU_TEST` 숨김).
   - 일부 화면은 TESTAREA 허용 목록(메뉴 `RESV_03` / 쿼리 `SELECT_TESTAREA`)에 E-Test 값을 넣어야 한다.
   - YMS 화면 C# 수정은 필요 없다.

**데이터 양 제약.** POC E-Test 실제 파일은 1개뿐이다(TSVET, 1 Lot / 1 Wafer / 24 Die).
- 여러 Wafer 가 있어야 의미가 생기는 화면(Gallery / 누적 / 수율 추이 / Lot 별 BoxPlot)은 구조상 동작해도 보여줄 내용이 거의 없다.
- 리뷰에서 보여주려면 고객에게 **1 Lot 전체(최대 25 Wafer x TSVET / COWET) 파일**을 받아야 한다.

  - Map 도 실제 Wafer 모양으로 나온다.
- 코드에서 TESTAREA 로 분기하는 곳은 PARAMETRIC / INLINE / AVI 만 확인됐다(`09_TEST` 전체 검색). 새 값은 MULTIPROBE 와 같은 경로를 탄다.

## 4. 연계 구조 (브리지 매핑)

```text
E-Test (지금)                                    YMS (화면이 읽는 곳)
TQP_GDS_SRC_FILE (파일 = Wafer + 공정)  ──>  TQP_PRODUCT / TQP_PROGRAM / TQP_LOT / TQP_WAFER
TQP_GDS_ET_DIE   (Die, 판정, MAP_X/Y)   ──>  TD_<PROGRAM> 행 (WAFER_SEQ, DIE_NUM, X, Y, BIN)
TQP_GDS_ET_VALUE (Die x Parameter)      ──>  TD_<PROGRAM> 의 Parameter 컬럼 (NUMBER)
TQP_GDS_ET_LIMIT (Spec)                 ──>  TQP_PARASPEC (PARAM_NAME, LSL / USL, PARAM_DESC)
Spec 판정 (Pass / Fail)                 ──>  TQP_BINDESC (Bin 정의) + TQP_WAFER_SUM / TQP_LOT_SUM (수율)
```

| YMS 항목 | 넣을 값 | 근거 / 주의 |
| --- | --- | --- |
| `TQP_PROGRAM.PROGRAM` | Device + 공정 (예: `OMM_TSVET`) | Spec 키(Device + 공정)와 1:1. TD 테이블 이름 = `TD_OMM_TSVET` |
| `TQP_LOT.TEST_AREA` | 공정 (TSVET / COWET / FT) | 3절 |
| `TQP_LOT.DEVICE` / `DEVICE_ALIAS` | `OMM` / Map ID | Map 연결 키는 `DEVICE_ALIAS = TQP_MAPDEF.MAPID` (`ProbeMapAnalysis.cs:1509`). Map ID = 파일명 Device 결정(Die 좌표 설계 10절)대로면 **`OMM` Map 등록 필요** (로컬에는 `OMM_Hybrid` / `Hybrid` 만 있음) |
| `TQP_LOT.LOT_ID` / `TQP_WAFER.WAFER_ID` | `LOT_ID` / `WAFER_ID` (예: RH-HS2615 / RH-HS2615-02) | 시간 = 파일 Test Date, `DATA_SOURCE` = 파일명 |
| TD `X` / `Y` | `TQP_GDS_ET_DIE.MAP_X / MAP_Y` (시스템 좌표, 왼쪽 아래 (1,1)) | YMS Map 은 TD X/Y 를 **변환 없이 Map Index** 로 쓰고 방향을 LeftBottom 으로 고정한다(`ProbeMapAnalysis.cs:1534`). `DieCoordinateMapper` ETest 결과와 같은 기준. MAP_X/Y 는 Upload 재설계 9절에서 저장 예정 |
| TD `DIE_NUM` | 고객 통합 Die# (`DieCoordinateMapper.DieNumberOf`) | YMS 는 행 순서(i+1)를 쓴다. Die# 를 넣으면 추이 차트 X축이 고객 번호 순서가 된다 |
| TD `BIN` | 1 = Pass / 2 = Spec Fail (범위 밖) / 3 = 미측정('-') 만으로 Fail | BIN 은 0~255 (`WaferMap.cs` 색상표 256), 요약은 BIN < 100 만 집계(`TD_TABLE.xml:15`) |
| TD Parameter 컬럼 | Spec 정의 Parameter 값만 (TSVET 37개, 전체 약 120개) | 테이블당 900컬럼 제한 안. **'-' 는 NULL 로 넣는다** (5절 1) |
| `TQP_PARASPEC` | PARAM_NAME = 변환한 컬럼 이름, PARAM_DESC = 헤더 원문, LSL / USL = Spec Lower / Upper | Parameter 마스터 겸 Spec. Map 의 Spec 색 / 차트 USL·LSL 선이 이 값을 쓴다 |
| `TQP_BINDESC` | Program 별 Bin 1 / 2 / 3 (BIN 1 은 HIGH_GEC = Y, 색 지정) | Bin Setup 화면(`frmSetupBin`)에서도 보인다 |
| `TQP_WAFER_SUM` / `TQP_LOT_SUM` | 기존 `TestCommon.SummaryData` 로 생성 | 수율 = Good Bin / NETDIE. NETDIE 와 측정 Die 수가 1.5배 넘게 다르면 측정 Die 수로 나눈다(`TestCommon.cs:1305`) -> Hybrid(26 Die 측정 / Map 76) 도 수율이 맞게 나온다 |

**저장 방법.** 기존 YMS 적재 함수를 그대로 쓴다. PCM / CP DataService 가 쓰는 순서와 같다(`PCMDataService.cs:203-291`).
1. `TestCommon.SaveWaferData`: `TQP_LOT` / `TQP_WAFER` MERGE
2. `TestDataManager.SaveData`: TD 테이블 / 컬럼 / `TQP_PARASPEC` / `TQP_DATA_TABLES` 자동 생성 + WAFER_SEQ 기준 지우고 다시 넣기
3. `TestCommon.SummaryData`: 요약 테이블 생성

**브리지 위치.**
- `TestCommon` / `TestDataManager` 는 `DACrux.TEST.BSL` 에 있다.
- E-Test 서비스(`GdsEtResult`)는 `DACrux.SEMDMS.BSL` 에 있다. 이 프로젝트는 이미 `DACrux.TEST.DSL` 을 참조하고, `DACrux.TEST.BSL` 은 `DACrux.SEMDMS.DSL` 을 참조한다.
- 선택지는 두 가지다(구현 설계 때 결정).
  - SEMDMS BSL 에 TEST BSL 참조 1개를 추가해 `GdsEtResult` 메서드로 둔다. wellknown 추가가 없다.
  - TEST BSL 에 새 클래스를 둔다. TEST Service wellknown 1행이 필요하다.

**호출 시점.**
- E-Test 파일 저장(READY) 직후.
- Spec 재판정(`RejudgeEtFiles`) / Map 재계산(`RemapEtFiles`) 뒤. 같은 Wafer 를 다시 반영하면 기존 함수가 WAFER_SEQ 데이터를 지우고 다시 넣는다.

## 5. 걸리는 점

| # | 내용 | 대응 |
| --- | --- | --- |
| 1 | YMS 적재 함수는 숫자가 아닌 값 '-' 를 `decimal.MinValue`(-7.9E28)로 저장한다(`TestDataManager.cs:497-518`). 그러면 Map 색 구간 / 통계 최소값이 깨진다 | 브리지가 '-' / 빈 칸을 빈 값으로 넘긴다 -> NULL 저장(`:317`), Map 에서 흰색. Fail 여부는 BIN 3 으로 남긴다 |
| 2 | 분석 화면은 Parameter 를 **컬럼 이름(PARAM_NAME)** 으로 보여준다(`SELECT_PARA_ITEM` 이 `ALL_TAB_COLUMNS` 와 이름으로 조인). E-Test 헤더 `Resistance_iforce=8.0mA@C4DC_28_37_FH` 는 `= @ . :` 때문에 컬럼 이름이 될 수 없다 | 변환 규칙 필요. 예: 대문자 / `=` `@` `:` -> `_` / `.` -> `P` (기존 Fab2 PCM 파서 방식) -> `RESISTANCE_IFORCE_8P0MA_C4DC_28_37_FH`. 원문은 PARAM_DESC. 변환 후 중복은 업로드 때 오류 |
| 3 | 컬럼 이름 길이: E-Test 헤더 최대 54자 / 평균 36자 (로컬 13,775개 중 30자 초과 10,810개) | 로컬 DB 19c(compatible 19.0.0, 128바이트) 는 문제없다. **고객 DB 가 12.1 이하이면 30바이트 제한** -> 고객 DB 버전 확인. 짧은 이름 규칙이 필요할 수 있다 |
| 4 | Map 원점: YMS Map 은 방향을 LeftBottom 으로 고정하고 저장된 `ORIGIN_INDEX` 를 그대로 쓴다. File Map Setup 의 LeftTop Map(`OMM_Hybrid` 저장 (6, 5), LeftBottom 환산 (7, 5))은 Wafer 원 대비 Die 배치가 X 1칸 밀려 보일 수 있다 | **화면으로 확인 필요.** Die 색 / 좌표 매칭에는 영향이 없고 Wafer 테두리 대비 위치만 영향. CLAUDE-075 "X 1 차이" 와 같은 현상으로 보임 |
| 5 | Program 이 다르면 Gallery 한 화면에 섞지 못한다 | 같은 Wafer 의 TSVET / COWET 비교는 Program 을 바꿔 각각 본다 |
| 6 | Spec 이중 보관: E-Test Spec(`TQP_GDS_ET_LIMIT`) 과 YMS `TQP_PARASPEC` | E-Test Spec 화면을 원본으로 두고 브리지가 PARASPEC 을 덮어쓴다. YMS Program Parameter Spec 화면에서 직접 고치면 다음 반영 때 덮어써진다 |
| 7 | 측정값 두 번 저장 (`TQP_GDS_ET_VALUE` + TD) | 정의 Parameter 만 저장하므로 파일당 약 900 값(TSVET 37 x 24). POC 에는 문제없다. 본 프로젝트에서 단일화 검토 |
| 8 | FT (좌표 없음, Part ID = Die#) | FT 파일 수령 후. Die# -> 시스템 좌표는 `DieCoordinateMapper` DieNumber 로 가능 |
