# E-Test -> YMS 컬럼 이름 30자 대응 설계

작성: 2026-10-21 / 작업: CLAUDE-170 / 상태: **설계** (소스 / DB 변경 없음) -> 2026-10-21 권장안 Y1 ~ Y9 결정, CLAUDE-171 구현(11절)
확인 수준: 소스 확인 + 로컬 DB 조회(읽기 전용) + 실제 Parameter 109개로 규칙 시뮬레이션
관련: [E-Test Upload YMS 적재 설계](2026-10-14_ETest_Upload_YMS적재_설계.md) 4.3 / 15절, [Para Setup 설계](2026-10-14_ETest_Para_Setup_설계.md) 5절, 변경이력 `DMS/Assistant/변경이력/2026-10-21.md` CLAUDE-169

## 1. 목적

고객 DB(CPKMESDV)는 **Oracle 11.2.0.4** 이다. 11g 는 테이블 / 컬럼 이름을 **30바이트**까지만 허용한다(12.2 부터 128).
E-Test 결과를 YMS 에 반영하면 Parameter 마다 `TD_<PROGRAM>` 테이블에 컬럼이 생기는데, 지금은 컬럼 이름이 최대 50자라 고객 DB 에서 만들 수 없다.
E-Test Parameter 이름이 30자를 넘으면 **YMS 컬럼에는 30자 이하의 짧은 이름을 따로 만들어 저장**하고, E-Test 쪽 이름과 화면은 지금대로 둔다.

## 2. 발견한 사실

| 항목 | 내용 | 근거 |
| --- | --- | --- |
| 고객 DB 버전 | Oracle 11.2.0.4, 사용자 TRAINING | 2026-10-21 09:19 스키마 DDL 실행 로그 |
| 실패 | `TD_OMM_TSVET`(115 컬럼 중 109개 30자 초과) / `TD_OMMTCB_TSVET`(91 중 85) 생성 실패 `ORA-00972 identifier is too long` | 같은 로그 |
| 다른 객체 | 나머지 테이블 / 인덱스 / 제약 / 시퀀스 / 함수 이름은 모두 30자 이하. 쿼리 XML / C# 에 12c 이상 전용 문법(FETCH FIRST / OFFSET / JSON / APPLY / DEFAULT ON NULL) 없음 | 로컬 DB 조회 / 소스 검색 |
| 현재 E-Test Parameter | `TQP_GDS_ET_ITEM` 194행(이름 109종, OMM 109 / OMMTCB 85) **모두 31 ~ 50자** | 로컬 DB 조회 |
| 앞으로의 업로드 | 11g 에서 E-Test -> YMS 반영을 하면 앱이 TD 테이블 / 컬럼을 만들 때(`TD_TABLE.CreateTDTable` / `AppendColumnAtTDTable`) 같은 오류로 실패한다 | 소스 확인 |

즉 지금 등록된 Parameter 는 **전부** 짧은 이름이 필요하다.

## 3. 현재 구조 (소스 확인)

```text
결과 파일 헤더 (예: Resistance_iforce=8.0mA@TSVDC_ASIC_HBM_N_FH)
  -> EtParameterNameRule.Parse            측정 종류 / 조건 / Chain 1·2 로 분해
  -> EtYmsRule.ToParamName                 ITEM_NAME (최대 50자) = E-Test 기준 이름
  -> TQP_GDS_ET_ITEM.ITEM_NAME             CK: 형식 + LENGTH <= 50 / UQ(FACTORY, DEVICE_ID, TEST_PROGRAM, ITEM_NAME)
     (E-Test 화면 / 값 / Limit / Chain 연결 / 연관 분석이 모두 ITEM_NAME 기준)

YMS 반영 (GdsEtResult.PublishEtFileToYms)
  GdsEtResult_Yms.cs:145   parameter.YmsName = parameter.ParameterName   <- ITEM_NAME 을 그대로 YMS 컬럼 이름으로 씀
  EtYmsPublisher           TD 컬럼 이름 / TQP_PARASPEC.PARAM_NAME = YmsName, PARAM_DESC = 헤더 원문
  TD_TABLE.CreateNewTable  "TD_" + Program + 분할 접미어(A, B ...)
```

| 위치 | 현재 | 30자 영향 |
| --- | --- | --- |
| `EtYmsRule.MaxParamNameLength` | 50 (ITEM_NAME / YMS 컬럼 공용) | YMS 컬럼은 30 이어야 함 |
| `EtYmsRule.MaxProgramLength` | 45 (`TQP_PARASPEC.TABLE_NAME` 50 기준) | TD 테이블 이름도 30 -> Program 26 (TD_ 3 + 접미어 1) |
| `EtYmsPublisher` | `YmsName` 과 `ParameterName` 을 이미 따로 받는다 | 받는 값만 바꾸면 된다 |
| YMS 분석 화면 (`TPUCMapView` / `TPUCPCMView` / `TPUCMapGallery`) | Parameter 목록에 **PARAM_NAME(=컬럼 이름)** 을 보여 준다 | 짧은 이름이 화면에 그대로 보인다. 원문은 Parameter Spec 화면(`frmSetupParameterSpec`)의 PARAM_DESC |
| `TQP_PARASPEC.PARAM_NAME` | VARCHAR2(50), `SELECT_PARA_ITEM` 이 컬럼 이름과 같음을 조인 조건으로 씀 | 짧은 이름을 그대로 넣으면 된다 |

## 5. YMS 이름 규칙 (권장안 C)

### 5.1 순서

입력은 등록 때 이미 분해해 둔 값이다(`EtParameterParts` / `TQP_GDS_ET_ITEM` 의 MEAS_TYPE / PARA_NAME / COND_VALUE / CHAIN_NAME / CHAIN_NAME2).

1. ITEM_NAME 이 30자 이하이면 **ITEM_NAME 그대로** 쓴다. 아래 2 ~ 7 은 30자를 넘을 때만.
2. 측정 약어: RESISTANCE -> `RES` / CONNECTIVITY -> `CONN` / LEAKAGE -> `LKG` / CONTINUITY -> `CONT` (고객 Naming Rule 의 RES / LKG 표기, 기존 1단계 약어와 같음). 목록 밖이면 MEAS_TYPE 그대로.
3. 조건: COND_VALUE 가 있으면 '.' -> 'P' (8.0MA -> `8P0MA`, 기존 규칙과 같음). 없으면 PARA_NAME 의 측정 종류 뒤 단어를 PARALLEL -> `PAR` / SERIAL -> `SER` 로(그 밖은 그대로).
   IFORCE 같은 조건 이름은 넣지 않는다. 값(8P0MA)만으로 구분된다.
4. Chain 1 이름 그대로.
5. Chain 2 가 있으면 Chain 1 과 **앞에서부터 같은 단어를 뺀 나머지**만 붙인다. 예: Chain 1 `TSVDC_ASIC1_N_FH`, Chain 2 `TSVDC_ASIC1_P_FL` -> `P_FL`.
6. 2 ~ 5 를 `_` 로 잇는다. 숫자로 시작하거나 예약 이름(X / Y / BIN / WAFER_SEQ / DIE_NUM / DIEPROBE_CNT)이면 앞에 `P_` (기존 규칙).
7. 그래도 30자를 넘으면 앞 21자 + `_` + 해시 8자리(ITEM_NAME 의 FNV-1a, 기존 `StableHash` 그대로).
8. 같은 Device + 공정 안에서 서로 다른 Parameter 가 같은 YMS 이름이 되면 **등록 오류**로 막는다(기존 `FindNameProblems` 방식).

분해 정보가 없는 Parameter(헤더 형식이 아님)는 기존 `ToParamName` 규칙을 한도 30으로 적용한다(약어 -> 해시).

### 5.2 실제 Parameter 109개 적용 결과 (시뮬레이션, 로컬 DB 이름)

| 측정 종류 | 개수 | 규칙 C 해시 | 규칙 A(기존 약어 30자) 해시 |
| --- | --- | --- | --- |
| RESISTANCE_IFORCE | 36 | 0 | 2 |
| CONNECTIVITY_IFORCE | 34 | 0 | 2 |
| LEAKAGE_PARALLEL | 26 | 0 | 0 |
| LEAKAGE_SERIAL | 13 | 1 | 13 |
| 합계 | 109 | **1** | 17 |

두 규칙 모두 최대 30자, 이름 겹침 0.

## 6. 저장과 흐름 (권장안 기준)

```text
Parameter 등록 (파일 헤더 등록 RegisterEtParameters / Spec 등록 경로)
  EtParameterNameRule.Parse -> ITEM_NAME (50, 지금과 같음)
                            -> YMS_PARAM_NAME = EtYmsRule.ToYmsName(parts) (30, 5.1)
  같은 Device + 공정 안 YMS 이름 겹침 검사 -> 겹치면 등록 오류
  TQP_GDS_ET_ITEM 에 ITEM_NAME + YMS_PARAM_NAME 저장 (이후 자동으로 바꾸지 않음)

Para Setup [등록 Parameter]
  "YMS 이름" 열 표시 / 수정 (30자 / 형식 / 겹침 검사, YMS 반영된 Parameter 는 수정 불가)

YMS 반영 (PublishEtFileToYms)
  parameter.YmsName = YMS_PARAM_NAME   (비어 있으면 "YMS 이름 없음"으로 실패, 이름 오류와 같은 처리)
  TD 컬럼 / TQP_PARASPEC.PARAM_NAME = YMS_PARAM_NAME, PARAM_DESC = 헤더 원문 (지금과 같음)
  TD 테이블 이름 = TD_ + Program(26자 이하) + 접미어
```

DB 컬럼(안):

```sql
ALTER TABLE TQP_GDS_ET_ITEM ADD (YMS_PARAM_NAME VARCHAR2(30 CHAR));
-- 기존 행을 채운 뒤
ALTER TABLE TQP_GDS_ET_ITEM MODIFY (YMS_PARAM_NAME NOT NULL);
ALTER TABLE TQP_GDS_ET_ITEM ADD CONSTRAINT CK_GDS_ET_ITEM_YMS
  CHECK (REGEXP_LIKE(YMS_PARAM_NAME, '^[A-Z][A-Z0-9_]*$') AND LENGTH(YMS_PARAM_NAME) <= 30);
ALTER TABLE TQP_GDS_ET_ITEM ADD CONSTRAINT UQ_GDS_ET_ITEM_YMS
  UNIQUE (FACTORY, DEVICE_ID, TEST_PROGRAM, YMS_PARAM_NAME);
```

이름이 ASCII(A~Z / 0~9 / `_`)뿐이라 30자 = 30바이트다.

## 9. 위험 / 남은 확인

- 고객의 다른 Device / 공정은 Chain 이름이 더 길 수 있다. Chain 1 이름만으로 22자를 넘으면(측정 약어 + 조건 + `_` 2개 = 약 8자) 해시가 늘어난다. 새 결과 파일을 등록할 때 분석 단계에서 해시 개수를 보여 주고 Y6 로 고친다.
- YMS 분석 화면에는 짧은 이름만 보인다(Y9). 원문 대조가 자주 필요하면 그때 YMS 화면에 원문 열을 추가하는 것을 따로 정한다.
- 이미 YMS 에 반영된 Parameter 의 YMS 이름은 바꿀 수 없다. 바꾸려면 그 파일의 YMS 반영을 지우고 다시 반영한다.
- 11g 실제 동작은 TRAINING 에서 업로드 1회로 확인해야 한다(로컬은 19c).
