# 데이터 구조 (2026-10-22 기준)

## 1. 세 데이터와 연결 키

| 데이터 | 알려주는 것 |
|---|---|
| GDS (칩 도면) | 칩 안에서 Chain(U9 Daisy Chain / U8 Net)이 지나가는 위치 |
| KLARF (AOI 결과) | Defect 가 있는 Die, Die 안 위치(XREL / YREL, µm), 크기, 분류, 이미지 |
| E-Test (전기 측정) | Die 별, Parameter(Chain / Net) 별 측정값 |

| 연결 | 키 |
|---|---|
| KLARF ↔ E-Test (Wafer) | KLARF Lot 핵심 문자열 + Slot ↔ E-Test 파일명 Lot-Wafer 번호. KLARF WaferID 는 다른 코드(숫자 등)라 직접 비교 불가 |
| KLARF ↔ E-Test (Die) | `샘플/U9_U8_Die좌표_대응표.tsv` (고객 제공). 규칙: E-Test X = 4 - BS_KLARF_Y, E-Test Y = 5 - BS_KLARF_X / FS KLARF X = -1 - BS X |
| E-Test ↔ GDS (Chain) | E-Test Parameter 이름 안 Chain / Net 이름 ↔ GDS Label 로 만든 Chain. U8 은 이름이 달라 E-Test 쪽을 바꿔(Replace) 연결 (10/21) |
| KLARF ↔ GDS (위치) | Defect 의 Die 안 좌표를 도면 좌표로 옮겨 Chain 영역과 겹침 확인. Defect 영역은 **사각형** (① Defect 크기 + 허용오차 / ② 지정 X·Y 정사각형) |

## 2. Wafer / Die

- 300 mm, Notch 아래. Die 76개, 위에서부터 행별 4 / 8 / 10 / 10 / 12 / 10 / 10 / 8 / 4 개. Wafer Map 은 KLARF Pitch 로 원형 생성 + Edge 2,000 ~ 5,000 µm 이면 이 76개와 같음.
- Full 타입 76 Die / Hybrid 타입은 Silterra 26 Die 만 실제 Die. **U8 도 U9 Hybrid 와 같은 배치** (26 Die 일치 확인).
- Die# 기준: BS top view 왼쪽 위가 1번, FS top view 오른쪽 위가 1번. KLARF (0, 0) = BS 에서 Die#39, FS 에서 Die#38.
- Die 크기: Scribe 제외 23,680 × 29,905 µm, Scribe 150 µm. KLARF Pitch 는 Scribe 포함 약 23,830 × 30,053 ~ 30,060 µm. 파일마다 중심 좌표(SampleCenterLocation)가 조금씩 다름 -> Offset / 허용오차 필요.
- 기준면: POC 는 분석 시 엔지니어가 Step 별로 BS / FS 선택. U9 AOI: SiN / RDL / C4 / G2DB = BS, TBDB / uPAD = FS. GDS 원본은 FS, BS 로 뒤집어 사용.

## 3. U9 와 U8 차이

| 항목 | U9 (OMM Hybrid / TCB) | U8 (PFIC) |
|---|---|---|
| 성격 | 시험 구조(Test Vehicle), 긴 Daisy Chain | 실제 제품 배선, Functional Net |
| 분석 단위 | Chain 15 ~ 30개 (TSVDC) | Net 약 27,000개 (Net 1개에 도형 10개) |
| GDS | 87 MB, 도형 60만, Label 3만 | 346 MB, 도형 182만, Label 27만 |
| 측정 | Resistance / Leakage | Connectivity / PowerShort / PlaneResistance |
| Spec | 고객 Spec 표 (`샘플/U9_ETest_Spec표.tsv`) | E-Test 파일 안 Upper / Lower Limit 행 |
| KLARF Device 표기 | OMM_Hybrid, OMM_TCB | OMM_U8 |
| E-Test 파일명 | `CAI_OMM_ATV_A0_TSVET_<일시>_U9-HS2635_U9-HS2635-01$Silterra$` | `CAI_PFIC_U8_A0_TSVET_<일시>_U8-NPI_U8-NPI-01` |

## 4. E-Test

- 파일명: `[Customer]_[Device]_[Wafer Type]_[Wafer Rev]_[Test Type]_[Test Date]_[Lot]_[Lot-Wafer No]`, `_` 로 자름. `$Silterra$` 는 기준정보에 안 넣음. U8 은 Device 칸 PFIC, Wafer Type 칸 U8.
- 단계: TSVET(1차) -> COWET(2차) -> FT(3차, Part ID = Die#).
- U9 Parameter 이름
  - RES: `Resistance_iforce=8.0mA@TSVDC_<영역>_<FH|FL>` / Fail: 값 > 715 Ω
  - LKG: `Leakage_Serial@<영역1>_FH:<영역2>_FL` (두 Chain 사이) / Fail: 값 = '-' 또는 |값| > 50 uA
  - TSVDC Chain(영역) 30개: TOP1 / TOP2 / BOT1 / L / R / ASIC1~4 / ASIC_HBM / HBM0 / HBM1 / HBM_C 각 P·N + TL / TR / BL / BR. TSVET 는 28개(TOP1 P·N 없음).
- U8 Parameter 이름 (408개)
  - `Connectivity_POS@<Net>` 100 (0.5 ~ 40 mA) / `Connectivity_NEG@<Net>` 100 (-40 ~ -0.5 mA)
  - `PowerShort@<Net>` 200 (-5 ~ 5 mA) / `PlaneResistance_POS|NEG@<Net>` 8 (Limit N/A)
  - Net = `VDD_nnnn`, `VSS_nnnnn`. 열 이름 끝에 공백 1칸.
- U8 샘플 판정: 비 Silterra 50 Die 는 Connectivity 전부 Fail(실제 Die 없음) -> 분석 제외. Silterra 26 Die 중 **Die#34 만 PowerShort 196 항목 Fail**.

## 5. KLARF

- 형식: KLA KLARF 1.2, Defect 마다 `TiffFileName` + `DefectList` 반복. DefectRecordSpec 22항목(DEFECTID, X, Y, XREL, YREL, XINDEX, YINDEX, XSIZE, YSIZE, ..., ROUGHBINNUMBER ...).
- 분류는 ROUGHBINNUMBER 에 있음(CLASSNUMBER 는 0). 이미지 파일명 `{WaferID}_{XINDEX}_{YINDEX}_{ROUGHBIN}_{DEFECTID}.jpg`.
- U9 샘플(FS2635 C4Bump): Defect 1,122 / InspectionTest 여러 블록.
- U8 샘플(NPI RDL): Defect 1,438 / Damaged Bump 852, Via Defect 290, RDL Discolor 270, Satellite Bump 16, RDL Lump 9, RDL Open 1.
- U8 사례: Die#34(PowerShort Fail) 에 RDL Lump 2 + Damaged Bump 1 / Die#54 는 Defect 327 인데 E-Test Fail 없음.
