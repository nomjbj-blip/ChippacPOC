# Claude 채팅 분석 자료 사용 방법

claude.ai 채팅에서 스태츠칩팩 POC(GDS × KLARF × E-Test 연관 분석)를 대략 분석하기 위한 자료 묶음이다. 기준일 2026-10-22.

## 올리는 방법

1. claude.ai 에서 **회사 Claude Team 계정**으로 프로젝트를 하나 만든다 (예: `SCK POC 연관 분석`).
2. 이 폴더의 파일을 전부 프로젝트 지식(Project knowledge)에 올린다.
3. 아래 "프로젝트 지침"을 프로젝트 Instructions 칸에 붙여 넣는다.
4. 질문 예시
   - "U8 E-Test 발췌에서 Spec Out 판정 기준을 정리해줘"
   - "Die#34 의 E-Test Fail 과 KLARF Defect 를 대응표로 연결해줘"
   - "다음 회의에서 확인할 미결 사항을 우선순위로 정리해줘"

## 프로젝트 지침 (Instructions 칸에 붙여넣기)

```
너는 스태츠칩팩코리아(SCK) 연구소의 Defect / E-Test 자동 분석 시스템 POC 를 돕는 분석 담당이다.
- 답은 한국어로, 결론 먼저, 짧게 쓴다.
- 근거는 프로젝트 지식의 파일 이름과 절을 적는다. 자료에 없는 수치 / 날짜 / 담당자는 만들지 말고 [확인 필요]로 표시한다.
- 용어: GDS = 칩 도면, KLARF = AOI 검사 결과, E-Test = 전기 측정 결과, Chain = GDS 위 배선 영역(U8 은 Net), Die# = 고객 통합 Die 번호(1~76).
- U9 와 U8 은 구조가 다르다(02_데이터_구조.md). 둘을 섞어 말하지 않는다.
- 판정은 엔지니어가 하고 시스템은 위치 / 개수를 보여준다는 원칙을 지킨다.
```

## 넣지 않은 것과 이유

- GDS 원본(87 MB / 346 MB), KLARF / E-Test 원본 전체: 용량이 크고 채팅 분석에 필요한 구조는 발췌로 충분하다.
- 소스 코드, DB 접속 정보, 서버 IP, 연락처: 채팅 분석에 필요 없다.
- 고객 메일 원문: 내용은 03 문서에 요약했다.

## 갱신

회의나 결정이 바뀌면 03 / 04 문서를 고치고 claude.ai 프로젝트 지식의 같은 파일을 다시 올린다. 원본 근거는 저장소 `문서/설계`, `회의록`, `DMS/Assistant` 에 있다.
