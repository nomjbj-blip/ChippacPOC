# 프로젝트 개요 (2026-10-22 기준)

## 목적

AOI 검사(KLARF)의 Defect 와 전기 측정(E-Test)의 Fail 을 칩 도면(GDS)의 Chain 영역 위에서 겹쳐 보고, 엔지니어가 연관 여부를 판단하도록 돕는 시스템이 가능한지 확인하는 POC.

| 목적 | 내용 |
|---|---|
| Fail 원인 찾기 | Fail Chain 위의 Defect 를 원인 후보로 좁힘 -> 이미지 리뷰, 파괴 분석 대상 선정 |
| AOI 기준 조정 | Fail 과 상관없는 Defect 확인 -> AOI Recipe, Reject 기준 조정 근거 |
| 잠재 불량 관리 | Defect 는 있으나 지금 Fail 이 아닌 위치 -> 이후 신뢰성 Fail 과 연계 |
| 검출 누락 확인 | Fail 인데 Chain 위에 Defect 없음 -> AOI 미검출 가능성, 파괴 분석 |

원칙: **판정은 엔지니어, 시스템은 위치 / 개수 / 이미지를 보여줌** (10/2, 10/13 회의).

## 일정과 참여

- POC 기간: 2026-10 (약 1개월). 다음 주(10/26 주) 월~수 고객 검증, 목요일 보고, 그 주에 미라콤 현장 지원 마무리.
- 고객(SCK 연구소): 서승환 책임(실무 담당), 조현 차석, 구재훈 상무. IT팀은 서버 / DB / 방화벽 담당.
- 미라콤: 정병주 프로(개발 / 현장).

## 시스템 구성

| 구성 | 역할 |
|---|---|
| DMS | KLARF 업로드, Wafer Map 에 Defect 표시, Defect 이미지 |
| YMS | E-Test 결과 적재, Wafer Map / 분석 화면 |
| GDS 도면 화면 | GDS 등록, Chain(Net) 영역 설정 |
| 연관 분석 화면 | Die 별 Chain 영역 안 Defect 수, Die 상세(도면 위 Defect + Chain + E-Test) |

POC 는 모든 파일을 **엔지니어가 수동 업로드**. 본 프로젝트에서는 MES 기준정보 연동, FTP 배치 자동 수집 예정.

## 화면 (POC 메뉴)

| 단계 | 화면 | 하는 일 |
|---|---|---|
| 준비 (Device 별 1회) | File Map Setup / Wafer Map View | KLARF 로 Wafer Map 형상 등록 (XY 방향 기본 LeftTop) |
| | GDS Map Setup / GDS Map View | GDS 등록, 필요한 Layer 만 저장, Input / Output 단자로 Chain 설정 |
| | GDS Map View U8 | U8 전용 (같은 형태 Chain 일괄 생성, 대량 Chain 표시) |
| | E-Test Para 등록 / 설정 | 결과 파일 헤더를 Parameter 로 등록, Spec 과 GDS Chain 연결 |
| 데이터 등록 (Lot 마다) | KLARF File Upload | KLARF + Defect 이미지 저장 (이미지는 FTP) |
| | E-Test Result Upload | 측정값 저장, Spec 판정, Fail Chain 표시 |
| 분석 | GDS-KLARF 연관 분석 (화면 A) | Die 별 Chain 영역 Defect 수 색 표시, E-Test Fail Die 표식 |
| | 상세보기 (화면 B, Die 상세) | 도면 위 Defect / Chain / E-Test 결과, Chain 밖 Defect 목록 |
| | 연관 분석 Simple | Wafer 1개를 받으면 바로 KLARF ↔ Chain 1차 분석 (E-Test 제외, 10/22 1단계) |

## 진행 상태 (10/21 회의 기준)

- U9 연관 분석 약 50% -> 이번 주 E-Test 연결, Wafer 화면, Defect 크기 / 마진 / Offset 추가.
- U8: GDS 로딩 / Label 표시 / 같은 형태 Chain 자동 추출(약 27,000 Net) 진행. 데이터량이 커서 상세보기 속도 개선 작업 중.
- 서버 / DB: IT팀 준비 중, Defect 이미지 FTP 설정 반영.
