## 2. U9 와 차이

| 항목 | U9 | U8 |
|---|---|---|
| 구조 | Daisy Chain (TSVDC / C4DC / ASICDC / HBMDC) | **Functional Net** (Net List 가 도면 Layer 의 Label 로 들어 있음) |
| 측정 항목 | RES / LKG | **Connectivity / PowerShort / PlaneResistance** |
| E-Test Spec | 고객 Spec 표 (RES > 715 Ω, LKG abs > 50 uA) | **파일 안 Upper / Lower Limit** (아래 5.3) |
| E-Test 파일명 | `CAI_OMM_ATV_A0_TSVET_..._U9-HS2635_U9-HS2635-01$Silterra$` | `CAI_PFIC_U8_A0_TSVET_..._U8-NPI_U8-NPI-01` (`$Silterra$` 없음) |
| KLARF Device | `OMM_Hybrid`, `OMM_TCB` | `OMM_U8` |
| Wafer 배치 | 76 Die 격자, Hybrid 는 Silterra 26 | **같음** (Silterra 26 Die 위치 일치) |

## 3. Wafer / Die (공통)

- KLARF `SampleTestPlan` 26 Die = U9 대응표(`SampleFile/U9_Die좌표_대응표_20261012.tsv`) 의 Silterra 26 Die BS KLARF 좌표와 **완전히 같다.**
- E-Test 76 DUT 중 **Connectivity 를 통과한 26 Die = 대응표 Silterra 26 Die 의 E-Test 좌표와 완전히 같다.** 나머지 50 Die 는 Connectivity 200 항목이 모두 Spec Out(값 약 0.003 mA, 실제 Die 가 없어 열린 상태로 보임).
- 결론
  - U8 은 U9 Hybrid 와 같은 Wafer Map / Die 대응표를 그대로 쓸 수 있다. U8 용 Map 을 새로 만들 때도 같은 형상(Edge 2,000 ~ 5,000 µm, 76 Die)이 나온다.
  - **비 Silterra 50 Die 는 판정 / 연관 분석에서 제외해야 한다.** 제외하지 않으면 Fail Chain(Net) 목록이 50 Die x 200 항목으로 넘친다. 대응표의 Silterra 열 또는 Map 의 검사 Die(KLARF SampleTestPlan) 기준으로 거른다.
- KLARF DiePitch 23,830 x 30,053 µm, SampleCenter (79, 14,860). U9 샘플(23,832 x 30,058 ~ 30,060)과 몇 µm 차이 -> Offset / 허용오차 논의와 같은 문제.

## 6. GDS (GDS Map / Chain 담당)

### 6.1 캡처로 본 구조

- 원형 Bump + 대각선 RDL + Via 끝단이 한 묶음이고, 같은 모양이 일정 간격 배열로 반복된다.
- 묶음마다 Net 이름 Label 이 하나씩 붙어 있다: `VSS_24776`, `NCV_247xx`, `VDD...HTR` 등. 고객 설명: "각 Functional Net 의 Net List 는 도면 내 Layer 에 반영".
- E-Test Net 이름(`VSS_15661`, `VDD_2162`)과 Label 형식이 같다. 캡처의 번호(24xxx)는 E-Test 샘플 번호(15xxx, 2xxx)와 다르므로 캡처는 다른 영역으로 보인다.

### 6.2 현재 Chain Rule 로 가능한지 (10/19 결정: POC 는 현재 Rule)

| 현재 기능 | U8 적용 | 판단 |
|---|---|---|
| Input / Output 단자 지정 + 경로 찾기(붙어 있는 도형) | Bump(Input) -> Via 끝단(Output) 으로 한 Net 묶음 영역 생성 | 가능. 묶음 하나가 짧아 경로 찾기는 단순 |
| Input 근처 Label 로 이름 자동 지정 | 묶음마다 Label 이 있어 Net 이름이 자동으로 붙음 | 가능 (Label Layer 확인 필요) |
| 유사 묶음 찾기(같은 크기 / 모양) | 같은 모양 묶음 수백 ~ 수천 개를 한 번에 찾음 | 찾기는 가능하나 **한 Chain 으로 묶임** -> Net 마다 이름이 다른 U8 에는 그대로 못 씀 (10/19 회의에서 확인) |
| Chain 수 | E-Test 측정 Net 200개(+ PlaneResistance) | Net 마다 하나씩 만들면 200회 수동 작업 |

- POC 현실안 [결정 필요]
  1. **측정 Net 중 Fail 난 Net(샘플에서는 Die#34 PowerShort 196개)부터, 또는 대표 Net 몇 개만** 현재 Rule 로 셋업해 연관 분석이 되는지 확인한다.
  2. 유사 묶음 찾기 결과를 Label 별로 나눠 Net 별 Chain 으로 만드는 기능(배열 Net 자동 추출)은 본 프로젝트 범위로 남긴다(10/19 결정).
- GDS 파일을 받기 전에는 Layer 번호, Label Layer, 단위, 도형 수, 파일 크기를 알 수 없다. **사용자가 SharePoint 에서 내려받아 `SampleFile` 아래에 두어야 다음 분석이 가능하다.**
