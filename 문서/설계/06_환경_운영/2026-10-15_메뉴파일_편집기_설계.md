# 메뉴 파일 편집기 (MenuFileEditor) 설계 / 결과

작성: 2026-10-15 / 작업 번호: CLAUDE-108 / 상태: 구현 완료, TEMP 빌드 + 자동 검사 PASS, 실제 화면 확인 대기

## 1. 목적과 범위

- 요청: 메뉴 파일(`MenuFile.mnu`)을 고치는 화면. 기존 도구는 왼쪽 조회(트리)가 없어지는 버그가 계속 생긴다. 순서 조정과 XML 에서 쓰는 값을 모두 고칠 수 있어야 한다. 기존 도구 캡처(트리 + ▲▼ + 속성 창) 참고.
- 범위: DACrux 클라이언트와 따로 실행하는 단독 도구(EXE). DACruxV5 / ENGUI / 기존 `DAcruxMenuEditor` 소스는 바꾸지 않는다.
- 범위 밖: 캡처에 있던 DB 모드(DB 메뉴 테이블 읽기 / 저장). 지금 POC 는 파일 메뉴만 쓴다.

## 2. 위치 / 빌드 / 실행

| 항목 | 내용 |

## 3. 화면 구성 (캡처 대응)

| 캡처 | 새 화면 |
| --- | --- |
| 위: DB / File, 경로, `...`, Save File / Save DB | 위: 파일 경로 / `...` / 다시 읽기 / 저장 / 다른 이름으로 저장 (DB 제외) |
| 왼쪽 트리 `[MNU_KEY] Caption`, 숨김 메뉴 회색 | 같음. 최상위 노드 = 파일 이름. 트리 위에 찾기 / 모두 펼치기 / 모두 접기 |
| 가운데 ▲ / ▼ | 같음. 트리에서 Ctrl+Up / Ctrl+Down, 오른쪽 클릭 메뉴에도 있음 |
| 오른쪽 속성 창 [01]~[06] | 같은 분류 / 표시 이름. Ribbon Tab / Group, RESV 03 까지 30개 열 전부 |
| 아이콘 칸 그림 + 16진수 | 칸에 그림 표시 + `32 x 32 (765 byte)` 요약, `...` 로 아이콘 창(그림 열기 / 지우기 / 그림 저장) |
| 아래 Delete / Save / Close | 같은 수준 추가 / 하위 추가 / 복제 / 삭제 / 검증 / 닫기 |

속성 창 규칙:

- Menu Key: 바꾸면 하위 메뉴의 Popup(Parent) Menu 도 같이 바뀌고, Menu ID 가 예전 Key 와 같으면 Menu ID 도 바뀐다. 빈 값 / 공백 / 중복 / ROOT 는 거부한다.
- Popup(Parent) Menu: 목록에서만 고른다(ROOT + 자기 자신과 하위를 뺀 Key). 바꾸면 새 부모의 마지막 순서로 가고 Level 이 자동으로 맞춰진다.
- Menu Order / Menu Level: 읽기 전용. 순서는 ▲▼, Level 은 부모에 맞춰 자동으로 정해진다.
- Enabled / Visible / Start / Multiple Dialog: True / False 선택.
- Stock Toolbar(빈 값 / MNU_DMS_LINK / MNU_EXPORT), Form Type(BASIC_FORM / MODAL_FORM / 빈 값): 목록 + 직접 입력.
- 아이콘: 그림 파일(PNG / ICO / BMP / GIF / JPG)을 32 x 32 또는 16 x 16 PNG 로 줄여 DACrux 형식(`89 50 4E ...`)으로 넣는다(비율 유지, 투명 배경).

## 4. 트리가 사라지지 않게 한 방법

캡처 도구의 소스는 저장소에 없다(`DAcruxMenuEditor` 는 FarPoint 표 방식의 다른 도구). 그래서 원래 원인은 확인하지 못했다. 대신 트리가 비거나 메뉴가 빠지는 흔한 경우를 구조로 막았다.

1. 데이터는 `MenuDocument` 하나만 쓴다. 트리 노드에는 DataRow 를 그대로 둔다(Key 가 바뀌어도 같은 노드).
2. 값만 바뀌면(Caption / Visible 등) 그 노드의 글자 / 색만 고친다. 트리 전체를 다시 만들지 않는다.
3. 부모 / 순서 / Key / 추가 / 삭제는 트리를 다시 만든다. 이때 펼침 상태 / 선택 / 맨 위 노드를 DataRow 기준으로 되살린다. 다시 만드는 코드는 `BeginUpdate` / try / finally `EndUpdate` 로 감싼다.
4. 속성 창에서 고친 경우는 속성 창 처리가 끝난 뒤(BeginInvoke) 한 번만 다시 만든다. 같은 메뉴면 속성 창 객체를 바꾸지 않고 Refresh 만 한다.
5. 다시 만들 때는 지금 선택한 메뉴를 우선한다(값 반영 직후 다른 메뉴를 눌렀으면 그 메뉴 유지). 선택한 메뉴를 지운 경우만 다음 형제 -> 이전 형제 -> 부모 순서로 고른다.
6. 부모가 없거나 순환하는 메뉴도 `(부모 없음) n개` 노드 아래에 보인다(조회에서 빠지지 않음, 검증에서 오류로 표시).
7. 파일 읽기에 실패하면 안내만 하고 지금 보던 문서 / 트리는 그대로 둔다.

## 5. 저장

- 형식: XML 선언(standalone) + `DataTable.WriteXml(WriteSchema)` 결과. 기존 편집 도구 / VS 저장과 같은 바이트(UTF-8 BOM 없음, CRLF, 2칸 들여쓰기, 스키마 `MainDataTable="Table1"`). `DataSet.WriteXml` 은 XML 선언과 `MainDataTable` 속성을 쓰지 않아 쓰지 않는다.
- 지금 원본 파일 3342번째 줄은 손으로 고친 흔적(`</Table1>  <Table1>`, 한 줄에 태그 2개)이 있다. 처음 저장하면 이 줄만 두 줄로 정리된다(값 변화 없음).
- 순서: 검증 오류가 있으면 저장 안 함 -> 기존 파일을 `%TEMP%\MenuFileEditor\backup\MenuFile_yyyyMMdd_HHmmss_fff.mnu` 로 백업(최근 30개) -> 같은 폴더 임시 파일에 쓴 뒤 바꿔치기.
- 연 뒤에 다른 곳(VS 등)에서 파일이 바뀌었으면 덮어쓸지 묻는다(기본 = 아니요).
- 저장하지 않은 변경이 있으면 닫기 / 다시 읽기 / 다른 파일 열기 때 저장 / 버리기 / 취소를 묻는다. Ctrl+S = 저장, F3 = 다음 찾기.

## 6. 검증 규칙 ([검증] 버튼, 저장 전 자동)

| 구분 | 내용 |
| --- | --- |
| 오류(저장 막음) | Key 빈 값 / 중복, Popup(Parent) Menu 빈 값 / 없는 부모, 순환, ENABLE / VISIBLE / IS_START / MULTI 가 True / False 가 아님, 아이콘 값을 그림으로 못 읽음 |
| 경고 | 화면 메뉴(BASIC / MODAL, 하위 없음)인데 Module / Assembly 빈 값(로그오프 / 종료 / 창 / 도움말 메뉴 제외), Module DLL 을 `100_ClientBin` 에서 못 찾음, Menu Level 과 실제 깊이 다름, 같은 부모 안 Menu Order 중복 |

결과 목록을 두 번 누르면 그 메뉴로 간다. 지금 원본 파일 = 메뉴 107개 / 오류 0 / 경고 6.

## 8. 검증 결과 (2026-10-15)

- 빌드: `MSBuild MenuFileEditor.csproj /p:OutDir=%TEMP%\chippac\build\menueditor\bin\` 경고 0.
- 자동 검사: `powershell -NoProfile -STA -ExecutionPolicy Bypass -File Verification\MenuFileEditorSmoke.ps1 -EditorExe <빌드 EXE>` -> `MENU_FILE_EDITOR_SMOKE=PASS (37)`.
  - 원본 메뉴 파일 사본 사용(원본은 바꾸지 않음), 화면은 화면 밖에 띄움, 속성 창 값은 속성 창 항목의 글자 입력 경로로 넣음, 예상하지 못한 메시지 창이 뜨면 닫고 FAIL.
  - 형식: 수정 없이 저장 = 기존 도구 저장 결과와 바이트 동일 / 원본과 공백 1줄 외 동일 / 저장 후 다시 읽기 값 동일 / DataSet.ReadXml 로 읽힘.
  - 동작: 위 / 아래 이동(MNU_ORDER 0..n-1), 맨 위에서 위로 안 됨, 값 변경 시 같은 노드만 갱신, Visible 회색, 부모 변경(Level / 예전 형제 순서), 순환 거부, Key 변경(하위 부모 같이 변경), 잘못된 Key 4종 거부, 값 반영 직후 다른 메뉴 클릭 시 선택 유지, 추가 / 하위 추가 / 복제 / 삭제(다음 형제 선택), 검증 오류 4종, 부모 없음 / 순환 메뉴 표시, 아이콘 32 / 16 변환 / 지우기, 찾기, 저장 백업, 외부 변경 확인, 없는 파일 열기 실패 시 트리 유지, 최소 크기 / 최소화 -> 복원.
  - 무작위 변경 300회(이동 / 부모 / 추가 / 하위 추가 / 복제 / 삭제 / Key / Caption / Visible / 펼침 전환): 매번 트리 노드 수 = 메뉴 수, 부모 / 형제 순서 일치, 선택 / 속성 창 일치, 펼친 노드 유지. 시드 3개(7 / 1234 / 99991) x 600회도 PASS. 끝난 뒤 검증 오류 0.
- 미확인: 실제 화면에서의 모양 / 조작감(회사 보안으로 화면 캡처 불가). 사용자 실행 확인 필요.
