> - 막대는 작업 중에만 보인다. 대기 상태와 작업이 끝난 뒤(완료 / 실패, 겹친 작업은 모두 끝난 뒤)에는 숨긴다.
> - 끝 문구(`이름 완료` / `실패`)는 그대로 남긴다.
> - 이전에는 끝나면 막대를 `Maximum = 1, Value = 1`(실패는 0)로 채워 남겼다.
> - 수정: `ProgressStatusBar.EndTask` -> `HideProgress()`(숨김 + Continuous + 값 0), `StartTask` 첫 작업에서 값 0 + 보임, Designer `progress.Visible = false`.
> - GdsMap EXE 화면(GdsMapForm / GdsMapViewForm / GdsDieAnalysisForm / MapCopyForm)은 자체 막대가 이미 끝나면 숨김이라 바꾸지 않았다.

## 1. 요청과 원인

- 요청(2026-10-14): "화면 아래에 CRUD 에 대한 프로그래스 바 필요. 방금 삭제 기능 해봤는데 화면 멈춤 현상 있음. 다른 화면들도 프로그래스바가 있어야 사용자가 알 수 있다. 동작 중인지. 죽었는지." 이어서 "처리하는데 시간이 걸린 상황이였음. 삭제 후 화면 제대로 작동".
- 원인: E-Test Para 설정 [선택 삭제] 로 Parameter 2,755개를 지울 때, 서버(`GdsEtResult_Para.DeleteEtParameters`)가 Parameter 마다 값 확인 조회 1번 + Spec 삭제 1번 + Parameter 삭제 1번(약 8,300번 DB 왕복)을 했다. 화면은 그동안 UI 스레드에서 서버 응답을 기다려 멈춘 것처럼 보였다.
- 조치 두 가지:
  1. 서버 묶음 처리: 삭제 = 등록 목록 1회 + 값 수 1회(Parameter 별 GROUP BY) + 배열 DELETE 2회. 사용 / 비고 저장 = 등록 목록 1회 + 배열 UPDATE 1회(없는 Parameter 가 섞이면 아무것도 저장하지 않음). 로컬 측정(같은 2,755개): 삭제 0.1초. 예전 한 건씩 방식은 삭제 쿼리만 15.7초(값 확인 2,755번 제외).
  2. 화면 아래 공통 진행 표시줄 + 오래 걸리는 작업을 작업 스레드에서 실행.

## 2. 공통 컨트롤 `DACrux.SEMDMS.Control.ProgressStatusBar`

위치: `DMS/02_DMS/DACrux.SEMDMS.Control/ProgressStatusBar.cs` / `.Designer.cs` (SEMDMS.ENGUI 와 TEST.ENGUI 가 모두 참조하는 프로젝트).

| 기능      | 내용                                                                                                       |
| ------- | -------------------------------------------------------------------------------------------------------- |
| 배치      | 화면 아래 한 줄: 왼쪽 기존 상태 Label(Fill) + 오른쪽 진행 표시줄(폭 420). 상태 Label 이 없는 조회 창은 맨 아래 한 줄                        |
| 작업 중 표시 | `작업 이름 중 · 경과 시간 · 지금 단계 · 대상 (처리 수 / 전체)` 0.2초마다 갱신. 막대는 전체 수를 모르면 계속 움직이고(Marquee), 알면 비율로 찬다          |
| 끝난 뒤    | `작업 이름 완료 · n.n초 (HH:mm:ss)` 회색 / 실패 `실패` 빨간색 / 중간 단계만 실패 `끝 (오류 있음)`                                    |
| 입력 막기   | 작업 중 그 화면(자식 컨트롤 포함)으로 가는 키 / 마우스 메시지를 버린다(IMessageFilter). 다른 화면, 창 제목 표시줄은 그대로. 모래시계 커서(UseWaitCursor) |
| 닫기 미루기  | 작업 중 화면 닫기(사용자 / MDI 닫기)는 취소하고 "끝난 뒤 닫을 수 있습니다". Windows 종료 / 프로그램 종료 요청은 막지 않는다                         |
| 겹친 작업   | 진행 중 작업을 목록으로 관리. 표시 이름 / 경과 시간은 처음 시작한 작업, 입력 차단은 막는 작업이 하나라도 있으면 유지. 끝나는 순서가 섞여도 맞게 풀린다                |

사용법(화면 코드):

| 메서드 | 쓰는 곳 |
| --- | --- |
| `Run(이름, () => 서버 호출)` | 버튼 처리기의 서버 호출 / 파일 읽기. 작업은 별도 스레드, 화면은 끝날 때까지 메시지를 처리하며 기다린다. 부르는 쪽에서는 보통 메서드처럼 결과를 받으므로 기존 순서(확인 창 → 저장 → 다시 조회)와 Smoke 의 리플렉션 동기 호출이 그대로 동작한다. **작업 안에서 화면 컨트롤을 만지지 않는다**(값은 미리 지역 변수로) |
| `RunSteps(이름, report => ...)` | 처리 수를 알 수 있는 반복(이미지 전송, Spec 여러 행 삭제) |
| `RunHere(이름, () => ...)` | 콤보 / 입력 칸 / 표 선택 변경 이벤트처럼 메시지를 처리하면 안 되는 곳. 화면 스레드에서 실행하고 표시만 |
| `using (Begin(이름)) { ... }` | 버튼 하나의 여러 단계(서버 호출 + 다시 조회 + 표 채우기)를 한 작업으로. `Begin(이름, false)` 는 입력을 막지 않는 표시(업로드 백그라운드 분석) |
| `Step / Note / Pulse` | 처리 수 / 처리 대상 이름 / 화면 스레드 반복문 안 표시 갱신 |

검사 편의: `RunInBackground = false` 면 화면 스레드에서 바로 실행(표시는 같음), `LastResult` / `DisplayText` / `IsBusy`.
