## 2. 현재 상태 (소스 확인 + 측정)

### 2.1 대기 커서는 이미 일부 있다

- 공통 진행 표시줄 `DACrux.SEMDMS.Control.ProgressStatusBar`(2026-10-14)가 막는 작업(`Run` / `RunSteps` / `RunHere` / `Begin(이름)`) 동안 `form.UseWaitCursor = true` 를 켠다. 쓰는 화면 9개: KLARF 업로드 / KLARF 조회 / 연관 분석 / Para 등록 / Para 설정 / 결과 업로드 / 결과 조회 창 / File Map Setup / Wafer Map 조회.
- GdsMap EXE: `SubDeviceSetupForm` 은 `UseWaitCursor`, `GdsDieAnalysisForm` 은 `Form.Cursor = WaitCursor`. `GdsMapForm` / `GdsMapViewForm` 은 대기 커서 없음(경과 시간 칸 / 진행 막대 / 버튼 비활성만).
- 운영 `100_ClientBin` DLL(10-14 17:12)은 `ProgressStatusBar.cs`(10-14 12:24)보다 새것이라, 사용자는 이미 이 동작을 쓰고 있을 가능성이 높다. 그런데도 모래시계가 안 보인다는 요청이다.

### 2.2 모래시계가 안 보이는 이유 (측정)

`UseWaitCursor` 는 컨트롤의 커서 값만 바꾼다. 실제 커서 모양은 Windows 가 다음 `WM_SETCURSOR`(보통 마우스가 움직일 때)를 보낼 때 바뀐다. 버튼을 누른 뒤 마우스를 가만히 두면 화살표 그대로이고, 화면 스레드에서 바로 실행하는 `RunHere` 는 메시지를 처리하지 못해 마우스를 움직여도 안 바뀐다.

측정 프로그램 `%TEMP%\chippac\cursorprobe\CursorProbe.exe` (마우스 아래 작은 창, `GetCursorInfo` 로 실제 커서 확인, 2회 같은 결과):

| 경우 | 실제 커서 |
| --- | --- |
| `UseWaitCursor = true` 만 (0.3초 메시지 처리) | **화살표** |
| `UseWaitCursor = true` + `Cursor.Current = Cursors.WaitCursor` | **모래시계** (바로) |
| 위 상태에서 화면 스레드 막음(`RunHere` 와 같은 상황) | **모래시계** 유지 |
| 끝: `UseWaitCursor = false` + `Cursor.Current = Cursors.Default` | 화살표 |

-> 공통 진행 표시줄이 커서를 켤 때 `Cursor.Current` 를 같이 바꾸면 9개 화면이 한 번에 고쳐진다. (측정 중 마우스가 조금 움직였음. 마우스가 창 안에 있을 때 값만 적었다.)

## 3. 설계

### 3.1 공통 대기 커서 (`DACrux.SEMDMS.Control`)

- 새 공용 클래스 `BusyCursor` (같은 프로젝트, 정적 함수 2개 + using 용 범위 1개):
  - 켜기: `form.UseWaitCursor = true` + 마우스가 그 화면 위에 있으면 `Cursor.Current = Cursors.WaitCursor` (바로 바뀜, 화면 스레드가 막혀도 유지).
  - 끄기: `UseWaitCursor` 를 원래 값으로 + 마우스가 그 화면 위에 있으면 `Cursor.Current = Cursors.Default` (다음 마우스 이동 때 원래 컨트롤 커서로 돌아감).
  - `UseWaitCursor` 는 자식 컨트롤 커서를 보관했다가 되돌리므로 지도 조작 커서(Cross / SizeAll)를 망가뜨리지 않는다.
- `ProgressStatusBar.UpdateBlock` 이 `BusyCursor` 를 쓰도록 바꾼다 -> 막는 작업을 쓰는 9개 화면은 화면 코드 수정 없이 해결.
- 입력을 막지 않는 작업(`Begin(이름, false)`, 결과 업로드의 백그라운드 분석): 결정 D2.
- 진행 표시줄이 없는 호스트 화면(`frmGdsMapSetup` / `frmGdsMapView` / `frmGdsDieAnalysis`)은 `using (BusyCursor.Show(this)) { … }` 로 감싼다.

### 3.2 화면별 빠진 곳 보완

2.3 표의 SEMDMS / TEST 이벤트를 `using (busyBar.Begin("…"))` (서버 호출이 없거나 화면 스레드 작업이면 표시줄 + 커서만) 또는 기존 `RunHere` 범위를 넓혀 감싼다.

| 화면 | 방법 |
| --- | --- |
| `frmKlarfUpload` / `frmKlarfFileViewer` | 선택 변경 처리 전체를 `Begin("표시")` |
| `frmGdsKlarfAnalysis` | `LoadSelectedWafer` 전체를 `Begin("Wafer 조회")` 하나로(안쪽 `Run` 은 그대로, 깜빡임 없어짐). `btnAnalyze_Click` 은 `ApplyResult` 까지 같은 `Begin`. `SelectDie` / `OpenDetail` 은 `Begin` |
| `frmEtResultUpload` | `dgvQueue_CellEndEdit` 의 서버 확인을 `RunHere`, 선택 변경 2개는 `Begin("표시")` |
| `frmEtParaSetup` | `ChangeGdsDevice` 의 `RunHere` 를 `PaintGds` 까지 넓힘 |
| `frmStandardMapSetup` | 원형 Map 다시 만들기 / Die 지우기 2개 / 기존 Map 열기를 `Begin` |
| `frmStandardMapView` | `LoadSelectedMap` 의 `RunHere` 를 `ShowStoredMap` 까지 넓힘 |
| 호스트 3개 | `OnShown` 의 EXE 읽기, `ShowDefectImages` 를 `BusyCursor` |

확인 창(MessageBox)이 막는 작업 안에서 뜨는 곳(Para 등록 / 설정의 일부 Notify, KLARF 조회 색 기준 오류)은 이번에 구조를 바꾸지 않는다. 확인 창은 별도 창이라 입력 / 커서에 문제가 없고, 뒤 화면만 모래시계로 보인다.

### 3.3 GdsMap EXE (`06_CoreLibSource/GdsMapControl`)

GdsMap 은 버전 충돌을 피하려고 별도 폴더에서 읽으므로 `DACrux.SEMDMS.Control` 을 참조하지 않는다. 같은 내용의 작은 클래스를 GdsMap 안에 둔다.

- `ElapsedStatusTicker` 를 "작업 중 표시"로 바꾼다: 시간 대신 `작업 중` 문구(끝나면 빈 칸)를 보이고, 시작 / 끝에서 화면의 대기 커서를 켜고 끈다(3.1 과 같은 방식). 이미 이 클래스를 쓰는 곳(GDS 읽기 / DB 저장 / 조회 / Chain DB 저장 / Die 분석 조회)은 자동으로 모래시계가 된다.
- 이 클래스를 안 쓰는 비동기 작업(`GdsMapViewForm` 의 Device 목록 / Device 선택 / 조회 1 / 2단계 / Map 삭제 1단계 / Chain 찾기 / 유사 묶음 / 적용, `cboViewSide` 반전, `GdsMapForm` Excel Export)은 같은 대기 커서 범위로 감싼다. 커서 종류는 결정 D3.
- `GdsDieAnalysisForm.SetBusy` 의 `Form.Cursor` 를 같은 방식(`UseWaitCursor`)으로 바꿔 지도 위에서도 보이게 한다.
- 지도 조작 커서(`map.Cursor = Cross / SizeAll`, GdsMapViewForm_Chain / _ChainEdit / _ChainExample / _ChainList, Designer)는 건드리지 않는다.

### 3.5 이번에 손대지 않는 것

- 글자를 칠 때마다 도는 표 필터(Para 등록 / 설정 찾기 칸, 결과 조회 창 필터): 매 글자마다 모래시계가 깜빡이는 것이 더 거슬린다. 느리면 별도로 입력이 멈춘 뒤 한 번 거르는 방식으로 다룬다.
- 콤보 / Leave 이벤트 안의 `Run`(메시지를 처리하며 기다림, `ProgressStatusBar` 주석은 이런 곳에 `RunHere` 권장): frmGdsKlarfAnalysis 139, frmEtResultUpload 884, frmEtParaSetup 223 / 1090 / 1104, frmEtParaRegister 135. 지금 문제는 없어 이번 범위에서 바꾸지 않고 기록만 한다.
- POC 메뉴 밖 기존 DACrux 화면.

## 5. 그리드 스크롤 잔상 (CLAUDE-105)

- 원인: POC 화면 그리드는 모두 기본 `DataGridView` 이고 이중 버퍼가 꺼져 있다. SEMDMS / TEST 8개 화면 18개 + GdsMap EXE 4개(Die 분석 2 / GDS Map 설정 1 / Sub Device 1). 투명 / 반투명 셀 색, 직접 그리기, `WS_EX_COMPOSITED` 는 없다. 기존 DACrux 화면은 FarPoint Spread(자체 이중 버퍼)라 같은 현상이 없다.
- 측정(`%TEMP%\chippac\gridprobe\GridScrollProbe.exe`, 행 2,000 x 열 10, 3행씩 40번 스크롤, 원격 데스크톱 아님):

| 설정 | 스크롤 한 번 다시 그리기 평균 |
| --- | --- |
| 기본 | 44.2ms |
| 이중 버퍼 | 4.0ms |
| DisplayedCells 열 자동 너비 | 39.8ms |
| DisplayedCells + 이중 버퍼 | 3.6ms |

  화면 갱신 한 번(16.7ms)보다 2 ~ 3배 길어 바탕 지움 -> 칸 그리기 중간 상태가 보이고, 휠을 계속 돌리면 잔상으로 남는다.
- 조치: 화면 안의 `DataGridView` 를 모두 찾아 이중 버퍼(보호 속성 `DoubleBuffered`)를 켜는 공용 함수 `GridBuffer.Enable(Control)` (SEMDMS.Control, GdsMap 은 같은 내용 1개) + 각 화면 생성자 `InitializeComponent()` 뒤 1줄. Designer 의 그리드 종류는 바꾸지 않는다. 나중에 코드로 만드는 그리드도 있으면 같은 함수를 부른다.
