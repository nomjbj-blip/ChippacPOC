# 클라이언트 설치 파일(Setup) 설계

작성: 2026-10-14 / Claude (CLAUDE-088) / 상태: **구현 / 검증** (결정 S1~S13 권장안 채택, 구현 결과는 16절)

- v1: Setup 방식 / ClickOnce 비교 / 설치 위치 / 재설치 흐름.
- v2 (같은 날 추가 지시): **Setup 한 번 실행으로 필요한 구성 요소와 설정이 모두 설치되어야 한다.** -> .NET Framework 4.8을 Setup에 포함(5.1절), 설치 끝에 환경 점검(5.2절)을 추가했다.
- 구현 (같은 날, "진행"): 빌드 구성만 설계와 다르게 바꿨다. Release 구성은 Debug와 참조 / 플랫폼이 달라 로그인 직후 오류가 날 수 있어, **Debug 구성 + DEBUG 기호 제외**로 빌드한다(16.2절).

## 1. 요청과 범위

- 서버(`101_ServerBin`)는 엔지니어가 직접 배포한다(수동).
- 사용자(고객 엔지니어)는 **Setup 파일로 클라이언트를 설치**한다.
- **Setup 한 번 실행으로 프로그램 / 필요한 구성 요소 / 설정이 모두 끝나야 한다.** 사용자가 다른 프로그램을 따로 찾아 설치하거나 설정 파일을 직접 고치지 않는다.
- 새 버전은 **새 Setup 실행 -> 기존 버전 삭제 -> 재설치** 방식이다. 프로그램이 스스로 업데이트하지 않는다.
- ClickOnce도 후보지만 제약을 확인한다. POC이므로 자동 설치 / 자동 업데이트는 쓰지 않는다.
- 배경: 2026-10-13 협의 회의 Action Item "서버 확보 후 설치 파일과 DB 전달". 개발자 철수 후 고객이 PC에 직접 설치해 쓴다. 고객 서버는 수배 중이라 **서버 주소가 아직 정해지지 않았다.**

이 문서는 클라이언트 Setup만 다룬다. DB 전달과 서버 설치 절차는 별도로 정리한다. 11절에서 서버와 버전을 맞추는 규칙만 정한다.

### 2.3 빌드 구성 (Setup은 Release로 만들어야 한다)

- 지금 `100_ClientBin`은 **Debug 빌드**다. Debug는 로그인 창 없이 `ADMIN`으로 바로 들어간다(`DACruxClientMain.cs:134-140`). 고객에게 그대로 주면 안 된다.
- Release와 Debug의 다른 점(클라이언트): 로그인 창 표시 / 오류 창에 스택 추적 없음(로그 파일에는 남음, `DCMH.cs:34`) / Defect Map 십자선 기본값 끔(`DPUCDefecMapViewer.cs:2043`).
- **GdsMap은 지금 Release로 빌드할 수 없다.** Release 출력이 `bin\Release`이고 `AllowUnsafeBlocks`가 없어 CS0227로 실패한다(`NexplantQMS.GdsMap.csproj:31-35`, 2026-10-08 빌드경로 설계 7절의 남은 문제).
- 모든 csproj의 Debug / Release 출력이 운영 폴더(`100_ClientBin` / `101_ServerBin`)다. VS에서 Release로 빌드하면 개발용 Debug 산출물이 덮인다.

### 2.5 기존 ClickOnce 설정이 남아 있다

`DACruxV5.csproj:25-49, 84-98`에 다른 사이트용 ClickOnce 게시 설정이 남아 있다.

- 게시 / 설치 주소 `ftp://10.148.1.30/DACrux/` / `http://10.148.1.30/DACrux/`, 제품명 `DACruxV5_FAB1`, `MinimumRequiredVersion 1.0.0.151`, 매 실행 전 업데이트 확인 + 필수 업데이트, 서명 안 함.
- `GenerateManifests=true`라서 빌드할 때마다 `100_ClientBin\DACruxV5.application` / `DACruxV5.exe.manifest` / `app.publish\`가 새로 생긴다(Git에도 추적됨). POC에서 ClickOnce 게시를 시도한 결과가 아니다.
- 프로그램은 ClickOnce로 실행될 때만 10분마다 새 버전을 확인하고 제목을 `DACrux Ver : x`로 바꾼다(`DACruxMain.cs:91, 100, 432`). Setup 설치에서는 동작하지 않는다.

### 2.6 버전과 서버-클라이언트 짝

- 클라이언트 / 서버 DLL의 AssemblyVersion은 거의 모두 `1.0.0.0` 고정이다(SEMDMS.Control만 `1.0.*`).
- Remoting은 binary formatter에 DataTable / DataSet / 기본형을 주고받는다. 버전 숫자 차이에는 둔감하지만 **인터페이스 메서드나 DataTable 열이 바뀌면 깨진다.**
- 서버와 클라이언트 버전을 비교하는 코드가 없다. 버전 숫자로 불일치를 알아낼 방법도 없다. -> 11절의 수동 규칙이 필요하다.

## 3. ClickOnce를 쓰지 않는 이유

| 제약 | 이 프로젝트에서의 영향 |
| --- | --- |
| 매니페스트에 든 파일만 내려간다 | 현재 빌드가 만든 매니페스트에 `GdsMap\*`이 **0건**이다(.NET 4.0 EXE가 4.8 프로젝트 참조를 해석하지 못함). 그대로 게시하면 GDS 화면이 열리지 않는다. GdsMap / OpenTK를 Content로 직접 등록하고 파일이 바뀔 때마다 맞춰야 한다. 메뉴 DLL을 새로 추가할 때도 같다 |
| 버전마다 새 폴더(`%LOCALAPPDATA%\Apps\2.0\<임의 이름>`) | 프로그램이 ini에 저장한 UserID / ServerIP / Factory가 업데이트 때마다 게시본 값으로 돌아간다. 설치 위치를 사용자가 찾기 어려워 문제 확인이 어렵다 |
| 서버 주소를 게시본에 넣어야 한다 | ServerIP는 ini로만 바뀌므로 사이트(서버)마다 따로 게시해야 한다. 고객 서버 주소가 아직 없다 |
| 게시 서버가 필요하다 | 고객 사내에 웹(IIS) 또는 공유 폴더를 두고 개발자 철수 후에도 고객이 운영해야 한다. 현재 설정(실행 전 필수 업데이트)은 게시 서버에 접속하지 못하면 시작이 지연되거나 실패한다 |
| 업데이트가 자동이다 | 요청과 반대다. 업데이트를 끄면 ClickOnce를 쓸 이유가 거의 남지 않는다 |
| 선행 조건 설치가 별도 단계다 | .NET 4.8은 부트스트래퍼(`setup.exe`)가 따로 처리하고 현재 설정은 .NET 4.0 기준이다. "한 번 실행으로 모두 설치" 요구와 맞지 않는다 |
| 기존 설정이 다른 사이트용이다 | 주소 / 제품명 / 최소 버전 / 선행 조건을 모두 다시 잡아야 한다. 잘못 게시하면 다른 사이트 주소로 나갈 수 있다 |
| 보안 정책 | 서명 없는 매니페스트는 "알 수 없는 게시자"로 표시된다. 회사 정책으로 ClickOnce 신뢰 확인 창 자체를 막는 경우가 있다 |

결론: Setup 파일 방식으로 간다. ClickOnce 설정 정리는 결정 S9에서 다룬다.

### 5.2 환경 점검 도구 `SCK_EnvCheck.exe`

설치 마지막 화면에서 자동 실행하고, 시작 메뉴 "SCK E-Test POC 설치 점검"으로 언제든 다시 실행한다. 결과는 화면 표와 `설치 폴더\설치점검_결과.txt`에 남긴다(원격 지원 때 파일만 받아 보면 된다).

| 점검 | 방법 | 판정 |
| --- | --- | --- |
| .NET Framework | 레지스트리 Release 값 | 528040 이상 = 정상 |
| 설치 폴더 쓰기 | 임시 파일 쓰기 / 삭제 | 실패 = 로그인 불가 경고 |
| 필수 파일 | `파일목록.txt`와 SHA-256 비교 | 누락 / 변경 파일 표시 |
| 서버 연결 | ini의 ServerIP로 TCP 7510 / 7513 / 7515 연결(3초 제한) | 포트별 성공 / 실패 |
| Defect 이미지 FTP | 같은 서버 21번 연결 | 참고 표시(FTP 주소는 로그인 후 서버 설정에서 받으므로 다를 수 있음) |
| 그래픽 | OpenTK로 숨은 창을 만들어 OpenGL 버전 / 장치 이름 확인 | 3.3 이상 = 정상, 미만 = "GDS 화면 사용 불가" |
| Excel | 레지스트리 `Excel.Application` 등록 여부 | 없음 = "일부 Download 기능 사용 불가" 안내(오류 아님) |

- .NET 4.8 / C# WinForms 작은 프로그램으로 만든다. OpenTK는 설치 폴더의 `GdsMap\OpenTK.dll`을 그대로 쓴다(`app.config` probing `GdsMap`).
- 저장소 위치 `DMS/12_Setup/EnvCheck/`(솔루션에는 넣지 않고 Setup 빌드 스크립트가 따로 빌드). 결정 S13.

## 6. 설치 파일 구성

### 6.1 포함 / 제외 규칙

기본은 Release 빌드 후 `100_ClientBin` 전체(하위 폴더 `GdsMap\`, `APPStyle\` 포함)이며 아래만 뺀다. DLL은 쓰지 않는 것처럼 보여도(NMath 커널 / Oracle.ManagedDataAccess / IBM.Data.DB2 등) 빼지 않는다. 빼서 얻는 크기보다 화면 하나가 실행 중에 깨질 위험이 크다.

| 제외 | 이유 |
| --- | --- |
| `*.xml` 중 DLL / EXE와 이름이 같은 문서 주석 파일 | 82 MB, 실행과 무관. `MenuFile.mnu` 같은 설정은 확장자가 달라 해당 없음 |
| `*.vshost.exe`, `DACruxV5.application`, `DACruxV5.exe.manifest`, `app.publish\` | VS / ClickOnce 부산물 |
| `excel_temp*.xls`, `temp_chart*.bmp`, `tmpMap_*.bmp`, `DEFECT_IMAGE\` 안의 파일, `AVI\`, `Temp\` | 실행 중 생기는 임시 파일 |
| `*.pdb` | 결정 S6 (권장: 포함) |

### 6.2 설치 후 폴더

```text
%LOCALAPPDATA%\Programs\SCK_ETest_POC\
 ├ DACruxV5.exe / DACrux.*.dll / FarPoint.* / Infragistics* ...
 ├ DACruxConfig.ini        <- 설치 때 ServerIP / Factory 기록, 이후 프로그램이 로그인 때마다 다시 씀
 ├ MenuFile.mnu / Global.Lng
 ├ GdsMap\                 <- NexplantQMS.GdsMap.exe / OpenTK*.dll (폴더 이름 변경 금지)
 ├ APPStyle\

 ├ SCK_EnvCheck.exe (+ .config)  <- 환경 점검 도구
 ├ 설치점검_결과.txt       <- 점검 도구가 씀

```

.NET 설치 파일은 설치 폴더에 남기지 않는다(필요할 때 임시 폴더에 꺼내 실행 후 삭제).

### 6.3 DACruxConfig.ini 기록 값

| 키 (`[LAST OPTION]`) | 값 |
| --- | --- |
| `ServerIP` | 설치 화면 입력값 |
| `EAIServerIP` | 같은 값(코드에서 접속에 쓰지 않음, 값만 맞춤) |
| `Factory` / `FactoryList` | `SCK` (로그인 화면의 Factory 선택은 숨겨져 있음) |
| `UserID` | 재설치면 이전 값, 처음이면 빈 값 |
| `Language` | 재설치면 이전 값, 처음이면 `English`(현재 값) |

`[APPLICATION UNIT]` 포트는 빌드 결과 파일 그대로 둔다. 프로그램이 ini를 다시 쓸 때 `MANUALURL` 줄을 빼는 기존 동작(`Config.cs:232-243`)은 이번 범위에서 고치지 않는다.

## 7. 설치 / 재설치 / 삭제 흐름

### 7.1 설치 (재설치 포함)

```text
Setup 실행 (일반 사용자 권한)
 -> 실행 중인 DACruxV5 확인 ------------------- 있음: 종료 요청 (Restart Manager)
 -> 기존 설치 확인 (HKCU 프로그램 제거 목록, 고정 AppId)
     있음 -> "기존 버전 x 를 삭제하고 새 버전 y 를 설치합니다" 안내 / 기존 ini 의 ServerIP / UserID / Language 보관
 -> 서버 주소 입력 화면 (기본값: 보관 값 > 빌드 기본값)

 -> [.NET 4.8 없음] 포함된 설치 파일을 임시 폴더에 꺼내 관리자 권한으로 실행 (UAC 확인 창)
       성공           -> 계속
       재부팅 필요     -> 계속, 마지막에 재부팅 안내 (1641 / 3010)
       거부 / 실패     -> 중단. 기존 버전은 아직 지우지 않은 상태 그대로. 이유와 로그 위치 표시
 -> [기존 설치 있음] 기존 Uninstaller 무음 실행 (/VERYSILENT /SUPPRESSMSGBOXES /NORESTART) -> 끝날 때까지 대기
       -> 설치 폴더에 지난 DLL / EXE 가 남지 않았는지 확인 (남으면 중단, 이유 표시)
 -> 파일 복사 / DEFECT_IMAGE 빈 폴더 / DACruxConfig.ini 값 기록 (6.3절)
 -> 바로 가기: 시작 메뉴(프로그램 / 설치 점검 / 삭제) + 바탕 화면(선택), "시작 위치" = 설치 폴더

```

- .NET 설치를 기존 버전 삭제보다 먼저 한다. .NET 설치가 실패해도 쓰던 프로그램이 지워지지 않는다.
- 관리자 권한이 없는 사용자는 UAC 창에 관리자 계정을 입력하면 된다(.NET은 PC 전체에 설치되고, 프로그램은 원래 사용자에게 설치된다). Windows 10 1903 이상 / 11에서는 이 단계가 나오지 않는다.
- 같은 버전을 다시 실행해도 같은 흐름(삭제 후 설치)으로 처리한다. 서버 주소만 바꾸고 싶을 때도 Setup을 다시 실행하면 된다.

### 7.2 삭제 (프로그램 추가 / 제거 또는 시작 메뉴)

- 설치한 파일 전부 + 실행 중 생긴 임시 파일(6.1절 임시 파일 목록) + `설치점검_결과.txt`를 지운다.
- 그 밖에 사용자가 설치 폴더에 만든 파일(예: TEST 화면 캡처 폴더)은 지우지 않는다. 남은 파일이 있으면 폴더도 남는다.
- `%LOCALAPPDATA%\DACrux\Log`, `내 문서\DACrux\`는 지우지 않는다.
- .NET Framework는 다른 프로그램도 쓰므로 지우지 않는다.

### 7.3 명령줄 (시험 / 일괄 설치용)

```text
SCK_ETest_POC_Client_Setup_2026.10.14.1.exe /SILENT /SERVERIP=10.x.x.x
SCK_ETest_POC_Client_Setup_2026.10.14.1.exe /VERYSILENT /SUPPRESSMSGBOXES /SERVERIP=10.x.x.x /DIR="D:\Test\SCK"
```

`/SERVERIP`는 Setup 스크립트에서 받는 사용자 정의 인자다. `/DIR`은 Inno Setup 기본 인자다. 무음 설치에서도 .NET이 없으면 UAC 확인 창은 뜬다(관리자 권한으로 Setup을 실행하면 뜨지 않음). 무음 설치의 환경 점검은 화면 없이 결과 파일만 쓴다.

### 16.5 사용 방법

- 만들기: `Build-ClientSetup.ps1 -ServerIP <고객 서버 주소>` -> 결과 `DMS\104_ClientSetup\<버전>\`. 빌드 전에 작업 현황에서 다른 세션이 파일을 고치는 중인지 확인한다.

### 16.9 Release 구성 선택 (2026-10-21)

질문 "왜 release mode 로 빌드가 안되지? debug 로 빌드 되도 되나?" -> 16.8 의 Setup 솔루션에 Debug 구성만 있었고, Build-ClientSetup 이 안에서 Debug 구성 + DEBUG 기호 제외로 고정이었다(16.2 근거는 10-14 당일 CLAUDE-091 로 해소). 사용자 "제안대로" 로 Release 를 고를 수 있게 했다.

- `Build-ClientSetup.ps1 -Configuration Debug|Release` (기본 Debug). Debug = `/p:Configuration=Debug /p:DefineConstants=TRACE` 그대로 / Release = `/p:Configuration=Release`(프로젝트별 Release 기호, 최적화). 빌드 구성은 화면 / 버전정보.txt / 빌드기록.txt / 서버 묶음 읽어보기에 남고, `-SkipBuild` 는 복사본 빌드의 구성(`build_config.txt`, 없으면 Debug)과 다르면 멈춘다.
- VS: `DACrux_SCK_Setup.sln` 에 Release 구성 추가. 도구 막대에서 고른 Debug / Release 를 따르고, `SetupSettings.props` 의 `SetupConfiguration` 으로 고정할 수 있다. 고객 전달용은 Release 권장.
- Release 와 Debug(DEBUG 제외)의 차이: 클라이언트는 같은 코드 경로(DEBUG 없음) + 최적화 켜짐 / 서버 묶음의 데이터 서비스는 `SINGLE_EQUIP`(설비별 Windows 서비스) / `DACrux.SEMDMS.BSL` 은 Release 에도 `DEBUG;TRACE`(소스에 DEBUG 분기·Debug 호출 없음, 서버 전용) / `TEST.ENGUI` Release 기호 비어 있음(TRACE 없음).
- 확인: TEMP 복사본 메인 솔루션 Release 빌드 오류 0(Middleware 893E8D59 / ProjectManager MSIL) / VS 와 같은 방식(MSBuild sln `/p:Configuration=Release`, 시험 버전 2026.10.21.91, `_test`)으로 Setup -> 솔루션 오류 0 / 경고 79, 자동 로그인 코드 없음, 자동 검사 36/36 / stage DLL 최적화 켜짐(DebuggableAttribute 에 DisableOptimizations 없음, Debug 판은 있음) / Debug `-SkipBuild` 경로 PASS / 구성 다른 재사용 FAIL 확인. Release 로 설치한 화면의 GDS / KLARF / E-Test 주요 기능 확인은 사용자.
