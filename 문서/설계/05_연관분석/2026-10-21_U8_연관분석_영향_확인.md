- 요청: "U8의 Data가 상당히 많다. 해당Data 기반으로 분석 시 영향이 많이 가는제 확인 한번 해줘"

| --- | ---: | ---: |

## 7. 측정 방법 (저장소 밖)

- 측정 도구 `U8Impact.exe`(저장소 밖 임시 폴더 `u8imp`): 운영 폴더 DLL 복사본을 참조해 `GdsKlarfAnalysis.Analyze / AnalyzeDie`, `GdsKlarfShapeIndex.Build`, `GdsChain.GetChainMembers`, `GdsDieAnalysisForm.ShowDieAsync`(화면 밖)와 합친 탭 다시 채우기 / [걸린 / Fail Chain 만] 끄고 켜기를 직접 호출. RO 는 BSL 객체를 연결해 in-proc 로 부름.
- 메모리는 측정 프로세스 기준(관리 힙 / Private / 최대 Working Set). DMS(DACruxV5)에서는 다른 화면 메모리가 더해진다.
- DB 조회: `docker exec oracle19c-DMS sqlplus`(SELECT 만): 장치별 Chain / Member / 점 수, KLARF Step / E-Test 파일 목록.
- U8 KLARF 원본 Defect 분포: `SampleFile/26_10_20 Sample File U8/XD093.01.001` 을 읽기만 해서 셈.
