# GDS Map 복사 설계 (Sub Device 기능 대체)

작성: 2026-10-15 / 작업 ID: CLAUDE-109 / 상태: 구현 완료(코드) / TEMP 빌드 + Probe·Smoke 확인 / 배포 안 함

## 1. 요청

- GDS Map View(GDS Map 조회) 화면에서 [복사] 버튼 -> 팝업에서 새 Device 이름 입력 -> 저장하면 지금 Device 의 Map 과 Chain 정보가 새 Device 이름으로 복사되어 생성된다.
- 복사 기능이 끝나면 기존 Sub Device 기능은 제거한다(복사로 같은 도면을 쉽게 만들 수 있으므로 필요 없음).

## 2. 지금 구조 (로컬 DB 확인 2026-10-15)

| 테이블 | 키 | 비고 |
| --- | --- | --- |
| `TQP_GDS_MAP` | FACTORY + DEVICE_ID | 헤더. MAP_STATUS DRAFT / READY |
| `TQP_GDS_LAYER` | + LAYER_ID | FK MAP (CASCADE) |
| `TQP_GDS_PLACED_EL` | + PLACED_ELEMENT_ID | FK LAYER. 도형 + 좌표 BLOB. U9 = 204,898행 |
| `TQP_GDS_IMPORT_JOB` | IMPORT_JOB_SEQ(시퀀스), UQ FACTORY + DEVICE_ID | 저장 건수(조회 화면 Map 정보) |
| `TQP_GDS_IMPORT_BATCH` | 작업 번호 | 저장 중에만 쓰고 완료 후 비어 있음 -> 복사 안 함 |
| `TQP_GDS_CHAIN` | + CHAIN_SEQ(시퀀스), UQ + CHAIN_CODE | FK MAP (CASCADE) |
| `TQP_GDS_CHAIN_VER` / `_LAYER` / `_RULE` / `_MEMBER` / `_EDIT` | + CHAIN_SEQ + VERSION_NO ... | FK CHAIN_VER (CASCADE), MEMBER / EDIT -> PLACED_EL, LAYER / RULE -> LAYER |

모든 테이블이 FACTORY + DEVICE_ID 를 키에 포함하므로 DB 안에서 `INSERT ... SELECT` 로 DEVICE_ID 만 바꿔 복사할 수 있다(도형을 화면으로 내려받지 않음).

## 3. 복사 규칙 (권장안으로 진행)

| 번호 | 항목 | 적용 |
| --- | --- | --- |
| C1 | 복사 범위 | Map 헤더 / Layer / 도형 / 저장 작업 건수 / Chain 전체(버전 / Layer / 규칙 / 포함 도형 / 편집 기록). E-Test 등록 / 연결, KLARF 데이터는 복사하지 않음 |
| C2 | Chain 번호 | 새 Device 의 Chain 은 새 CHAIN_SEQ(시퀀스). Chain Code / 이름 / 색 / 포함 도형은 그대로 |
| C3 | 새 Device 이름 | 빈 값 / 50자 초과 / 원본과 같은 이름 금지. 이미 있는 Device(대소문자 무시)면 오류(덮어쓰지 않음 - 필요하면 그 Device 를 먼저 삭제) |
| C4 | 원본 | 저장이 끝난(READY) Map 만. 화면에 저장하지 않은 Chain 변경이 있으면 "DB 에 저장된 내용만 복사" 를 확인한 뒤 진행 |
| C5 | 실패 처리 | 새 Map 헤더를 DRAFT 로 먼저 만들고 모두 복사한 뒤 READY 로 바꾼다. 중간에 실패하면 새 Device 의 일부 데이터를 지우고 오류를 알린다. 원본은 바뀌지 않음 |
| C6 | 완료 후 | Device 목록을 다시 읽어 새 Device 가 보이게 한다. 지금 화면은 그대로(새 Device 는 사용자가 골라 조회). 결과는 상태 줄 한 문장 |
| C7 | 버튼 | 도구 막대 [Map ▾] 왼쪽 [Map 복사]. DMS 호스트 모드에서만 보이고, READY Map 을 고른 뒤 쓸 수 있음 |

## 4. 서비스 (DefectDefine 방식, 새 wellknown / 새 DSL 없음)

- `iGdsMapImport.CopyMap(strFactory, strSourceDeviceID, strTargetDeviceID, strUser)` -> 1행: `TARGET_DEVICE_ID / LAYER_COUNT / PLACED_COUNT / CHAIN_COUNT`
- 처리: 입력 검사 -> 원본 READY 확인 -> 새 이름 중복(대소문자 무시) 확인 -> `COPY_MAP`(DRAFT) -> `COPY_LAYER` -> `COPY_PLACED_EL` -> `COPY_IMPORT_JOB`(새 작업 번호) -> Chain 마다 새 CHAIN_SEQ 로 `COPY_CHAIN` / `_VER` / `_LAYER` / `_RULE` / `_MEMBER` / `_EDIT` -> `UPDATE_MAP_READY` -> 도형 수 원본과 비교. 실패하면 `DeleteMap(새 Device)` 후 오류.
- 쿼리는 테이블별 XML 에 추가만: `TQP_GDS_MAP.xml`(COPY_MAP / SELECT_MAP_BY_NAME), `TQP_GDS_LAYER.xml`, `TQP_GDS_PLACED_EL.xml`, `TQP_GDS_IMPORT_JOB.xml`, `TQP_GDS_CHAIN*.xml` 6개.

## 5. 화면

- 신규 `MapCopyForm`(Designer): 원본 Device(읽기 전용) / 새 Device 입력 / [복사] / [취소]. 복사 중에는 진행 막대(Marquee) + 버튼 막기. 실패하면 창에 사유를 보이고 다시 입력할 수 있음.
- `GdsMapViewForm`: `btnCopyMap` + 처리 함수(미저장 Chain 확인 -> 창 열기 -> 완료 시 Device 목록 다시 읽기 + 상태 줄).
