# GDS Map 조회 화면 설계 (DB 기반)

작성: 2026-10-02 Claude / 작업 ID: CLAUDE-013 / 상태: 설계 (소스 수정 없음)

선행 문서: [GDS Map DB 저장 설계](2026-10-02_GDS_Map_DB저장_설계.md) 13절(조회 옵션 / 조회 튜닝 기준)이 이 설계의 출발점이다.

## 1. 목적과 범위

`frmGdsMapSetup`(GDS Map Setup)은 GDS 파일을 읽어 DB에 **등록**하는 화면이다. 이 화면은 GDS 파일 없이 **DB에 저장된 개정본(READY)** 을 골라 도면을 다시 그리는 **조회 전용** 화면이다.

| 구분 | 1차 범위 | 후속 |
| --- | --- | --- |
| 조회 조건 | Factory / Device / Revision(READY) 선택, 개정본 정보 표시 | 영역(Bounds) 지정 조회 |
| 조회 옵션 | **도면만** (LAYER + PLACED) | **Chain만 / 둘 다** (Chain 저장 구현 후) |
| 표시 | 기존 GdsMapControl로 도면 / Layer 표시 / 색상 / 확대 / 선택 | 도형 목록 Grid / 원본(SOURCE) Grid |
| 변경 | 없음 (읽기 전용) | MAP_ACTIVE 지정(10절 결정) |

KLARF 연관분석은 이 화면 범위가 아니다(F07). 이 화면에서 만든 "DB -> 도면" 경로를 F07이 재사용한다.

## 2. 현재 확인 결과 (2026-10-02 소스 기준)

| 항목 | 확인 내용 | 설계 영향 |
| --- | --- | --- |
| 호스트 | `SEMDMS.ENGUI/GdsMap/frmGdsMapSetup.cs`가 `GdsMap/NexplantQMS.GdsMap.exe`를 `Assembly.LoadFrom`으로 올리고 `GdsMapForm(true)`를 만든다 | 조회 화면도 같은 방식. 4.0 호스트 / 4.8 GDS 화면 분리 유지 |
| 도면 표시 | `GdsMapControl.ShowStructure(GdsLibrary)`만 있다. 내부는 Flatten -> `_layerList.AddSceneItem` -> `BuildGpuBuffers` 한 번 -> `ZoomToFit` | DB 도형을 넣는 **새 공개 함수 1개**가 필요. `BuildGpuBuffers`는 전체 재구성이므로 페이지마다 부르지 않고 마지막에 한 번 |
| `Structure` 의존 | Layer 표시(`UpdateVisibleLayer` / `SetLayerVisibility`), Chain 후보 탐색, 배치 추출이 `Structure != null`을 검사 | DB 조회 시 빈 `GdsStructure`(이름 = TOP_STRUCTURE, Layers = DB Layer 목록)를 만들어 둔다. 기존 검사 코드를 고치지 않는다 |
| 도형 복원 | `Persistence/MapPlacedSceneItemFactory.Create(MapPlacedElementData)` 존재 (BOUNDARY / PATH / TEXT) | 그대로 사용. DB 행 -> `MapPlacedElementData` 변환기만 추가 |
| 저장 형식 | PLACED 20열, `POINTS_BIN` v1 = 월드 X/Y double LE(점당 16바이트), TEXT는 CLOB | 변환기는 `GdsMapPlacedRowBuilder`의 역변환 |
| 인덱스 | `IX_GDS_PLACED_LAYER (MAP_REV_SEQ, LAYER_ID, PLACED_ELEMENT_ID)` 존재. Bounds 인덱스 없음 | Layer별 키 순서 페이지 조회 가능. 영역 조회는 후속 |
| 조회 성능 | Middleware `GetDataTable` BLOB 그대로 조회 행당 0.013ms (13.4절 측정) | DB 자체보다 **Remoting으로 넘기는 DataTable 크기**가 병목 |
| DataTable 전달 | 소스 전체에 `RemotingFormat` 지정 없음 -> 기본 XML 직렬화. byte[]는 Base64 문자열로 커진다 | 신규 BSL 반환 DataTable만 `RemotingFormat = Binary` 지정 검토(계약 변경 없음, 2단계에서 측정) |
| Chain 테이블 | DDL만 있고 저장 기능 없음 | Chain 옵션은 1차에서 비활성 |

## 3. 화면 설계

### 3.1 파일과 호스트

| 계층 | 파일 (전부 신규) | 역할 |
| --- | --- | --- |
| DMS 호스트 | `02_DMS/DACrux.SEMDMS.ENGUI/GdsMap/frmGdsMapView.cs` / `.Designer.cs` | `frmGdsMapSetup`과 같은 구조. 형식 이름 `NexplantQMS.GdsMap.GdsMapViewForm` 로드 |
| GDS 화면 | `06_CoreLibSource/GdsMapControl/GdsMapViewForm.cs` / `.Designer.cs` | 조회 조건 / 옵션 / 진행률 / 도면 표시. 파일 열기 / DB 저장 기능 없음 |
| 메뉴 | `01_WinApp/DACruxV5/MenuFile.mnu` / `100_ClientBin/MenuFile.mnu` | `MNU_DMS_GDS_MAP_VIEW` 1행을 **파일 맨 뒤에** 추가 (CLAUDE-010 교훈: 행 순서 변경 금지) |

기존 `GdsMapForm`에 조회 모드를 넣지 않고 화면을 분리한다. 이유: 등록 화면은 파일 / Grid / Chain 편집 / DB 저장이 이미 얽혀 있고, 조회 화면은 읽기 전용이라 두 화면의 버튼 활성 규칙이 다르다. 공통 부분(지도 / Layer 목록)은 `GdsMapControl`과 `LayerColorCheckedListBox`를 그대로 쓴다.

### 3.2 배치 (Designer에서 관리)

```text
+----------------------------------------------------------------------------------+
| [조회 조건 panelTop]                                                              |
|  Factory [cboFactory v]  Device [cboDevice v]  Revision [cboRevision v]  [조회][중지] |
|  옵션: (o) 도면만  ( ) Chain만  ( ) 둘 다      ※ Chain 옵션은 Chain 저장 후 활성     |
+----------------------------+-----------------------------------------------------+
| [개정본 정보 grpRevision]   |                                                     |
|  개정본 번호 / 상태         |                                                     |
|  Top Structure / 단위       |                 GdsMapControl (map)                 |
|  SOURCE / PLACED / 좌표 수  |                                                     |
|  등록자 / 등록 시각         |                                                     |
| [Layer chkLayerItems]       |                                                     |
|  [v] 1  (12,345)  ■         |                                                     |
|  [v] 2  (  987)  ■          |                                                     |
|  [전체][해제]               |                                                     |
+----------------------------+-----------------------------------------------------+
| StatusStrip: 진행률(progressLoad) / 문구(lblStatus) / 마우스 좌표 / 조회 시간       |
+----------------------------------------------------------------------------------+
```

- Factory / Device: DB에 등록된 값 목록(콤보, 직접 입력 허용). 저장 화면이 자유 입력이므로(10.1절 결정 2) 조회는 실제 등록된 값만 보여 주는 것이 오입력을 줄인다.
- Revision: 선택한 Device의 **READY** 개정본만, 최신 번호 순. 항목 표시 `REVISION_CODE (번호 / 등록일)`.
- Layer 목록: 개정본 선택 시 `TQP_GDS_LAYER` + Layer별 도형 수를 먼저 읽는다. **체크된 Layer만 조회**하므로 큰 도면에서 필요한 Layer만 가져올 수 있다. 조회 후에는 체크 변경이 표시 / 숨김으로 동작한다(다시 조회하지 않음). 조회하지 않은 Layer를 체크하면 "다시 조회 필요" 문구를 띄운다.
- 색상: `COLOR_ARGB`(저장 당시 화면 색상)를 `map.SetLayerColor`에 넣는다.

### 3.3 조회 흐름 (도면만)

```text
[화면]                                   [SEMDMS Service / BSL]              [DMSMGR]
 화면 열림 -> GetMapDeviceList ---------> SELECT DISTINCT FACTORY, DEVICE_ID (READY)
 Device 선택 -> GetMapRevisionList -----> MAP_REV + IMPORT_JOB 건수 (READY)
 Revision 선택 -> GetMapLayerList ------> LAYER + PLACED Layer별 COUNT (IX_GDS_PLACED_LAYER)
 [조회]
   Layer마다 반복 (Task.Run)
     GetPlacedElementPage(rev, layer, 마지막 ID, 행 수) -> 키 순서 다음 페이지
     DataRow -> MapPlacedElementData (POINTS_BIN 해석)  <- 백그라운드
     진행률 = 받은 도형 수 / Layer 도형 수 합계
   UI 스레드: map.ShowPlacedElements(개정본 정보, Layer 목록, 도형 목록) -> GPU 버퍼 1회 -> 전체 보기
 [중지] -> 현재 페이지가 끝나면 멈추고 화면은 이전 상태 유지
```

- 원격 호출과 BLOB 해석은 `Task.Run`, 도면 구성(`ShowPlacedElements`)만 UI 스레드에서 한 번 실행한다. 저장 화면(18절)과 같은 원칙이다.
- 1차에서는 모든 페이지를 받은 뒤 한 번에 그린다. `BuildGpuBuffers`가 전체 재구성이라 페이지마다 그리면 도형 수 제곱에 비례해 느려진다. "첫 화면 먼저 그리기"는 측정 후 결정(8절).
- 조회 중에는 조건 / 옵션 / Layer 체크를 막는다. 다른 개정본을 다시 조회하면 기존 도면을 통째로 바꾼다.

### 3.4 Chain만 / 둘 다 (후속, 설계만)

| 옵션 | 읽는 데이터 | 화면 처리 |
| --- | --- | --- |
| Chain만 | `CHAIN`(ACTIVE) -> `CHAIN_VER`(IS_CURRENT=1) -> `CHAIN_MEMBER` -> 같은 개정본 `PLACED_EL` 조인 | Member 도형만 `ShowPlacedElements`로 표시 + Chain 색상. 도형 수가 적어 한 번에 조회 |
| 둘 다 | 도면만 흐름 + Member의 `PLACED_ELEMENT_ID` / `ROLE_CODE` / Chain 색상만 | 도형을 두 번 읽지 않고 ID로 기존 `SetVisibleChainOverlays` / `HighlightChainElements` 강조 |

화면에는 Chain 목록(코드 / 이름 / 버전 / 색상 / 체크) 패널이 추가된다. Chain 저장 기능이 생기기 전까지 두 옵션은 비활성으로 둔다.

## 4. 서버 계약 (신규 `iGdsMapView`, 기존 DefectDefine 방식)

저장용 `iGdsMapImport`와 분리한 **읽기 전용** 서비스다. 기존 함수는 바꾸지 않는다.

| 함수 | 입력 | 반환 (DataTable 열) |
| --- | --- | --- |
| `GetMapDeviceList()` | - | FACTORY / DEVICE_ID / READY_COUNT |
| `GetMapRevisionList(string strFactory, string strDeviceID)` | Factory / Device | MAP_REV_SEQ / REVISION_CODE / TOP_STRUCTURE / USER_UNIT / DATABASE_UNIT / REVISION_STATUS / CREATE_USER / CREATE_TIME / SOURCE 수 / PLACED 수 / 좌표 수 (IMPORT_JOB의 RECEIVED_* , READY만) |
| `GetMapLayerList(string strMapRevSeq)` | 개정본 번호 | LAYER_ID / COLOR_ARGB / DISPLAY_NAME / PLACED_COUNT / POINT_COUNT |
| `GetPlacedElementPage(string strMapRevSeq, string strLayerID, string strAfterPlacedID, int iMaxRows)` | 개정본 / Layer / 이전 페이지 마지막 ID(첫 페이지는 빈 값) / 최대 행 수 | PLACED 20열 중 표시에 필요한 열 (5절) |

- BSL은 개정본이 **READY**인지 먼저 확인한다. DRAFT(저장 중 / 실패)는 조회하지 않는다.
- `iMaxRows` 상한은 서버에서 제한한다(예: 50,000). 기본값은 2단계 측정으로 정한다(시작값 10,000).
- 파일: Interface `iGdsMapView.cs` / RO `GdsMapView.cs` / BSL `GdsMapView.cs` (신규), DSL은 기존 테이블별 클래스(`TQP_GDS_MAP_REV` / `TQP_GDS_LAYER` / `TQP_GDS_PLACED_EL`)에 **조회 함수 추가**, XML은 같은 이름 파일에 `SELECT_` 쿼리 추가. `101_ServerBin` config 2개에 `GdsMapView.bin` wellknown 1줄.

## 5. 조회 쿼리 설계

**페이지 조회 (`SELECT_PLACED_EL_PAGE`, TQP_GDS_PLACED_EL.xml, `logging="FALSE"`)**

```sql
SELECT * FROM (
    SELECT PLACED_ELEMENT_ID, SOURCE_ELEMENT_ID, LAYER_ID, DATA_TYPE, ELEMENT_TYPE,
           CLOSED_FLAG, PATH_WIDTH, PATH_TYPE, MIN_X, MIN_Y, MAX_X, MAX_Y,
           POINT_COUNT, POINTS_FORMAT_VERSION, POINTS_BIN,
           TEXT_VALUE, TEXT_TYPE, TEXT_FONT, TEXT_HORIZONTAL, TEXT_VERTICAL
      FROM TQP_GDS_PLACED_EL
     WHERE MAP_REV_SEQ = :MAP_REV_SEQ
       AND LAYER_ID = :LAYER_ID
       AND PLACED_ELEMENT_ID > :AFTER_ID      -- 첫 페이지는 CHR(0) 또는 별도 쿼리
     ORDER BY PLACED_ELEMENT_ID
) WHERE ROWNUM <= :MAX_ROWS
```

- OFFSET 방식 대신 **마지막 키 다음부터(keyset)** 읽는다. 뒤 페이지로 갈수록 느려지지 않고 `IX_GDS_PLACED_LAYER` 범위 스캔을 쓴다. `FETCH FIRST`는 대상 DB 버전 확인 전이라 `ROWNUM`을 쓴다.
- 확인 필요: 세션 `NLS_SORT`가 BINARY가 아니면 `ORDER BY` 문자열 순서와 인덱스 순서가 달라 정렬이 생길 수 있다. 2단계 Probe에서 실행 계획 / 시간으로 확인한다.
- `TEXT_VALUE`(CLOB)는 TEXT 행에만 값이 있다. CLOB 조회 비용이 크면 TEXT Layer만 별도 쿼리로 나누는 안을 측정 후 결정한다.

**Layer 목록 (`SELECT_LAYER_WITH_COUNT`)**: `TQP_GDS_LAYER` LEFT JOIN (`PLACED_EL` GROUP BY LAYER_ID: COUNT(*) / SUM(POINT_COUNT)). 인덱스만으로 COUNT 가능, SUM(POINT_COUNT)는 테이블 접근 -> 샘플 시간 측정.

## 6. 클라이언트 설계 (GDS 프로젝트, 수정 허용 예외 폴더)

| 파일 | 변경 | 내용 |
| --- | --- | --- |
| `Persistence/GdsMapPlacedRowReader.cs` | 신규 | `DataRow -> MapPlacedElementData`. `GdsMapPlacedRowBuilder`의 역변환. POINTS_FORMAT_VERSION = 1만 허용, 바이트 길이 = POINT_COUNT x 16 검사, NULL 열 처리 |
| `Controls/GdsMapControl_DbView.cs` | 신규 partial | `ShowPlacedElements(string topStructure, IList<LayerInfo> layers, IList<MapPlacedElementData> items)` 공개 함수 1개 |
| `GdsMapViewForm.*` | 신규 | 3절 화면 |
| `NexplantQMS.GdsMap.csproj` | 등록만 | 신규 파일 Compile 등록. SEMDMS RO / Interface 참조는 이미 있음 |

**`ShowPlacedElements` 처리 순서** (기존 `ShowStructure`와 같은 정리 순서를 따른다)

1. `_mapContentVersion++`, 선택 / Layer / Defect / TEXT 라벨 비우기.
2. 빈 `GdsStructure`(Name = TOP_STRUCTURE)를 만들고 DB Layer마다 `GdsLayer`를 넣어 `Structure`에 지정한다. 기존 Layer 표시 / Chain 탐색 코드의 `Structure != null` 검사가 그대로 동작하게 하는 목적이며, 원본 도형은 넣지 않는다.
3. 도형마다 `MapPlacedSceneItemFactory.Create` -> `_layerList.AddSceneItem`. TEXT는 기존 `AddTextLabel`(구조 경로는 TOP_STRUCTURE 고정. DB에는 SREF 경로가 없음).
4. `ApplyInitialLayerColors` -> `CalculateTextLabelDisplayAreas` -> `BuildGpuBuffers` -> `ZoomToFit`.

기존 `ShowStructure` / Flatten / 저장 추출 코드는 바꾸지 않는다. 확인 필요: `GdsStructure.Layers`의 setter가 private이므로 `GdsLayerList.Add`로 채울 수 있는지, `GdsLayer` 생성자 형태는 구현 1단계에서 확인한다.

**알려진 차이 (파일 조회 대비)**
- 원본 Grid(SOURCE) / SREF 구조 경로 / 파서 중복 행은 1차에서 표시하지 않는다.
- 배치 도형 추출(`VisitPlacedElementBatchesAsync`)은 DB 조회 도면에서도 동작은 하지만 의미가 없으므로 조회 화면에는 저장 버튼이 없다.

## 7. 성능 예상과 측정 항목

샘플 `OMM all layer2.gds`(PLACED 605,080 / 좌표 8,292,978) 기준.

| 구간 | 예상 근거 | 측정 방법 |
| --- | --- | --- |
| DB 조회 | 행당 0.013ms -> 약 8초 | 2단계 Probe (BSL 직접) |
| Remoting 전달 | 좌표만 약 132MB. XML 기본 직렬화면 Base64로 약 1.33배 + XML 처리 | Service 경유 페이지 1개 시간 / 크기, `RemotingFormat = Binary` 전후 비교 |
| 행 해석 + Scene 생성 | 파일 Flatten 약 1.2~4.9초 수준 예상 | 3단계 화면 진행률 시간 기록 |
| 메모리 | 파일 조회와 비슷한 GPoint / Vertex + 페이지 DataTable 일시 | 페이지 처리 후 DataTable 즉시 해제 (`Dispose` / 참조 해제) |

목표(잠정): 샘플 전체 도면 조회 60초 이내. 넘으면 8절 후보를 적용한다.

## 8. 튜닝 후보 (측정 후 결정)

1. 신규 BSL 반환 DataTable `RemotingFormat = Binary` (계약 변경 없음).
2. 페이지 행 수 조정 / Layer 병렬 2개 요청.
3. TEXT CLOB 분리 조회.
4. 첫 화면 먼저 그리기: GPU 버퍼를 Layer 단위로 추가하는 경로가 필요해 GdsMapControl 변경이 커진다. 1~3으로 부족할 때만.
5. 영역 조회: Bounds 인덱스(DDL 추가) 필요 -> 사용자 승인 대상.

## 9. 구현 단계 (작은 단위, 단계마다 확인 후 진행)

| 단계 | 내용 | 완료 확인 |
| --- | --- | --- |
