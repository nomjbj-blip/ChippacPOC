## 1. 요구 (2026-10-07 사용자 지시)

- GDS Map View 화면에서 `C4DC_212_71` 같은 Label을 입력하고 [검색]을 누르면 Map에서 그 Label이 **어디에 있는지 보여 준다**.
- Label은 Chain 정보 기반이다(지금은 Layer 775에 있음). **Layer는 바뀔 수 있으므로 Layer가 아니라 속성으로 찾는다.**

## 2. 확인한 사실 (2026-10-07, 샘플 `OMM all layer2.gds`)

| 항목 | 값 |
| --- | --- |
| 배치 TEXT 수 | **30,992개, 모두 Layer 775**, 서로 다른 값 15,708개 |
| 값 형식 | `C4DC_x_y` 30,356개 + 기타 636개(`TSVDC_BL_FL`, `HBM0_HTR_STK_FL` 등). 최대 20자, 소문자 / 앞뒤 공백 없음 |
| `C4DC_212_71` | **2곳**: (10800, 14582.208) / (10960, 14582.208) - 160µm 간격의 쌍(패드 / 단자 쌍으로 보임) |
| 같은 값 반복 | 최대 4곳(`HBM0_HTR_STK_FL` x4 등) -> 검색 결과는 여러 건일 수 있다 |
| TEXTTYPE / DATATYPE | 전부 237 / 0 -> 이 값으로는 Label을 구분할 수 없다 |
| DB 저장 | `TQP_GDS_PLACED_EL`의 `ELEMENT_TYPE = 'TEXT'` 행: `TEXT_VALUE`(CLOB), `TEXT_TYPE`, `LAYER_ID`, 위치(POINTS_BIN 첫 점 / MIN_X~MAX_Y). TEXT 전용 인덱스 없음 |
| 화면 | 조회한 Layer의 TEXT만 지도에 Label로 그린다(`_textLabels`). 영역 확대 함수 `FocusChainBounds(GBox)` 있음 |

**속성 기반 정의**: Label = **도형 종류(ELEMENT_TYPE)가 TEXT인 배치 도형 전체**(Layer 무관). Layer / TEXTTYPE은 결과를 좁히는 **선택 조건**으로만 둔다(기본 = 전체). 그러면 Label Layer가 775에서 다른 번호로 바뀌어도 그대로 찾는다.

## 3. 검색 대상을 어디서 찾을까

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| A. 지금 지도에 올라온 TEXT에서 찾기 | DB 호출 없음 | **Label Layer(775)를 조회하지 않으면 못 찾음** - 보통 Chain 작업은 배선 Layer만 조회 |
| B. 검색할 때마다 DB에서 `TEXT_VALUE LIKE` | 항상 최신 | CLOB LIKE + TEXT 인덱스 없음 -> 검색마다 Device 전체 행 스캔(60만 행, 수 초) |
| **C. Label 색인을 한 번 DB에서 받아 화면에 두고 검색 (권장)** | Layer 조회와 무관, 검색은 메모리(3만 건, 즉시), 부분 / 시작 일치도 쉬움 | Map당 1회 조회(TEXT 3만 행 x 수십 바이트 = 약 1~2MB). 첫 조회 시간은 실제 Map 등록 후 측정 |

**C 권장.** Device를 조회할 때(또는 첫 검색 때) TEXT 행만 가볍게 받는다: 도형 ID / Layer / TEXTTYPE / 값 / 위치(Bounds). 좌표는 DB 저장 기준이므로 화면 보기 기준(Front / Back)에 맞춰 `GdsSideTransform`으로 X 반전한다.

서버: 신규 쿼리 `SELECT_PLACED_TEXT_INDEX`(`TQP_GDS_PLACED_EL.xml`, 기존 쿼리 변경 없음) + 서비스 `iGdsMapView.GetMapTextIndex(Factory, Device)` 1개. `TEXT_VALUE`는 `DBMS_LOB.SUBSTR(TEXT_VALUE, 1000, 1)`로 문자열 반환(최대 20자 실측). 첫 조회가 느리면(실측 후) `(FACTORY, DEVICE_ID, ELEMENT_TYPE)` 인덱스를 별도 승인 받아 추가.

## 4. 화면 설계 (GDS Map View)

```text
조건 영역: Factory [▼] Device [▼] [조회] [중지]   보기 기준 [Front ▼]   Label [C4DC_212_71      ] [검색] (정확히 ▼)
왼쪽 패널(Layer 목록 위): Label 검색 결과 (값 / Layer / X / Y)  -> 행 선택 = 그 위치로 이동
지도: 결과 위치에 검색 표시(십자 + 원), 선택한 결과는 강조
상태줄: "C4DC_212_71: 2건 (Layer 775) / 1번째 위치로 이동"
```

- **검색**: [검색] 또는 Enter. 대소문자 무시, 앞뒤 공백 제거. 일치 방식 콤보: **정확히(기본) / 시작 / 포함**. `*` 와일드카드는 1차 제외(8절 결정 2).
- **결과**: 1건이면 바로 이동, 여러 건이면 목록에 모두 보여 주고 첫 번째로 이동. 목록 행 선택(또는 이전 / 다음)으로 이동. 결과가 많으면(예: 시작 일치 `C4DC_2`) 목록 최대 1,000건 + "외 n건" 표시.
- **이동**: 결과 위치를 중심으로 일정 크기(기본 300µm 사각형, 8절 결정 4)가 보이도록 `FocusChainBounds`와 같은 방식으로 확대 / 이동. 여러 건 쌍(예: 160µm 쌍)이 한 화면에 들어오도록 결과 전체 범위로 맞추는 [전체 보기] 버튼.
- **표시**: 지도에 검색 위치 마커를 별도 오버레이로 그린다(`GdsMapControl`에 `SetSearchMarkers(points, selectedIndex)` 신규). Chain Marker / 선택 표시와 섞이지 않게 다른 색.
- Label Layer를 조회하지 않았으면 글자는 지도에 없지만 위치 마커는 보인다. 상태줄에 "Label Layer 775 미조회 - 글자를 보려면 체크 후 [조회]" 안내.
- 보기 기준을 바꾸면 검색 위치도 같은 규칙으로 X 반전(목록 / 마커 갱신). Device를 바꾸면 색인 / 결과를 비운다.
- 조회 전(도면 없음)에는 검색 비활성.

## 5. Chain 정보와 연결 (2단계, 선택)

Label이 Chain 단자 위치를 나타내므로, 결과 행에 **그 위치의 도형이 속한 화면 Chain**(Input / Output / Member 중 Label 위치를 포함하는 도형)을 함께 보여 줄 수 있다. 예: `C4DC_212_71 / Layer 775 / (10800, 14582.2) / Chain A의 Input`. 1차는 위치 확인만 하고, 2단계에서 "Label로 Chain 이름 짓기 / Label 위치의 도형을 Input / Output으로 지정" 등과 함께 정한다.
