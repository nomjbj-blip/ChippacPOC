- 기존 화면은 손대지 않는다. 새 화면과 새 화면 전용 파일로 분리해서 만든다.

- `DMS/06_CoreLibSource` 는 수정 금지 (예외: `06_CoreLibSource/GdsMapControl`). Map 컨트롤은 호출 / 상속으로만 재사용한다.
- Service / RO / BSL 은 기존 Function 을 재활용하고, 필요하면 해당 영역에 Function 을 **추가만** 한다. 기존 Function 은 바꾸지 않는다.
- Control 은 `DMS` 안에 있는 것을 최대한 재활용한다 (`DACrux.Map.EditWaferMap`).
- 애매한 부분은 임의로 정하지 않고 사용자에게 묻는다.

## 1. 목적

- 지금 화면은 파일에 있는 Die 위치만 `AddDie` 로 넣는다. 그래서 Wafer 원 형태가 아니라 파일 사각 격자 일부만 보인다.
- 바꿀 방식:
  1. 작업자가 Wafer 크기 / XY 방향 등을 **선택해서 생성** 버튼을 누른다.
  2. 파일 헤더(행/열/실제 Die 크기)와 선택값으로 **Wafer 원 안의 전체 Die 를 원 형태로 생성**한다.
  3. 작업자가 Map 컨트롤 Edit 기능 (+ 보조 버튼) 으로 **필요 없는 Die 를 제거**한다.
  4. 제거한 Die 는 `USECODE = -1` 로 함께 저장한다.

### 2.2 DMS 기존 Map Setup (`frmSetupMap`) Rule

- XY Direction 은 Map 마다 고르는 속성이다 (콤보 LeftTop / RightTop / LeftBottom / RightBottom, `TQP_MAPDEF.XY_DIRECTION` 저장). 첫 항목과 enum 기본값(0) 은 LeftTop.
- 조회 화면 (`frmAVICumMapView`, `frmCumMapReport_FOI` 등) 은 저장된 `XY_DIRECTION` 을 읽어 그린다.
- 원 형태 생성 순서 (`MapDraw`): Notch / Wafer / Edge / Angle / XYDirect -> DieSize -> DieMin/Max -> Origin / OriginIndex -> FirstDie -> `DieCalculation(true)` -> `Redraw()`.
- 원점 Rule (`dsm_OnWaferGridApply`): 격자를 Wafer 중심에 대칭으로 놓는다.

```
OriginIndexX = DieMinX + xcnt / 2 - ((xcnt + 1) % 2)
OriginIndexY = DieMinY + ycnt / 2 - ((ycnt + 1) % 2)
OriginX = (Left 방향 ? -1 : +1) * DieSizeX * 0.5 * (xcnt % 2)
OriginY = (Bottom 방향 ? -1 : +1) * DieSizeY * 0.5 * (ycnt % 2)
```

### 2.3 Map 컨트롤 (`06_CoreLibSource/DACrux.Map`, 읽기만 함)

- `WaferMap.DieCalculation(true)`: DieMin~DieMax 격자 전체를 Die 로 만든다. `UseDie()` 판정에 따라 원(반지름 - Edge) 안이고 Flat 영역 밖이면 `DieProp = 1`, 아니면 `-1` 이다.
- `UseDie(x, y, w, h)` 는 `protected` 다. 새 화면 전용 상속 클래스에서 호출해 재사용한다 (5절).
- Flat 영역 (`m_rectNotchArea`) 은 그리기 중에 계산된다. 따라서 **설정 -> Redraw -> DieCalculation -> Redraw** 순서로 한다.
- `EditWaferMap` Edit 모드: DELETE(-1) / ADD(1) / SKIP(0) / MARK(2). 클릭과 드래그로 바꾼다. 기본 모드가 `ADD` 다.
- `Die` 는 class 다. `m_wMap.Dies[i].DieProp` 를 바꾼 뒤 `Redraw()` 하면 반영된다. NetDie 는 Redraw 때 다시 센다.
- `OnChangeDieProperty` 이벤트로 편집 후 정보를 갱신한다.

### 2.4 DMS AVI Parser (`ParserAviMapFile`, 참고만)

- 같은 파일 포맷이다. 좌표는 `X = 열 + 1`, `Y = ROWCT - 행` (Bottom 기준) 이다.
- 사용자 확인: AVI 만 Bottom 기준이고 나머지는 좌측 상단 (1,1) 이 기본이다. 그래서 이 화면 기본값은 LeftTop 으로 하고 방향은 선택 가능하게 한다.

## 3. Map 생성 Rule

### 3.1 파일 항목 해석

| 항목 | 샘플 | 사용 |
| --- | --- | --- |
| DEVICE | Hybrid | Map ID 초기값 |
| LOT / WAFER | HS2617B_TBDB / XD074.01 | 정보 표시 |
| FNLOC | 180 | Flat 방향 초기값 (0=Top, 90=Right, 180=Bottom, 270=Left) -> `NotchAngle` |
| ROWCT / COLCT | 7 / 10 | 파일 격자 크기 |
| BCEQU | 000 | 정보 표시 (형상은 Bin 구분 없음) |
| REFPX / REFPY | 1 / 1 | 정보 표시 |
| DUTMS | mm | mil 이면 0.0254 곱함 |
| XDIES / YDIES | 23.834 / 30.060 | 실제 Die 크기 (mm) |
| RowData | `___` / `__` / 숫자 | 숫자 = 파일 Die, 밑줄 = 빈 칸 |

### 3.2 좌표 기준: 파일 좌표 유지 + XY 방향 번호 변환

- **파일 Die 의 Map 인덱스는 파일 좌표를 그대로 유지한다.** 확장 영역은 0, 음수, COLCT / ROWCT 초과 번호를 쓴다. AVI / KLARF 결과 좌표와 변환 없이 매칭하기 위해서다.
- XY 방향을 바꾸면 **형상은 그대로 두고 번호만** 방향에 맞게 바꾼다 (`c` = 0부터 시작하는 열, `r` = 0부터 시작하는 행):

| XY 방향 | X 인덱스 | Y 인덱스 | 파일 (1,1) 위치 |
| --- | --- | --- | --- |
| LeftTop (기본) | c + 1 | r + 1 | 왼쪽 위 |
| RightTop | COLCT - c | r + 1 | 오른쪽 위 |
| LeftBottom | c + 1 | ROWCT - r | 왼쪽 아래 |
| RightBottom | COLCT - c | ROWCT - r | 오른쪽 아래 |

- 확장 영역도 같은 식을 쓴다. 예를 들어 LeftTop 에서 왼쪽으로 2열 확장하면 X = -1, 0 이 된다.
- FNLOC 로 좌표를 회전하지 않는다. FNLOC 는 Flat 그림 위치에만 쓴다.

### 3.3 Die 크기 / Wafer 크기 선택

- Die 크기 = 파일 실제 값으로 고정한다. 지금 화면의 "Wafer 맞춤 배율" 은 제거한다.
- Wafer 크기 = 콤보 (75 / 100 / 125 / 150 / 200 / 300 mm, 현재 화면 항목) 에서 작업자가 선택한다. 선택 전에는 생성 버튼을 막는다.
- Edge (mm) 입력, 기본 0. Flat / Notch 라디오, 기본 Flat. Flat 방향 콤보는 FNLOC 를 초기값으로 한다.
- 작업자가 "원형 생성" 버튼을 누를 때만 생성한다. 설정을 바꾼 뒤 편집 내용이 있으면 "다시 생성하면 편집 내용이 초기화됩니다" 확인창을 띄운다.

### 3.4 Wafer 크기에 따른 격자 범위 (확장)

유효 반지름 `Reff = WaferSize / 2 - Edge`.
파일 격자 반폭 `HalfW = COLCT * DieSizeX / 2`, 반높이 `HalfH = ROWCT * DieSizeY / 2`.

```
ExtendX = max(0, ceil((Reff - HalfW) / DieSizeX))     // 좌/우 같은 수만큼 확장
ExtendY = max(0, ceil((Reff - HalfH) / DieSizeY))     // 위/아래 같은 수만큼 확장
DieMinX = 1 - ExtendX,  DieMaxX = COLCT + ExtendX
DieMinY = 1 - ExtendY,  DieMaxY = ROWCT + ExtendY
```

- 좌우 / 상하를 같은 수만큼 늘리므로 격자 중심과 홀짝이 바뀌지 않는다. 그래서 원점은 파일 격자 기준 Rule (2.2) 그대로 계산한다 (`xcnt = COLCT`, `ycnt = ROWCT`, DieMin 은 확장 전 값 1 기준).
- 확장 영역 Die 도 `DieCalculation` 이 원 판정으로 자동 1 / -1 로 만든다.
- Wafer 가 파일 격자보다 작으면 확장은 0 이다. 파일 Die 중 원 밖 Die 는 `DieCalculation` 에서 -1 이 된다. 정보창에 "원 밖 파일 Die N개" 를 표시한다.

샘플 (10열 x 7행, 23.834 x 30.060 mm, Edge 0, Flat 영역 제외 계산):

| Wafer | 확장 (X, Y) | 격자 | 비고 |
| --- | --- | --- | --- |
| 300 mm | (2, 2) | 14 x 11, 인덱스 X -1~12 / Y -1~9 | 파일 범위 안 원 Die 66개 중 파일 Die 26개 모두 포함 |
| 200 mm | (0, 0) | 10 x 7 | 원 안 28개, 파일 Die 18개가 원 밖 |

(확장 영역 Die 개수는 구현 2단계 검증 스크립트로 확정한다.)

### 4.2 작업자 흐름

1. 파일 선택 -> `StandardMapFile.Load` 로 검증 / 파싱한다. 설정 초기값을 채운다 (Map ID = DEVICE, Flat 방향 = FNLOC, XY = LeftTop).
2. Wafer 크기 등을 선택하고 [원형 생성]을 누르면 `GenerateCircleMap()` 이 3.2~3.4 를 적용한다.
3. 편집 모드
   - 보기 (기본): 클릭해도 Die 가 바뀌지 않는다. 구현 방법은 6절 4단계에서 컨트롤 동작을 확인한 뒤 결정한다 (기본 EditMode 가 ADD 라서).
   - 제거: `EditMethod = EditMode.DELETE` (클릭 / 드래그).
   - 복원: `EditMethod = EditMode.ADD`.
4. 보조 버튼 (작업자가 필요할 때 누름, 누르기 전 대상 개수 확인창)
   - [파일 빈칸 제거]: 파일 격자 안에서 파일이 빈 칸(`___`)인 위치의 Die 를 -1 로 바꾼다.
   - [Wafer 밖 제거]: 현재 Wafer / Edge / Flat 기준으로 모든 Die 를 다시 판정해 원 밖 Die 를 -1 로 바꾼다. 생성 시 자동 제거는 그대로 두고, 작업자가 ADD 로 살린 원 밖 Die 나 Edge 변경 후 재판정에 쓴다.
5. 편집할 때마다 정보창을 갱신한다: 사용 Die / 제거 Die / 원 밖 파일 Die / 파일과 다른 위치 수.
6. [새 Map 저장]: 기존 흐름을 유지한다 (중복 ID 확인 -> 확인창 -> `MapCreationService.Create`). 모든 Die 를 X / Y / USECODE(DieProp, 제거 = -1) 로 저장한다.

## 6. 단계별 구현 계획

각 단계는 빌드 + 실제 EXE 화면 확인 후 다음 단계로 간다.

1. `StandardMapFile`: 원본 (열, 행) 보관 + XY 방향 변환 함수. 기존 화면 표시가 깨지지 않는지 확인한다.
2. `StandardMapCircleRule` + 검증 스크립트 (샘플 300 / 200 mm 결과 표 확정).
3. `StandardMapEditMap` 추가, Designer 의 `m_wMap` 타입 교체, `GenerateCircleMap` 적용. 원 형태 표시를 확인한다.
4. 생성 설정 컨트롤 (Edge / Flat / XY / 원형 생성) + 편집 모드 (보기 / 제거 / 복원).
5. 보조 버튼 2개 + 정보 갱신.
6. 왼쪽 등록 Map ID 목록 (`ProbeAdmin.GetMapIDList` 재활용) + 더블클릭으로 기존 `frmSetupMap` 열기 (기존 화면 코드 변경 없이 `LoadMap` 호출).
7. 저장 후 기존 Map Setup 화면에서 열어 원 형태 / 제거 Die / 음수 인덱스가 그대로 보이는지 확인한다.

## 7. 1차 범위 제외

- ITEK 의 Map 삭제 / 다른 Map 복사 / 기존 Map 덮어쓰기
- Bottom 정규화 회전 저장, 원본 파일 FTP 백업

## 8. 구현 중 확인 항목 (결과에 따라 사용자에게 다시 묻는다)

1. **음수 / 0 인덱스 저장**: `SetMapDef` (DIE_INDEX_MIN) / `CreateUseMap` (X, Y) 와 기존 Map Setup / 조회 화면이 음수 인덱스를 문제없이 처리하는지 7단계에서 확인한다. 문제가 있으면 기존 Function 을 바꾸지 않고 사용자에게 보고한다.
