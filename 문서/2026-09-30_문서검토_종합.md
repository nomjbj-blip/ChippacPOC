## 2. 파일별 상세 검토

### 2.1 고객 요구 문서 (AOI-ET PDF 2건)

두 문서 모두 SRS가 아닌 **사례 중심 PPT 슬라이드**. 허용오차·성능·리포트 포맷·ET 파일 포맷·좌표 변환 규칙은 미기재.

#### 문서 A: `AOI-ET Correlation Automation_r01.pdf` (4p, SCK R&D, 2026-06-26) — **최신**

- p.3 **Ver.1 Requirements**
  1. AOI KLARF 파일의 결함 정보(좌표)가 GDS CAD 내 daisy chain을 구성하는 bump 및/또는 RDL routing 위치와 일치하는지 검증
  2. 일치 시 해당 bump/RDL의 정확한 위치 정보 제공
- As-Is (수작업): Wafer Map에서 Die 선택 → Die Map 결함 확인 → KLARF 리뷰 이미지 → Die Map을 CAD Map에 수동 오버레이 → Fail chain GDS 영역과 육안 대조 → 표 작성 (표 헤더 "ASICDC RES **Manual** AOI-ET Correlation")
- KLARF 레코드 예시 (p.2)
  ```
  13 -58994.628 88367.090 12478.370 13377.791 -3 3 3.880 5.180 20.120000 5.180 0 3 0 25 1 1 0 3014 0 1 1 1 69;
  TiffFileName XD074.01_-3_3_25_14.jpg;
  ```
  | 필드 | 값 | 추정 의미 |
  |---|---|---|
  | 1 | 13 | DEFECTID |
  | 2–3 | -58994.628, 88367.090 | Wafer 기준 좌표(µm) 추정 |
  | 4–5 | 12478.370, 13377.791 | **Die 내 상대좌표 XREL/YREL** (슬라이드 "Defect Coordination") |
  | 6–7 | -3, 3 | XINDEX/YINDEX → Die #11 |
  | 8–9 | 3.880, 5.180 | XSIZE/YSIZE(µm) |
  | 10 | 20.12 | DEFECTAREA |
  | 11 | 5.180 | DSIZE |
  | 12~ | 0 3 0 25 1 1 0 3014 0 1 1 1 69 | CLASSNUMBER/TEST/CLUSTER/BIN/IMAGECOUNT 등 — DefectRecordSpec 필요 |
- 리뷰 이미지 헤더: Lot `PFIC_RH-HS2617B_TBDB`, Wafer `XD074.01`, Device `OMM_Hybrid`, Step `OMM_Hybrid_TBDB_Silterra`, Def 399, FOV 390.47 µm
- GDS 영역 분류(p.3): Corner(TL/TR/BL/BR), PIC All(EDGE), Bot All(EDGE), Left/Right All, ASIC All, ASIC HBM, HBM01 All(CORE), HBM0/HBM1 All
- 판정 사례 (p.3)

  | Die# | Fail Chain | Manual Insp. | TBDB AOI | UPD AOI | Correlation |
  |---|---|---|---|---|---|
  | 7 | ASIC_EDGEDC_L1_FH | - | UPD Residue | - | No |
  | 11 | ASIC_EDGEDC_L1_FH | UPD Residue | UPD Residue | - | No |
  | 11 | ASIC_COREDC5_P_FH | UPD Residue | UPD Residue | - | **Yes** |
  | 11 | ASIC_COREDC5_N_FH | UPD Residue | UPD Residue | - | **Yes** |

  → 판정 단위는 Die가 아니라 **(Die, Fail Chain) 쌍**. 같은 결함도 chain 영역 안이면 Yes, 밖이면 No.

#### A vs B 차이

- A가 요구사항을 명문화(Ver.1), KLARF 원문·좌표·GDS 영역 분류 추가
- 범위 축소: B는 C4/TBDB/UPD AOI + TSV(TSVDC) 포함 → A는 ASICDC RES의 bump/RDL 매칭에 집중
- 판정 표: B "Structure/Unit/Type/Test/AOI 3종/FA" → A "Die#/Fail Chain/Manual/TBDB·UPD AOI/Correlation(Yes/No)"
- 표기: B "Unit #" → A "Die#", structure명 "#숫자" 접미사 제거
- 서로 다른 웨이퍼 사례 (B "Wafer #1" / A "XD074.01")

#### 기술 리스크

1. 좌표계: A의 AOI Map(#11→#6 우측 감소) vs B의 C4ET Map(5→12 우측 증가) 좌우 반전 추정
2. Die 번호 ↔ KLARF (XINDEX, YINDEX) 매핑 규칙·기준 Die 미정
3. KLARF DefectRecordSpec 미제공, "Defect 13" vs 이미지 "Def: 399" 불일치
4. Tolerance 미정 (결함 4~5 µm, bump pitch, RDL 폭 대비). BBox 매칭 vs Polygon 매칭
5. Chain명 ↔ GDS(cell/net/text/layer) 규칙 부재, P/N·FH·L1/R3·#1549 의미 불명. Net 추출(LVS급) 필요 시 난이도 급상승
6. GDS 대용량·기밀(반출 제한)
7. Multi-step AOI(TBDB/UPD/C4) 좌표계 상이 가능, "TBDB AOI" 컬럼에 "UPD Residue" 기재 모호
8. ET 원시 포맷·Open 판정 기준·데이터 소스 미정
9. Ver.2 이후 TSV·결함 자동분류 확장 가능성
10. 판정 값(Yes/No vs 분류명/Unknown), 다결함-다chain 규칙 미정

### 2.2 제안서 v1.1 / v1.1F

파일: `스태츠칩팩코리아_Defect E-Test 자동 분석 시스템 구축 제안_v1.1.pdf/.pptx`, `_v1.1F.pptx` (작성 2026.07.29, 46장 / F 47장). 페이지 번호는 v1.1 기준(F는 대부분 +1).

- **목적(p.3)**: AOI Defect 좌표와 E-Test 불량의 상관관계 자동 분석·매핑. 3대 목표: 표준화된 분석 시스템, 연계 분석 절차 간소화, 수집·판정 자동화

  - YMS: Setup(Wafer Map, Bin, Program Parameter, Parsing Rule), Bin Analysis, Test Analysis
  - **Correlation(신규)**: Setup(Die Setup, Die Layer Setup, CAD Data Mapping), Analysis(Die Level View, Map View/Gallery, Chart), Report(Kill Ratio, 전이율, 공정별 기여도, Alarm)
- **중점 7항목(p.5)**: GDS/CAD 관리, Die 레이아웃 Label, Die 단위 Correlation, 설비 Monitoring(메일), Die 특정 영역 Monitoring, DMS 고도화, YMS 고도화
- **아키텍처(p.7~11)**: AOI→KLARF, TEST→CSV, GDS/CAD Import(예시 화면 .dwg 류), CAD Item List(No/Item/Location/Width/Height), Die Layout: Structure 1 : N CAD Item 체크 매핑
- **분석 로직(p.9)**: E-Test Fail Structure → 매핑된 CAD Item 사각 영역 → 영역 내 AOI Defect = 원인 후보
- **Die 영역 Monitoring 예시(p.11)**: Structure ASIC BCDC BL FH / 단위 Wafer / 5개 / 메일 TRUE / 설비 Hold TRUE
- **일정(p.13)**: Phase1 M1 분석설계, M2~4 개발, M5 테스트·적용(Open), M6 안정화(완료보고)

#### Chain 개념

- Input → Output 전기적 연결 경로. 계층: Device → GDS Revision → Chain → (Part) → Element
- 구현상 실질: Input Element에서 선택 Layer 내 실제 도형 교차를 따라 도달한 배치 Element 집합 + 수동 보정
  - 최종 = 자동 후보 + 수동 추가 − 수동 제외 + 단자
- Part/Connection은 보류

#### 현재 구현 흐름

1. GDS 조회 → `새 Chain` → Layer 체크
2. `Input 지정`(실제 형상 + 픽셀 오차, 겹치면 메뉴 선택, 1개) → `Output 지정`(선택)
3. `후보 경로 찾기`: 공간 격자 BFS, Polygon·PATH 폭 교차(경계 접촉 포함). Output 있으면 첫 경로, 없으면 도달 전체
4. 표시: 기본 경로(노랑), 직접 겹침(하늘, 1단계), 분기(주황 점선)
5. `경로 추가/제외` 수동 보정 → 연결 검사
6. 유사 묶음 제외: 평행이동 형상 매칭(오차 0.0001), 녹색/주황/빨강, 일괄 제외 + 1단계 되돌리기
7. 다중 Chain: 행 선택=편집, 체크=Visible, Chain별 고유색
8. 렌더링: Chain 외곽선·겹침·분기 OpenGL VAO/VBO (Marker/TEXT는 GDI+)

#### 현재 DB 모델 (17.38, 초안 SQL 미실행: `GdsMapControl/Persistence/2026-09-29_device_map_oracle_schema.sql`)

| 테이블 | 내용 |

#### 유효 결정사항

1. Input/Output 수동 지정, 자동 확정 금지
2. 작업 영역 없이 Layer 필터 + 실제 형상 교차 탐색
3. Input 1, Output 0~1, 열린 경로 정상 저장
4. 직접 겹침 확장 1단계
5. 수동 제외는 재탐색해도 복원 안 함
6. 다중 Chain 독립, 논리 삭제
7. Visible / Layer 표시 / 활성 Chain 분리
8. 범위 드래그 제외 철회 → 유사 묶음
9. PlacedElementId 개정본 범위, Revision 변경 시 자동 이월 없음
10. Map 전체 DB 저장, 배치 Commit 후 READY
11. 도형 접촉 ≠ 전기적 연결 확정
