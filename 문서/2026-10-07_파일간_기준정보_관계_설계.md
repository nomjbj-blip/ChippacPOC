-> **Wafer ID 원문으로는 연결할 수 없다.** 두 파일에 공통으로 있는 것은 **Lot 핵심 문자열 + Slot 번호**뿐이다. 그래서 표준 Wafer 기준은 **(Factory, Device, Lot, Slot)** 이고, Lot 과 Slot 을 붙인 **표준 `WAFER_ID`** (`RH-HS2615` + 2 -> `RH-HS2615-02`) 를 하나 더 만든다 (결정 R1).

### 1.2 DMS 의 기존 KLARF 저장 위치 (수정하지 않음)

기존 KtoD 적재가 KLARF 헤더를 아래 테이블에 이미 넣는다. POC 는 이 테이블을 **읽기만** 한다.

```text
TQD_PRODUCT (PRODUCT = DeviceID, FACILITY, TECHNOLOGY ...)
  └ TQD_LOT   (LOT_SEQ, LOT_ID = LotID 원문, PRODUCT)
      └ TQD_WAFER (WAFER_SEQ, LOT_SEQ, WAFER_ID = WaferID 원문, SLOT_ID)
          └ TQD_STEP (STEP_SEQ, WAFER_SEQ, STEP_ID, TEST, RESULT_ID, INSPECTION_EQ, SETUP_SEQ, RESULTTIMESTAMP, FILETIMESTAMP ...)
TQD_INSP_INFO (STEP_SEQ, WAFER_SEQ, FACTORY, PRODUCT, LOT_ID, WAFER_ID, STEP_ID, TEST, SLOT_ID, ...)  -- 펼친 형태
```

기존 테이블에 표준 기준 컬럼을 추가할 수 없으므로 (기존 소스 영향 금지), **POC 쪽에 기준 정보 등록 테이블을 따로 두고 KLARF 는 `STEP_SEQ` 로 가리킨다**.

## 2. 구조 설계

### 2.1 기준 계층

```text
Factory
 └ Device ──────────────── GDS Map (TQP_GDS_MAP, Device 단위 1개)
    └ Lot
       └ Wafer (= Lot + Slot)
          ├ KLARF 파일  (Step 별, DMS TQD_STEP)
          └ E-Test 파일 (시험 프로그램 / 시각 별)
```

- GDS 는 Device 까지만 있다 (Lot / Wafer 없음).
- KLARF / E-Test 는 Wafer 아래에 **여러 개** 붙을 수 있다 (Step 별 AOI, 재시험 E-Test).
- Defect Image (jpg) 는 이 등록 대상이 아니다. 자체 기준 정보가 없고 (파일명 앞 Wafer ID 뿐) KLARF Defect (DEFECTID) 의 상세 자료이므로 **나중 Defect / 결과 Data 설계**에서 다룬다 (2026-10-07 사용자 지적 "한 행에 한 파일 정보").

### 2.2 신규 테이블 `TQP_GDS_SRC_FILE` (파일 기준 정보 등록)

- 이름: 테이블이 많아 구분하기 쉽게 `TQP_GDS_` 접두어를 붙인다 (사용자 지시). 제약 / 인덱스도 `*_GDS_SRC_FILE_*`.
- **한 행 = 파일 1개.** 행끼리 부모 / 자식 관계는 두지 않는다.
- **기준 정보는 칸 하나로 쓴다** (원문 / 표준 칸 구분 없음, 사용자 지시 "RAW_ 제거, 같이 사용"). 원문과 표준이 다른 경우는 KLARF 의 Lot / Device 뿐이고, KLARF 원문은 DMS `TQD_LOT / TQD_WAFER / TQD_STEP` 에 그대로 남아 있어 (SOURCE_KEY 로 조회) 정보가 없어지지 않는다. E-Test 는 파일명 값이 곧 표준 값이다 (Wafer `RH-HS2615-02` = Lot + Slot).

| 컬럼 | 형식 | 설명 / E-Test 샘플 / KLARF 샘플 |
| --- | --- | --- |
| SRC_FILE_SEQ | NUMBER PK | 시퀀스 `SRC_FILE_SEQ` |
| FILE_TYPE | VARCHAR2(20) NOT NULL | `ETEST` / `KLARF` |
| FILE_NAME | VARCHAR2(260 CHAR) NOT NULL | E-Test 원본 파일명 / KLARF `TQD_STEP.INSP_FILENAME` (없으면 WaferID) |
| SOURCE_TABLE | VARCHAR2(30) | 상세 저장 위치. KLARF = `TQD_STEP`, E-Test = 결과 Data 설계 때 정함 (그 전엔 NULL) |
| SOURCE_KEY | NUMBER | KLARF = `STEP_SEQ` |
| FACTORY | VARCHAR2(30 CHAR) | 등록 화면 선택 / KLARF 는 `TQD_INSP_INFO.FACTORY` 기본값 |
| DEVICE_ID | VARCHAR2(50 CHAR) | `TQP_GDS_MAP.DEVICE_ID` 와 같은 값 체계 (R3). 둘 다 등록 화면에서 선택 (KLARF 는 R4 로 엔지니어가 직접 등록하므로 이때 고름) |
| LOT_ID | VARCHAR2(100 CHAR) | `RH-HS2615` / `PFIC_RH-HS2615_C4Bump` (KLARF 는 등록 때 원문, 연결 규칙 확정 후 갱신 — R5) |
| SLOT_NO | NUMBER(3) | 2 / 2 (1 ~ 99) |
| **WAFER_ID** | VARCHAR2(110 CHAR) **가상 컬럼** | `LOT_ID || '-' || 2자리 SLOT_NO` = `RH-HS2615-02` / 지금은 `PFIC_RH-HS2615_C4Bump-02`, Lot 갱신 후 `RH-HS2615-02` (R1) |
| STEP_ID | VARCHAR2(100 CHAR) | `TSVET` / `OMM_Hybrid_C4Bump_Silterra` |
| SETUP_ID | VARCHAR2(200 CHAR) | 파일명 접두어 `CAI_OMM_ATV_A0` / SetupID `ROOT-CAI-OMM_Hybrid-...` |
| EQUIP_ID | VARCHAR2(100 CHAR) | `Head 1 - Site 1` / `KLA LDS CIRCL Tool` |
| EVENT_TIME | DATE | 2026-06-09 16:19:40 / ResultTimestamp 2026-06-05 12:01:42 |
| 감사 컬럼 | | CREATE_USER / CREATE_TIME / UPDATE_USER / UPDATE_TIME |

KLARF 의 원래 Wafer ID (`XD106.02`) 는 이 테이블에 없고 `TQD_WAFER.WAFER_ID` 에서 본다.

제약 / 인덱스

- UNIQUE (FILE_TYPE, FILE_NAME, EVENT_TIME) — 같은 파일 이중 등록 방지 (KLARF 는 이름이 같아도 검사 시각이 다르면 별도)
- UNIQUE (SOURCE_TABLE, SOURCE_KEY) — 같은 DMS `TQD_STEP` 을 두 번 등록하지 않음
- 인덱스 (FACTORY, DEVICE_ID, WAFER_ID) — Wafer 로 파일 찾기 (나중 연결의 기본 조회)
- 인덱스 (FACTORY, DEVICE_ID, LOT_ID, SLOT_NO) — Lot 단위 조회

`WAFER_ID` 를 가상 컬럼으로 둔 이유: KLARF 의 LOT_ID 를 나중 규칙으로 갱신하면 WAFER_ID 가 **저절로 같은 형식으로** 바뀐다. 파일마다 따로 조립하다 형식이 어긋날 일이 없다. INSERT / UPDATE 문에는 이 컬럼을 넣지 않는다 (넣으면 ORA-54013).

GDS Map 은 이미 `TQP_GDS_MAP` (FACTORY + DEVICE_ID) 이 Device 기준을 갖고 있어 이 표에 넣지 않는다. DEVICE_ID 를 같은 값으로 맞추는 것으로 연결한다 (R3).

### 2.3 Parsing / 등록 시 채우는 규칙

| 컬럼 | E-Test (업로드 시 Parsing) | KLARF (엔지니어가 직접 등록, DMS `TQD_*` 에서 읽음) |
| --- | --- | --- |
| FACTORY / DEVICE_ID | 업로드 화면 선택 (파일에 없음) | 등록 화면 선택 (KLARF `Hybrid_OMM` 은 참고 표시) |
| LOT_ID | 파일명 Lot 토큰 그대로 `RH-HS2615` | `TQD_LOT.LOT_ID` 원문 `PFIC_RH-HS2615_C4Bump` |
| SLOT_NO | Wafer ID 가 `{Lot}-{숫자}` 형식이면 숫자 (02 -> 2), 아니면 NULL | `TQD_WAFER.SLOT_ID` (2) |
| STEP_ID | 파일명 시험 프로그램 `TSVET` | `TQD_STEP.STEP_ID` |
| SETUP_ID | 파일명 접두어 `CAI_OMM_ATV_A0` | KLARF SetupID |
| EQUIP_ID | 내용 `Test Head - Site` | `TQD_STEP.INSPECTION_EQ` |
| EVENT_TIME | 파일명 14자리 일시 | `TQD_STEP.RESULTTIMESTAMP` |

E-Test 파일명 분해는 뒤에서부터 한다 (Lot / Wafer 안에 `_` 가 있어도 안전): 마지막 = Wafer, 그 앞 = Lot, 그 앞 = 14자리 일시, 그 앞 = 시험 프로그램, 나머지 = 접두어. 내용의 `Wafer ID` 열 값이 파일명 Lot 과 다르면 경고만 한다.

KLARF 등록은 **엔지니어가 원할 때 직접 실행**한다 (R4). 프로그램이 미등록 KLARF 를 찾아 자동 등록하지 않는다. DMS 적재 서비스는 수정하지 않는다.

같은 파일을 다시 등록하면 확인 창을 띄우고 기존 행을 삭제 후 재등록한다 (GDS Map 과 같은 정책).

### 2.4 E-Test 헤더와의 관계

[E-Test 설계](2026-10-07_ETest_결과파일_Parsing_DB설계.md) 의 `TQP_ET_FILE` 에 있던 Lot / Wafer / 프로그램 / 일시 / 파일명 칸은 `TQP_GDS_SRC_FILE` 로 옮긴다. E-Test 결과 Data 테이블은 나중 설계에서 `SRC_FILE_SEQ` 를 참조한다.
