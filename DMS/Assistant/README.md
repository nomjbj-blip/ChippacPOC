**역할(2026-10-02 사용자 지시):** Claude가 메인 개발을 맡고, Codex는 사용자가 요청한 보조 작업(리뷰 / 분석 / 별도 기능)을 맡는다. 어느 쪽이든 작업 전 [작업 현황](작업_현황.md)에 담당 행을 먼저 등록한다.

이 폴더는 개발 지침, 현재 기능 상태, 변경 이유와 다음 작업을 함께 관리한다. 대화 내용을 모두 옮기기보다 다음 작업자가 소스를 찾아 작업을 이어가는 데 필요한 내용을 남긴다.

1. [공통 개발 지침](공통_개발_지침.md): 작업 범위 / 설명 방식 / 즉시 갱신 규칙

4. 아래 기능 문서 중 작업 대상
5. [빌드 / 검증 가이드](빌드_검증_가이드.md): 출력 위치 / 빌드 명령 / Verify 스크립트 / 자주 겪은 문제 / 신규 메뉴

## 바로 갱신할 내용

- 작업 시작: [작업 현황](작업_현황.md)에 담당 도구 / 기능 / 수정 예정 파일을 기록한다.
- 결정 또는 코드 변경 직후: 해당 기능 문서의 현재 상태 / 중요한 로직 / 미완료 항목을 수정한다.
- 검증 직후: 명령 / 대상 소스 또는 EXE / 결과 / 미확인 범위를 당일 변경 이력에 기록한다.
- 중단 또는 인계 직전: 진행 중인 작업 상태와 다음 한 단계를 갱신한다.
- 당일 이력은 `변경이력/YYYY-MM-DD.md`에 항목을 추가한다. 과거 날짜 기록은 지우지 않는다.

[기능 문서 양식](양식/기능_문서_양식.md) / [작업 기록 양식](양식/작업_기록_양식.md)을 사용한다. 파일 변경을 감시하는 프로그램은 없다. 각 도구가 작업 과정에서 직접 문서를 갱신하는 방식이다.
