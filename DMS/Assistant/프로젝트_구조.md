## GDS 폴더를 잘못 수정하지 않기

루트에 `GdsMapControl`, `GdsMapControl_chain`, `GdsMapControl_0922`도 있다. 기존 기록과 SQL 링크는 루트 `GdsMapControl`을 가리키는 경우가 있다. 현재 POC 솔루션의 프로젝트 경로는 **DMS/06_CoreLibSource/GdsMapControl**이다. 다른 폴더가 최신이라고 이름으로 추정하지 말고 대상 솔루션과 EXE를 먼저 확인한다. 폴더 간 일괄 동기화는 하지 않는다.

2026-10-02 Claude 비교 결과(bin / obj / .vs / packages 제외): 루트 `GdsMapControl`과 DMS 내부 폴더는 **두 파일만 다르다.**

| 파일 | DMS 내부에만 있는 내용 |
| --- | --- |
| `GdsMapTestForm.cs` | `GdsMapTestForm(bool hostedByDms)` 생성자 / DMS 표시 시 직접 DB 버튼과 가상 결함 숨김 |
| `NexplantQMS.GdsMap.csproj` | NuGet HintPath를 `00_Solution/DACrux2015wc_ChippacPOC/packages`로 변경 |

따라서 GDS 수정은 DMS 내부 폴더에서만 한다. 루트 폴더는 이전 사본으로 보고 수정하지 않는다.

## 기존 문서와 달라진 사항

| 예전 기록 | 2026-10-02 확인 결과 |
| --- | --- |
| GDS 소스가 루트 GdsMapControl 기준 | POC 솔루션은 DMS 내부 프로젝트 참조 |
| PLACED 전송 형식 v1 | 현재 MapPlacedBatchPayload.FormatVersion = 2 |
| GDS Service / SQL 전부 미구현 | 개정본 헤더 건수 / DRAFT 등록 / 재조회 코드와 XML 존재. 전체 도형 적재는 별도 |
| 파일 Map 좌표 LeftBottom | 현재 파서는 첫 RowData를 Y=1로 만드는 LeftTop |
| frmSetupMap도 MapCreationService 사용 | 현재 기존 화면은 자체 저장 경로 유지. 새 파일 Map 화면만 서비스 호출 확인 |
| Chain 테이블 DDL 없음 | 10/01 설계서에 신규 TQP_GDS_* 13개 테이블 적용 기록. 현재 DB는 재조회하지 않음 |

과거 인수인계 원본은 수정하지 않았다. 다음 작업에서는 최신 기능 문서와 소스를 함께 확인한다.
